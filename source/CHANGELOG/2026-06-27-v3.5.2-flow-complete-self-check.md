# 2026-06-27 | ae-sdd v3.5.2 - 流程收尾合规自检 + 自愈机制

## Summary

**背景/痛点：** ae-sdd 流程在 Story 级 ⑧完成输出前、PRD 级 `prd-complete` 前，缺少"收尾合规自检"环节。Story 级 ⑦bis 闸和人工审核点 4 后直接进 ⑧，AI 可能"裸 ✅ 收尾"——用户确认的是 CodeReview 内容，但产出物是否齐全、文档是否合规落位、state 是否推进、门禁是否全过，没有独立核对。PRD 级更严重：探查发现 `cmd_state_prd_complete`（tools/bin/ae-sdd:268-271）把 4 层 AND 校验注释为"简化：提示用户先跑"，实际不复跑校验直接写 `awaiting_compact` → 存在"跳过 `prd-check-complete` 直接 compact"的漏洞路径。

**本次做了什么：** 按用户需求"每次流程结束时先自检合规，不合规就修复"，在两处流程结束点增加自检 + 自愈机制。Story 级新增 ⑦ter 节点（人工审核点 4 后、⑧前自跑 5 维度自检：全门禁 / 文档位置 / state 完整 / 产出物齐全 / 无遗留 🔴），自愈策略为"🟢 可自愈项 AI 直接修后重跑，🔴 阻断项升级用户"。PRD 级新增 §1.7 SOP，强制 `prd-check-complete` 先于 `prd-complete`，堵住跳校验漏洞。落地强度按用户选定"SKILL 文字 + 复用现有 CLI"路线——7t-1/2/3 复用 `gates check` / `state read`（已有硬阻断 exit code），7t-4/5 由 AI 按编排文字执行清单齐全性核对，不新建硬门禁、不动 tools/ 代码。

**达成的效果：** 流程结束前 AI 必须以现有 CLI 客观输出为证据自检，禁止"给自己打钩"裸收尾；不合规项优先自动修复，修不了的阻断升级用户；PRD 级堵住跳校验漏洞，compact 前必须有 `prd-check-complete` 的 `all_pass=true` 证据。

## 触发原因

- 用户需求（原话）："更新 ae-sdd，每次流程结束时都先自己做一次流程检查，看看合不合规，不合规就修复。"
- 探查发现的实现 gap：`cmd_state_prd_complete`（tools/bin/ae-sdd:268-271）把 4 层 AND 校验注释为"简化"，实际不复跑 → 存在"跳过 prd-check-complete 直接 compact"漏洞，需编排层 SOP 补齐。
- 与 ⑥.10 测试真实性同源的"防止 AI 给自己打钩"设计原则：主 agent 声称"流程已完成"无效，必须以现有 CLI 客观输出为证据。
- 前序变更连带：本次为新增编排层节点，无 update-graph rule id 对应（属流程编排层增强，非门禁/CLI 契约变更）。

## 影响范围

- **不涉及运行时逻辑 / 门禁行为 / CLI 命令变更**：纯 SKILL 编排层文档改动，未新增硬门禁、未改 tools/ 代码、未改 CLI 命令契约。7t-1/2/3 复用现有 `gates check` / `state read`（已有硬阻断 exit code），7t-4/5 是编排层"清单齐全性"逻辑（由 AI 按编排文字执行）。
- **不改变已有门禁、子 SKILL 职责边界、文档存放路径**：⑦ter 是 Phase 3 新增节点，不与 ⑥/⑥bis/⑦/⑦bis 重叠；§1.7 是 §1.6 的执行约束补强，不改 PRD state.json schema。
- **版本号推进 3.5.1 → 3.5.2**：需 UC-01 三处一致（SKILL.md frontmatter / paths.py / README:5），已同步。
- **无破坏性变更**：现有流程不受影响，⑦ter 是新增环节；§1.7 是补强约束（原"prd-complete 跳校验"本就是漏洞，堵漏洞不算破坏）。
- **按 ae-sdd-update-skill §边界判定表归位**：流程节点定义 / 整体执行清单 → ae-sdd-skill（SKILL.md），符合"流程编排层"职责，未塞进子 SKILL。
