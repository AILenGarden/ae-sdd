## Summary

v3.5.12 我声称 G-09B（reviewer session 独立性）能堵"root 总派给自己"。用户连问两次"G-09B 都已经是阻断设计了，还不需要写 CLI？"——这个质问抓到了真问题。核实事实：**G-09B 根本没注册成独立门禁**，只是 review_loop.py 的内部函数，只在 collect() 里被调用。更糟的是 G-REVIEW-LOOP 有 skip 后门（无 reviewLoop 字段即放行）。两条防线都依赖 root 主动调 review-loop collect——**root 不调就什么都不会发生**，跟"root 总派给自己"的老问题在 root 不配合时完全没区别。

本次修复：G-09B 升级为独立 GATE_REGISTRY 门禁（id=G-09B），review phase（story-reviewed/task-reviewed/code-reviewed）切相时由 check_all 自动跑，**不依赖 root 调 collect**。check_g09b 自己机械派生 Tier（读 RA 规模+决策线索），Tier 1（微/小+无关键决策）豁免单审，Tier 2/3 强制要求 state.activeAgents 有 ≥Tier 个 sessionId≠root 的 reviewer + reviewLoop 字段存在。5 场景 E2E 验证全通过：不派/自扮/没跑review-loop 全阻断，完整合规才放行。

## 触发原因

- 用户连问两次"G-09B 都已经是阻断设计了，还不需要写 CLI？"——抓到 v3.5.12 的真 bug
- 核实：G-09B 未注册 GATE_REGISTRY（只在 review_loop.py 内部），G-REVIEW-LOOP 有 skip 后门，两条防线都依赖 root 主动调 collect → root 不调即绕过
- 用户决策选 A：G-09B 独立硬门禁，review phase 切相时自己机械派生 Tier + 校验 activeAgents，不依赖 root 调 collect

## 影响范围

- **运行时行为变更（核心）**：review 节点切相时新增 G-09B 校验。Tier 2/3 的 review 必须：① 派 ≥Tier 个独立 session 的 reviewer 并 register_agent 登记 ② 跑 review-loop start 启动状态机。否则 check_all 阻断。这是堵"root 总派给自己"的真正硬约束
- **门禁数**：27→28（+G-09B）
- **Tier 1 豁免**：微/小规模 + 无关键决策的 review 不受影响（单审合规）
- **无破坏性变更**：旧 state（无 activeAgents）在 Tier 2/3 phase 会阻断——但这正是设计意图（强制 root 真派）
