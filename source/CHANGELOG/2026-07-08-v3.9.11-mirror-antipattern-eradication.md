# 2026-07-08 | ae-sdd v3.9.11 - 镜像反模式根除 + 5 层防复发护城河

## Summary

2026-07-08 life 项目实测事故：`cs-ai-STORY-003-BE` 在 `testcase-generated` phase 卡死，PreToolUse hook 拒绝 Write TestCase 文档，ClaudeCode 进程无法推进。根因排查发现是**5 个独立缺口叠加**：

1. `.ae-sdd/state.json` 镜像冻结指 `cs-ai-STORY-005-BE`（phase=completed），未跟随 STORY-003 切换
2. STORY-003 work-item state 只有 `currentStep: step-4-test-generate`（非标命名），缺 `phase` 字段
3. v3.9.8 mirror-fallback fix 修了 CLI 入口（state read/next-step/health），但 G-00 阻塞门禁未同步——删镜像后 G-00 仍报"项目骨架不完整"
4. `cmd_state_write` 未检测镜像冻结——镜像指 completed work-item 时 `set_phase` 静默报错，镜像永不刷新
5. 缺少主动健康检测脚本——镜像误指长期无人发现

**本次做的是「反模式根除 + 5 层防复发护城河」**，让这类问题在任意 4 层叠加下都不再造成事故：

| 层 | 防御点 | 修法 |
|---|---|---|
| 1 | G-00 镜像可缺 + 镜像-源一致性硬约束 | `gates.py:174-244` 二段校验（镜像缺失降级 / 镜像存在校验锚点） |
| 2 | G-00 单测 5 场景全覆盖 | `test_gates.py::TestG00` 新增 5 用例 + 修 2 老用例 |
| 3 | `cmd_state_write` 镜像冻结检测 | `ae-sdd` CLI 入口加 `_check_and_recover_stuck_mirror` |
| 4 | prompt-inject 反模式检测 | `_detect_phase_naming_antipattern` 扫 step-X- 自由命名 |
| 5 | `scripts/check_mirror_health.py` 维护脚本 | 7 项检测：目录/镜像/源/phase/一致性/指死/命名 |

**life 项目实测**：删除 `.ae-sdd/state.json` 后 G-00 通过、hook 放行 Write TestCase、health 9/10 pass、`check_mirror_health.py` exit=0。

## 触发原因

**life 项目 STORY-003 卡死事故**（2026-07-08 16:18 起）：

用户跑 STORY-003 到 testcase-generated phase，派 TestCase Agent 写 testcase 文档，hook 全部拒绝。表面现象像"hook 设计缺陷禁一切 Bash"，但深挖发现：

- `.ae-sdd/state.json` 镜像冻结指 STORY-005（phase=completed）
- `.auto-engineering/cs-ai-STORY-003-BE/state.json` 只有 `currentStep: step-4-test-generate`，无 `phase` 字段
- hook 读 state 走 v3.9.8 mirror-fallback，但镜像存在时优先读镜像 → 拿到 phase=completed → PHASE_PERMIT["completed"]=frozenset() → 所有写操作拒绝

这不是单点 bug，是**5 个独立缺口的叠加**。单点修任何一层，剩余 4 层仍可能复现。本次目标是**修到不再复现**——5 层全补 + 单测 + 维护脚本。

## 影响

### 兼容性
