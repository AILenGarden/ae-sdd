## 改动 1：AI Coding 反模式库（AP-1~AP-6）

**文件**：`source/standards/thinking/be-coding-ai-anti-patterns.md`（新增）

6 大反模式，每条包含：定义 / LLM 触发场景 / 检测信号 / 防御动作 / 实测案例：

| # | 反模式 | LLM 频率 | 危害 |
|---|--------|---------|------|
| AP-1 | 幻觉 API | 极高 | 🔴 P0 — 运行时 NoSuchMethodError |
| AP-2 | 抄旧代码（带 Bug 复用）| 极高 | 🔴 P0 — 复制历史安全漏洞 |
| AP-3 | 过度设计（展示能力）| 极高 | 🟠 P1 — 无用抽象增加维护负担 |
| AP-4 | 注释撒谎 | 高 | 🟠 P1 — 注释和实现不一致 |
| AP-5 | 默认值陷阱（hardcode）| 高 | 🔴 P0 — 生产配置被硬编码 URL/密钥覆盖 |
| AP-6 | 上下文漂移 | 极高 | 🔴 P0 — 写到后期忘记原始需求，代码实现偏离 |

## 改动 2：coding_authenticity_scan.py（新增）

**文件**：`scripts/coding_authenticity_scan.py`

对标 `test_authenticity_scan.py` / `ra_authenticity_scan.py`，把 AP-1~AP-6 中可静态命中的反模式变成硬信号：

| 扫描规则 | 对应反模式 | 严重度 |
|---------|----------|--------|
| 已知幻觉 API 特征（如 `@TransactionalEventListener(fallback=)` 等）| AP-1 | BLOCKER |
| 过时安全配置版本错位 | AP-2 | BLOCKER |
| 过度抽象命名密度 | AP-3 | WARN |
| TODO/FIXME/XXX 留在生产代码 | AP-4 | WARN |
| hardcode URL / 密钥 / timeout / retry / TTL | AP-5 | BLOCKER |
| Coding 报告引用不存在的代码文件 | AP-6 | BLOCKER |
