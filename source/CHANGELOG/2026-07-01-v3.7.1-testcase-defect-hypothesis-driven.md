# v3.7.1 — TestCase 系列假设驱动强化

**日期：** 2026-07-01
**版本：** v3.7.0 → v3.7.1
**触发原因：** 解决"测试用例覆盖不全 / 无价值用例多 / 挖不出真实BUG"三大顽疾
**范式：** 假设驱动·覆盖兜底（缺陷假设挖掘为主线，三层覆盖矩阵降为查漏兜底）

---

## 变更摘要

引入「假设驱动·覆盖兜底」范式：TestCase 系列从纯覆盖率导向升级为缺陷假设导向。testcase-generate 先挖掘缺陷假设（主线）再生成证伪用例，testcase-review 交叉校验假设覆盖率，strategy 提供通用缺陷假设库 SSOT，模板落地假设字段。

## 详细变更

### A. `source/standards/testing/be-testcase-strategy.md`（测试策略 SSOT）
- **§核心原则 升级**：从"覆盖全场景"→「假设驱动 + 覆盖兜底」双原则，新增三类用例分级定义
- **新增 §通用缺陷假设库（7大类）**：H-并发/H-事务/H-边界/H-状态机/H-集成/H-安全/H-时序资源，每类含假设 ID/触发条件/预期暴露方式/推荐层级/信号来源。素材源自 CodeReview T1-T5 + DB 反模式 + B1-B4 + 领域经典（不含 D1-D8 测试伪造手段）
- **新增 §项目特有坑信号源指引**：6 个项目坑信号源（assets §6.9/§10/§14 + function §1.8/§1.9 + config §5 + 同类 Story 历史测试报告），不新建 assets 章节复用现有成熟格式
- **§覆盖完整性自检清单 升级**：新增假设驱动校验项（主线）置于覆盖率校验（兜底）之前

### B. `source/skills/phase1-design/testcase-generate-skill.md`（生成端强化）
- **frontmatter description**：加"假设驱动·覆盖兜底"范式
- **§输入 新增缺陷信号源**：6 个项目坑信号源表 + 降级规则（缺失标注"未加载"，禁止编造）
- **§生成规则 新增 §0 缺陷假设挖掘（主线）**：双向机制（自上而下通用库匹配 + 自下而上项目坑挖掘 + Story 业务分析），产出 H-{N} 假设清单
- **§生成规则 §2 重构**：三类用例分级（证伪/正向/兜底）+ 三层覆盖矩阵降为查漏工具
- **§合规性校验 新增 TC-G11 假设覆盖率**：含成熟度降级机制（坑库成熟度≥50%→40%阈值；<50%→25%阈值）+ 假设-用例双向校验 + 报告明示
- **§禁止事项 + §执行清单 同步**：禁止跳过假设挖掘/禁止凑数用例/禁止编造坑；执行清单加第 1.5 步缺陷假设挖掘

### C. `source/skills/phase1-design/testcase-review-skill.md`（审查端同步升级）
- **frontmatter description**：TC-1~TC-9 → TC-1~TC-10
- **§检查口径 修订 TC-8**：区分真冗余（剔除）vs 非冗余多对多证伪（保留）
- **§检查口径 新增 TC-10 缺陷假设覆盖率**：假设完整性 + 证伪占比 + 凑数剔除 + 标注规范，与 generate TC-G11 阈值一致
- **新增 §与 generate 假设驱动的衔接**：明确 review 是 generate 假设挖掘质量的第二道把关
- **§流程图 + §输出要求 + §禁止事项 同步**：TC-10 加入流程/报告/禁止跳过

### D. `source/templates/testcase/be-testcase-template.md`（模板字段）
- **新增 §缺陷假设清单**：落地 H-{N} 完整清单 + 证伪用例映射
- **§覆盖矩阵 新增列**：假设覆盖（H-{N}）
- **§用例列表 新增字段**：用例类型（证伪/正向/兜底）+ 证伪的缺陷假设 + 缺陷假设分类

### E. 版本同步（3 处一致性）
- `source/SKILL.md` frontmatter version: 3.7.0 → 3.7.1（description 追加 v3.7.1 假设驱动强化说明）
- `tools/lib/paths.py` MASTER_VERSION: "3.7.0" → "3.7.1"
- `README.md:5` 版本号同步 + 变更摘要

## 影响范围

- **TestCase 系列（③/③bis）**：范式从覆盖率导向升级为假设驱动导向
- **Phase 1 设计阶段**：③ 生成测试用例 + ③bis TestCase Review 均受影响
- **下游消费者**：Task 生成/Coding 读取 TestCase 文档时新增假设字段（向后兼容，旧文档无假设字段不影响）
- **不改动范围**：Story 系列 / 流程编排（SKILL.md 仅 version+description）/ assets schema / tools 代码 / CodeReview

## 验证方式

## 设计决策记录

| 决策 | 选择 | 理由 |
|------|------|------|
| 范式 | 假设驱动·覆盖兜底 | 治本"挖不出真实BUG"，覆盖矩阵保证完整性但不保证缺陷发现力 |
| 假设库位置 | strategy.md（SSOT 集中） | 集中维护，一处定义多处引用 |
| 门禁强度 | 硬门禁 ≥40% | 强制假设挖掘充分，治"凑数用例" |
| 降级机制 | 按坑库成熟度降级到 25% | 避免项目初期坑库不全时过度阻断 |
| Review 同步 | TC-10 + TC-8 修订 | 避免审查端抵消生成端假设驱动效果 |
