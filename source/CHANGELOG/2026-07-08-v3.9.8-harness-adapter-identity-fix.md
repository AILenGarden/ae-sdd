# 2026-07-08 | ae-sdd v3.9.8 - harness adapter 身份定位修复：ae-sdd 是 client-agnostic 独立小 Agent

## Summary

`scripts/templates/agent.md.template`（v3.4.0 时代定型）把 ae-sdd 写成 "Harness Auto-Engineering Orchestrator"，导致 3 个客户端（Claude Code / Codex / ZCode）拉取 `source/SKILL.md` 经 adapter 转译出的 `.harness/agent.md` 后，AI 误以为"我已经是 Harness 编排器了"，**跳过任务大小评估（big/mid/small/micro）直接编码**。

用户问句"ae-sdd 是独立小 Agent，跟 Harness 有什么关系"直接戳破此根因。

## Why

### 设计意图（ae-sdd 独立）

`source/SKILL.md` 第 1-4 行明说：
> 端到端自动化工程主入口（v3.9.8）。从 DR/PRD 出发，经 RA→DR→Story→TestCase→Task→Coding→Test，直到全部通过。

`source/HARNESS.md` 第 163/178/210 行只在**分发层**提到 Harness（与 claude/codex/zcode/hermes 平级），明确"ae-sdd 是 client-agnostic 独立 Skill"。

### 工程现实（adapter 强行套壳）

`scripts/templates/agent.md.template`（v3.4.0 模板）的 3 处硬编码：
1. **L11 标题**：`# ae-sdd Auto-Engineering Orchestrator (Harness)` — 钉死身份为 Harness 子编排器
2. **L17 角色声明**：`You are the ae-sdd auto-engineering orchestrator in Harness format` — AI 自认为"我就是编排器"
3. **L44-61 routing 表**：life 项目专属的 `im-expert / cs-expert / user-expert / vehicle-expert / bff-expert / java-tester / code-reviewer` — 不是通用任务大小评估，掩盖了 ae-sdd 第一轮应该做的"大/中/小/微"评估

`scripts/templates/README.md.template`（同源）也犯同样错误：
1. **L1 标题**：`# ae-sdd Harness (AUTO-GENERATED)`
2. **L7 描述**：`转译成 Harness 格式（agent.md）` — 把 ae-sdd 钉死为 Harness 专属

### 触发链（用户实测 4 次手改均无效）

|---|---|---|
| 12:46 | 手动改 `.harness/agent.md` | 备份成 `agent.md.bak-2026-07-08` |
| 12:49 | adapter 自动重转 | 备份成 `agent.md.bak.20260708T125218`，手改被覆盖 |

**根因**：改渲染产物 `agent.md` 不改模板 `agent.md.template`，下一次 build 立刻覆盖。

## Fix（v3.9.8 patch）

### 1. `scripts/templates/agent.md.template` — 身份重写

- L11 标题： `# ae-sdd Auto-Engineering Orchestrator (Harness)` → `# ae-sdd — 独立端到端自动化工程 Skill`
- L17-18 注释：新增"🆕 身份定位（v3.9.8 fix）" 段落，引用 bak 备份作为历史证据
- L19 角色声明：`You are the ae-sdd auto-engineering orchestrator in Harness format` → `You are the **ae-sdd skill** — 一个客户端无关（client-agnostic）的端到端自动化工程 Skill，独立运行于 Claude Code / Codex / ZCode / Harness 等任意宿主之上`
- **新增 L21-27 任务大小评估表**：第一轮必做 big/mid/small/micro 评估，禁止跳过
- L29-33 保留英文 SOP 段 + 新增禁止动作（跳过评估 / 把 ae-sdd 当宿主编排器）
- L44-61 routing 表：life 专属 `*-expert` 表删除，改为通用任务大小评估 + 业务域路由的可选叠加层
- L65-72 "How you work §2" 改为"任务大小评估（第一轮必做）"

### 2. `scripts/templates/README.md.template` — 身份重写

整个模板重写：
- L1 标题：`# ae-sdd Harness` → `# ae-sdd Harness 适配产物`
- 新增 §"宿主格式对照"：明确 Claude/Codex/ZCode 直读 source，Harness 才用本目录
- 卸载章节注明 `harness unmount` 仅当宿主走 harness mount 协议时用

### 3. `scripts/build_harness.py` — 新增 `assert_independent_identity` sanity check

位置：渲染 agent.md / README.md 后，写盘前。**fail-fast**，exit code 2。

5 条正则（避免裸禁词误报，只拦截"ae-sdd 是 X 子编排器"的归属句式）：
1. `ae-sdd ... Harness` — 禁止钉死 Harness 子编排身份
2. `Harness format/mode/role` — 禁止描述 ae-sdd 为 Harness 的 format/mode/role
3. `You are the ... orchestrator` — 禁止声明 ae-sdd 是 orchestrator
4. `ae-sdd ... orchestrator` — 禁止钉死 orchestrator 身份
5. `auto-engineering orchestrator` — 禁止出现此短语

错误信息含 L行号 + match 字符串 + 修复指引（编辑 templates/）。

### 4. `.harness/agent.md.bak-2026-07-08*` — 保留作为证据

不删除 — 这次 fix 的关键证据就是"用户 4 次手改都被覆盖"。后续审计可追。
