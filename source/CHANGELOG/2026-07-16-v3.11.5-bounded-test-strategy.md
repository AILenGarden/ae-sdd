# 2026-07-16 | ae-sdd v3.11.5 - 有界风险驱动测试策略

## Summary

旧测试策略一边要求避免凑数，一边又用完整状态矩阵、逐字段有效/无效边界、最少用例公式和 25%/40% 证伪占比强制扩张测试组合。v3.11.5 改为有限风险登记、边界准入、行为等价类、最低充分层级、局部数量上限和明确停止条件；高影响风险继续强制保护，超出局部预算必须记录价值、成本、不可合并原因和确认人。

## Design ledger impact

| Design ID | Impact |
|---|---|
| `D-024` | UC-20 合法设计范围从 D-001~D-024 / §1~§21 扩展为 D-001~D-025 / §1~§22，并补对应正反例测试。 |
| `D-025` | 新增风险驱动的有界测试策略，验证证据为源契约测试、TC-G11/TC-10 与后续项目运行指标。 |

## Changes

| Area | Change |
|---|---|
| TestCase strategy | 删除全转换矩阵、逐字段边界穷举、最少用例公式和证伪比例配额；新增有限风险登记、准入规则、局部上限、停止条件与预算例外。 |
| TestCase generate | 将命中的假设改为候选，要求 `keep/merge/exclude/defer` 选择决策；TC-G11 改为组合价值与有界性校验。 |
| TestCase review | TC-1~TC-10 同时检查漏测高风险和无界扩张；同触发条件或不同层级不再自动视为独立价值。 |
| TestCase template | 新增风险等级、证据来源、行为分区、独立失败机制、选择决策、停止条件证据和预算例外字段。 |
| CodingModel | 将六类场景从强制数量清单改为按适用性准入的风险候选，并同步最低充分层级与停止条件。 |
| Design / UC-20 | 新增 D-025 与 §22；更新 UC-20 合法 ID/章节范围及回归测试。 |
| Runtime source | 定向重建 TestCase generate/review 与 ae-sdd-update slim entry，保持 fallback hash、semantic inventory 和 render 一致。 |
| Version | 通过 `ae-sdd bump 3.11.5` 同步 `source/SKILL.md`、`tools/lib/paths.py` 和 README。 |

## 触发原因

- 用户反馈 ae-sdd 产生过多无价值边界测试，且测试策略没有停止边界。
- 现行“避免凑数”目标与数量公式/比例门禁互相矛盾，导致边际缺陷发现价值为零的测试仍被强制生成。

## 影响范围

- 改变 TestCase 生成与评审的用户可见策略语义；已有 TestCase 文档继续可读，新生成文档需提供选择证据。
- 新增一个只读 Markdown 源契约测试，并对 UC-20 的合法设计范围做机械扩展。
- 不改变 CLI、gate 注册、state schema、scanner、Document Storage、evidence、typed operation 或 Monitor 行为。
- `source/docs/ae-sdd-implementation-architecture.md` 仅同步版本标记；实现架构和运行时数据流无语义变化。
- Monitor、UG-27 typed operation 和 UG-29 RA scope：N/A，无解析字段、协议或数据流变化。
