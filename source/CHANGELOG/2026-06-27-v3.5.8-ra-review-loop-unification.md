# 2026-06-27 | ae-sdd v3.5.8 - RA 挖掘循环 review-loop 化

## Summary

2026-06-27 用户在审阅 ae-sdd 体系时指出："需求分析阶段没有反复挖掘流程吗？RA 也需要 Review 呀，走一样的 Review 机制，也就是挖掘到无新增内容了，才结束转人工审核。" 经核对确认：RA（`requirement-analysis-skill.md`）是 ae-sdd 全链路事实源头，DR/Story/Task/Coding 全部引用其结论，但它的第七步"16 道 RA 质量闸"是**一次性终检**——AI 跑一遍 16 道闸就交差，**8 维度挖掘是否穷尽无收敛判据、无反复挖掘闭环、无漏报升级**。对比 DR Review（`dr-review-skill.md`）已引用 `review-loop-skill.md` 公共协议（连续 3 轮无新增才退出 + 3 轮仍有 🔴 升级用户 + 漏报升级），RA 反而缺失这套机制——这是体系性缺口。

本次变更将 RA 第七步从"一次性终检"重构为**引用 review-loop 公共协议 + RA 专属配置**，与 DR Review 同等机制；同时把第二步循环对象从"仅缺口"扩展为"缺口 + 8 维度挖掘穷尽"，与第七步 loop 语义对齐（避免两处循环打架）。这与 v3.5.6 那次"RA 多轮挖掘强制落地"正交互补：v3.5.6 在工具层强制 AI **进入** RA 流程（save_doc 前置检查 + flow_violation_scan + ra-gate CLI + 反模式 8/9），v3.5.8 在方法论层保证 AI **在 RA 里挖到穷尽**（反复挖掘 + 收敛判据）。两者缺一不可。

## 触发原因

- **用户反馈（2026-06-27）**：用户审阅 ae-sdd 体系时指出"RA 也需要 Review，走一样的 Review 机制，挖掘到无新增内容了才结束转人工审核"。核对确认 RA 第七步确实缺失反复挖掘闭环。
- **体系性缺口**：review-loop-skill §各节点专属配置表列了 6 个 review 节点（Story Review / DR Review / Code Review / Task Review / Proposal / Story Generate 自检），唯独没有 RA；连下游的 Story Generate 都有自检 loop，上游事实源 RA 反而没有。
- **grep 铁证**：RA skill 全文 0 处匹配"连续 N 轮""无新增""反复挖掘""多轮挖掘收敛"——它的第七步是"全过即完成"的一次性终检。
- **后果高危**：RA 漏一条规则/场景/衍生规则 R'，下游 DR/Story/Task/Coding 全部跟着漏，返工成本指数级上升（RA 改一行 → DR/Story/Task 全重审）。这正是 2026-06-27 自我修订建议书诊断的"RA 多轮挖掘流程未执行"系统性漏洞的机制根因。
- **与 v3.5.6 互补**：v3.5.6 已用工具层强制 AI 进入 RA 流程，但进入后"挖到一半就停"的问题仍无方法论层机制保障，本次补齐。
