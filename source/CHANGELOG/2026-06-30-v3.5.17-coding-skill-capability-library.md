# 2026-06-30 | ae-sdd v3.5.17 - CodingSKILL 能力库化 + CodingProcess 全流程化

## Summary

**背景/痛点：** v3.5.16 虽然把 CodeAnalysis 剥离为 CodingProcess 节点，但 Execute 流程仍塞在 coding-skill，且 coding-skill 仍被当作"执行器"。用户纠正定位：CodingSKILL 应是**纯能力库**（"如何写对代码"的知识——决策方法/骨架展开/分层红线/CodeAnalysis 方法论/检查清单），被 CodingProcess 调用；CodeAnalysis 是 CodingProcess 调用能力库做的一个**行为**，不是独立能力。之前的"文档太长 AI 懒得读"问题，根源正是 coding-skill 1880 行混杂了流程与能力。

**本次做了什么（流程与能力彻底分离）：**
- **coding-skill 退为纯能力库**：1880→588 行（-69%），只留"如何写对代码"的知识（12 个 § 能力块），零流程编排
- **CodingProcess 扩展为全流程节点**：200→478 行，持有 Task→CodePlan→Coding 全流程编排（Phase A CodeAnalysis + Phase B Execute + Phase C 异常追溯），调 coding-skill 能力库
- **Execute 流程迁入 CodingProcess**：原 coding-skill 的第一~九步编排/异常路径 A1-A6/执行清单/讲解规范/交付表全部迁入 CodingProcess Phase B/C
- **修正悬空锚点**：gates.py 的 §6.7 死锚点（coding-skill 从无 §6.7）改为正确指向 §5

**达成的效果：** 能力与流程彻底分离——能力库（coding-skill）专注"如何写对代码"，流程节点（CodingProcess）专注"什么时候做什么"。AI 在编码时，CodingProcess 编排流程、按需调用能力库的特定能力块，不再被 1880 行混杂内容淹没。

## 触发原因

用户："CodingSKILL 的能力是告诉AI如何生成代码、代码规范、代码设计时如何做决策、要参考哪些理论、思维。所以分析代码的时候才需要依赖 CodingSKILL...code analysis 是一个行为，CodingProcess 去调用 CodingSKILL 做 Code Analysis 这个行为。" 据此重新定位：CodingSKILL=能力库（被调用），瘦身方向=剥流程留能力。
