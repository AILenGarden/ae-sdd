# 2026-07-07 v3.9.3 — R6 顶层命名 + R2 强制向上归入（递归算法）

## Summary

- 🆕 v3.9.3 实施：废除 v3.8.2 双段 `{ID}--{name}` 目录命名 + `--name` 形参，**全部走 R6 顶层名**（`PRD-{特征}` / `DR-{特征}` / `Story-{合并编号}` / `Task-{task_id}`）
- 🆕 R2 强制向上归入（用户定义的递归算法）：创建新节点前先查父级（PRD/DR/Story 文档"来源 DR/PRD"字段），父级文档存在 + 关联性对则嵌进父级 state；父级无 state 则**递归替父级建** state 再嵌
- 🆕 session.json 与 state.json 共用 R6 顶层目录（旁路 L1 根治）
- 🆕 `cmd_enter` 必须传 R6 顶层名或可派生顶层名的 raw ID（不再支持裸 raw story_id 拼路径）
- 🆕 `prompt_inject` 自动激活改用 `find_nested_state_by_story_id` 查归属，找不到则**放弃自动激活**（不再用 `id=id` 怪异名建 state）
- 🆕 模板字段规范：`来源 DR` / `来源 PRD` 必填，必须对应 design/ 真实文档且 DR 文档 §Story 拆分 章节必须列出本 Story ID
- ⚠️ **BREAKING CHANGE**：
  - `work_item_dir_name(id, name)` → `work_item_dir_name(top_node, features)` 签名变更
  - `cmd_state_new --name` 形参废除（required 改 optional）
  - `cmd_enter --story` 不再支持裸传（需 `--work-item <R6 顶层名>` 或 `--story <STORY-ID>`）
  - 旧 `STORY-XXX--YYY/` 双段目录不再被自动命中，需手工 `state relocate --story STORY-X` 迁移

## Why

### 病灶（用户多次反馈"改了 N 次不根治"）

`STORY-004-BE` 目录反复冲突的根因是 v3.6→v3.7.4→v3.8.2→v3.9.0 多次"局部修复"未触达旁路：

1. **旁路 L1 — `session.py` 完全绕开 `work_item_dir_name`**：`session_path()` 直接 `raw story_id` 拼路径，session.json 落到 `<项目根>/.auto-engineering/{STORY-004-BE}/session.json`，与 state.json 命名空间**完全独立**
2. **旁路 L2 — `cmd_enter` 不强制 name**：用户反复跑 `enter --story STORY-004-BE` 重建同名目录
3. **旁路 L4 — `prompt_inject` 自动激活用 `id=id` 怪异名**：产 `STORY-X--STORY-X` 双段怪异名（name=id）
4. **旁路 L5 — 零门禁扫"非 ID--NAME 单段目录"**：没有兜底
5. **`cmd_state_new` 不接 R2 预检**：手工 `state new` 时 AI 不查父级，直接拼 `{ID}--{name}` 目录
6. **`match_state` 路由 R2 不验证父级文档**：只查已存在 state，不查 design/ 真实文档

**用户对话原话**（确认 v3.9.3 设计意图）：
> "先找 Story 有没有父级 DR，父级 DR 有没有父级 PRD。"
> "Story 模板里就改写清楚归属 DR，如果没有归属 DR 就当做没有。"
> "PRD、DR、Story、Task 都可以作为顶层，但是都需要先确认有没有父级，如果有父级且父级存在 state，那是要嵌进去写的。如果有父级，但父级没 state，那就要替父级创建一个 state 然后嵌进去写，这是一个递归的过程。"

### 端到端验收

```bash
# 1. 创建 STORY-006 无父级 → 顶层 Story-006
ae-sdd state new --id STORY-006-BE --entry-node STORY --story-ids STORY-006-BE

# 2. 创建 STORY-006 有父级 DR-005（且 DR 文档含 STORY-006）→ 嵌进 DR-005
echo -e "# DR-005\n\n## Story 拆分\n\n- STORY-006-BE\n" > design/DR-005-some-title.md
echo -e "# STORY-006-BE\n\n## 元信息\n\n- 来源 DR: DR-005\n" > design/STORY-006-BE-Story.md
ae-sdd state new --id STORY-006-BE --entry-node STORY --story-ids STORY-006-BE
# → .auto-engineering/DR-005/state.json 内 storyStates 包含 STORY-006-BE

# 3. enter 走 R6 顶层名
ae-sdd enter my-project --work-item Story-006
# → .auto-engineering/Story-006/session.json

# 4. enter 派生顶层名（用 raw STORY-ID）
ae-sdd enter my-project --story STORY-006-BE
# → 自动派生 Story-006，写 .auto-engineering/Story-006/session.json

# 5. 父级文档不存在 → 视为无父级
ae-sdd state new --id STORY-999-BE --entry-node STORY --story-ids STORY-999-BE
# → design/ 找 DR 文档 → 找不到 → 顶层 Story-999（不阻塞）
```
