# 2026-06-25 | ae-sdd v3.4.0 - 门禁体系加固（4 份建议书全量采纳 P0-P3）

## Summary

ae-sdd 的门禁体系存在"两头强、中间空"问题：前置门禁（G-00/G-RA）有 CLI/hook 强制，但中段流程（文档存放、源码核对、人工审核）与质量门禁几乎全靠 agent 自觉；且 3 处文档撒谎（承诺不存在的命令/自动调用）。本次根据 `D:\al-agent-workspace\ae-sdd-update-doc` 下 4 份修订建议书（G-CODEPLAN-SRC 单点 / G-DOC-STORAGE 单点 / 系统性排查 25 B类+3撒谎+1假门禁 / 入口关卡三道闸方案），全量采纳 P0-P3，把"中段与质量评审"的文档约定升级为可执行门禁，形成 G-00/G-RA（前置）→ G-CODEPLAN-SRC/G-DOC-STORAGE/G-14/入口关卡（中段）→ G-09/G-CODE-1（后置）的完整门禁链，并建立 UC-06 文档-实现一致性自动检测防止文档撒谎复发。门禁数 19→22，PHASE_FLOW 10→11（新增 ra-generated），CLI 新增 `enter`/`state confirm`/`gate doc-storage` 3 个子命令。

## 触发原因

- **建议书1 G-CODEPLAN-SRC**：life 项目 STORY-020 实测中 AI 出 CodingPlan 未读现有源码，凭推测设计类骨架（改错文件、漏改 Converter、与现有范式不符），CodeReview 事后读源码时序错位。
- **建议书2 G-DOC-STORAGE**：AI 未调 resolve_path 自行把 CodingPlan 写到 `d:\tmp\`；life 项目 assets.md gitPath 过时；工程目录与文档目录分离项目路径模型不匹配。
- **建议书3 系统性排查**：25 项 B 类门禁（有规定无门禁）+ 3 处文档撒谎（L-1/L-2/L-3）+ 1 处假门禁（F-1 Stop hook 只查头不查内容）。
- **建议书4 入口关卡**：门禁全挂在状态机切换上，agent 不进状态机即可绕过所有门禁；三道关卡方案（entry token + 产物落地校验 + 代码改动准入）。
- 4 份建议书共同根因：强制力分布不均匀 + 文档与实现脱节 + 质量检查退化为存在性检查。

## 影响范围

- **运行时逻辑/门禁行为变更**：新增 3 个门禁（G-14/G-CODEPLAN-SRC/G-DOC-STORAGE）+ 入口关卡三道闸 + F-1 交叉验证 + ra-generated phase + 审核点 token。涉及 gates.py/gate_intercept.py/stop_check.py/prompt_inject.py/state.py/memory_gate.py 运行时行为。

- **版本号推进**：v3.3.0→v3.4.0（UC-01 三处一致）。
- **不采纳项**：建议书2 §5.4 life assets.md 更新（项目侧维护，非 ae-sdd 改动）；建议书3 B1-1/B1-3/B1-4 的 gate tr-check/complete-check/cr-gates 新命令（以 G-14 + G-08 内容校验 + 审核点 token 覆盖核心风险，避免 CLI 膨胀，后续迭代）。
