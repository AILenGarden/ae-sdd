# v3.11.0 Typed Operations and State Leases

## 变更

- 为 Work Item 增加 `StateStore` 并发边界：短文件锁、TTL lease、过期接管、fencing token、revision CAS、幂等 mutation 和损坏文件 fail-closed。
- 新增 `ae-sdd ops describe/next/execute` 与 `ae-sdd lease acquire/status/renew/release/break`。LLM 通过 registry 的 JSON Schema 操作 state、文档、门禁、VerificationPlan 和 Evidence；raw `state.patch` 不注册。
- `document.resolve/save`、`gate.check`、`verification.plan`、`evidence.record/finalize` 使用真实模块适配器；旧 `state write` 保留为经 StateStore 短租约的兼容入口。
- Work Item 文档/报告作用域优先于 Story；只有唯一 legacy Story 候选时才 fallback，多候选返回 `SCOPE_AMBIGUOUS`。G-13 支持父 Story 继承和 standalone micro BUG 最小链路。
- VerificationPlan 增加 `evidenceInputFingerprint` 与可执行 `nextActions`。Evidence record 使用内容寻址 immutable snapshot，同 logical key 的旧 active entry 标记 superseded，finalize 只校验 active snapshot，旧 manifest 可读取且不在读取时静默改写。
- 维护者契约进入 `operation-protocol.md §9` 和 `ae-sdd-update` self-update 路由：明确 authority/version/admission/required-change-set/Definition of Done；UG-27 增加维护入口、设计架构、registry 和 `UC-19` 级联，防止后来维护者只改代码或只改对话说明。

## 验证

- StateStore、真实 subprocess 并发、typed operation/CLI、Work Item scope、G-09/G-13、Evidence lifecycle 和 legacy state write 均有 focused tests。
- 发布前必须依次运行 `python tools/bin/ae-sdd update-check --json`、`python -m pytest`、`python scripts/build_dist.py` 和 runtime smoke；dist/installed runtime 只由构建/分发脚本生成。
- 新增 `UC-19` 维护契约检查：协议 §9、self-update 入口、UG-27 级联、主设计文档版本和 registry version markers 任一漂移都会 fail closed。
