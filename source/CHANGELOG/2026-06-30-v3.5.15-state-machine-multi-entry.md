# v3.5.15 多入口状态机——4 子链 + scale 路由

**日期：** 2026-06-30
**版本：** v3.5.15（与 coding-skill 外科手术式治理合并发布）
**触发原因：** 用户发现「流程起始点可以是 PRD/Issue/对话/BUG 等，但 state 状态机只以 PRD（实为 initialized→ra 强制主干）为单一 assumed 起始点」，要求大中小微四种规模各自有独立 state 追踪模型。

## 变更摘要

将单条线性 `PHASE_FLOW`（initialized→ra→dr→story→...→completed，11 phase，所有规模共用）重构为 **4 条子链 `PHASE_FLOWS`**（大11/中10/小8/微4 phase），按 `state.scale` 路由。修复微任务停在 initialized 时 `next_step` 误建议"跑 RA"的可观测 bug；BUG/配置类复用微链（entryNode 标 BUG/CONFIG）。旧 state 无 scale 自动反推（默认"大"最保守）。

## 详细变更

### 核心改动：`tools/lib/state.py`
- `PHASE_FLOW`（list）→ `PHASE_FLOWS`（dict[scale→list]），保留 `PHASE_FLOW = PHASE_FLOWS["大"]` 别名（向后兼容）
- 新增 `VALID_SCALES = ("大","中","小","微")`
- 新增 `set_scale(state, scale, entry_node=None)`：写 scale + entryNode，校验 scale 合法
- 新增 `_infer_scale(state) → (scale, confidence, reason)`：旧 state 兼容——按 completedSteps 含 dr/story/task 反推；无法判定默认"大"（最保守）
- 新增 `_resolve_scale(state)`：有 scale 用之，无则 _infer_scale + 回写
- `set_phase`：校验改为「按 state.scale 选子链，phase 须在该子链内」
- `next_step_suggestion`：改为按 state.scale 选子链 mapping（`_NEXT_STEP_MAPPINGS`）；微链 initialized→coding（修复可观测 bug）
- `read_state` 空模板加 `"scale": None, "entryNode": None` 默认值

### `tools/lib/gate_intercept.py`（3 处消费点）
- `_check_state_write` 跨步跳跃判定：从 `PHASE_FLOW.index` 改为「按 state.scale 选子链后 `.index`」；微链 initialized→coding（idx 0→1）合法单步不再被误拦
- `PHASE_ENTRY_GATES`：单 dict → 嵌套 `PHASE_ENTRY_GATES[scale][phase]`；微链 coding 入口仅 `["G-00"]`（免 G-07/08 task-reviewed 前置）
- 关卡3（coding 写 src/ 须审核点确认）：按 scale 路由——微链免 task-reviewed，改要求 coding phase 确认
- `_PRODUCT_PHASE_MAP` / `PHASE_PERMIT` / `_DESIGN_PHASES`：保持不动（phase 名跨链唯一，无需按 scale 拆）

### `tools/lib/memory_gate.py`
- `is_forward_transition`：加 `scale` 参数，按 `PHASE_FLOWS[scale]` 选链判定（旧用 `PHASE_FLOW` 大链）
- `check_state_transition`：从 state_data 读 scale 传给 is_forward_transition

### `tools/lib/classify.py`
- `Classification` 加 `entry_node: Optional[str]` 字段
- `classify()` 末尾推断 entry_node：BUG 关键词→entry_node=BUG+scale=微；配置类→CONFIG+微；PRD→PRD；Issue/对话→RA

### `tools/bin/ae-sdd`（CLI）
- `cmd_state_write` 加 `--scale`（choices 大/中/小/微）+ `--entry-node` 参数
- 首次 state write 携带 --scale 时调 `state.set_scale`；与已有 scale 冲突 warn 不覆盖

## 设计决策（用户逐项确认）

| # | 决策 | 选项 |
|---|------|------|
| 1 | 独立粒度 | 4 子链 + scale 路由（共用 state.json schema，物理存储不变） |
| 2 | BUG/配置类 | 并入微链（entryNode 标 BUG/CONFIG，不单独开链） |
| 3 | scale 写入时机 | 首次 state write --scale 携带；旧 state 无 scale 反推降级 |
| 4 | 物理存储 | 不变（仍 .auto-engineering/{txn-id}/state.json） |

## 兼容性策略

- 旧 state.json 无 scale 字段 → read_state 不报错；set_phase/next_step 调 _infer_scale 反推
- 反推规则：completedSteps 含 dr→大；含 story→中；含 task→小；无法判定→默认"大"（最保守，避免误放行微任务跳 RA）
- ⚠️ 安全考量：phase=coding 时无法可靠区分微链（直跳 coding）vs 大链（走完 task-reviewed 进 coding），故 coding 阶段不推微，默认大——微任务必须显式 --scale=微
- `PHASE_FLOW` 保留为大链别名（向后兼容，加 deprecation 注释）

## 影响范围

- **修复可观测 bug**：微任务/BUG 停在 initialized 时，`ae-sdd state next-step` 不再误建议"跑 RA"，改建议"进 coding"
- **修复防御性 gap**：微任务正经跑 `state write --phase coding` 不再被 gate_intercept「跨步跳跃」误拦
- **不破坏**：大/中/小链行为与旧版一致（旧版 = 大链）；BUG/配置类对话通道不变
