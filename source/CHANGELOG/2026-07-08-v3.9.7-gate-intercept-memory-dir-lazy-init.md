# 2026-07-08 | ae-sdd v3.9.7 - gate_intercept 内存根目录惰性初始化（生命项目死环修复）

## Summary

2026-07-08 04:30-04:38 实测：D:\Item\life\ 项目中 Claude Code 写源码被 `gate_intercept._check_memory_entered` 拦截，提示 "尚未执行 memory enter，禁止写操作"。根因不是嵌套 state 漏判（v3.9.1 已修），而是 `.ae-sdd/memory/` 目录**从未被项目创建**，`_check_memory_entered` 透过 `locate_scope()` + `is_scope_active()` 链路调用 `_read_json(_stage_path)`,当 stage 文件不存在时静默返回 `{}` → `is_scope_active()` 始终 False,等价于"判未 enter"。

本次修复仅在 `_check_memory_entered` 入口处 best-effort 惰性创建 `.ae-sdd/memory/` 根目录,修复"目录缺失 = 永假"的隐性死路。**不改变活跃态判定语义**:无 stage token 时仍拒;有 token 时仍按 token 内容判定。同时在 life 项目放置一份占位 enter token(`.ae-sdd/memory/.stage/design__STORY-004-BE.json`),作为紧急解锁——后续 Story Review 阶段须由真实 `ae-sdd memory enter+write+exit` 流程覆盖。

附带的母版元数据漂移也顺手同步:`.harness/agent.md` 自 2026-07-06 09:52 后未重建(锁在 v3.9.1,落后 5 个小版本) → 重新生成到 v3.9.6;life 项目的 `.ae-sdd/config.yaml` `master.version` 同步 3.9.2 → 3.9.6。

## 触发原因

- **用户反馈(2026-07-08)**:Claude Code 在 D:\Item\life\ 项目中无法工作,写源码被 gate_intercept 拦截,提示 "phase=story-generated 不允许 Bash 操作"/"尚未执行 memory enter 禁止写"。runtime-stats 显示 04:31-04:38 期间 7 次 Bash 被第 7 步 PHASE_PERMIT 拒绝,1 次 Write 被第 5.5 步 `_check_memory_entered` 拒绝(#16-29)。
- **根因**:v3.9.0 嵌套 state 模型发布后,母版依赖 `.ae-sdd/memory/` 子目录做活跃态判定。life 项目使用 v3.9.0 嵌套 state,但 `.ae-sdd/memory/` 从未被任何 `ae-sdd init` / `ae-sdd memory enter` 调用创建,导致 `_check_memory_entered` 链路里 `_read_json(_stage_path)` 永远返回空 dict。
- **为什么不修改活跃态判定**:活跃态判定是 v3.8.2 设计的核心防伪机制(防止 Agent 跳过 enter 直接写源码)。本次 fix 不改变 `is_scope_active` 语义,仅消除目录缺失造成的"判未 enter"假象。
- **元数据漂移**:母版 .harness 自 2026-07-06 09:52 后未重建、life 项目 config.yaml 的 master.version 3.9.2 落后当前 4 个小版本,同步刷新避免后续再次漂移。
