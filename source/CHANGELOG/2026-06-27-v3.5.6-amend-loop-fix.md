# 2026-06-27 | ae-sdd v3.5.6 - 修补 amend 循环 commit noise

## Summary

**背景/痛点：** v3.4.0 引入 post-commit 自动分发闭环后，mount_harness 在 commit 完成后自动重转 harness 产物（`agent.md` + `.adapter.lock`）。该机制在正常 commit 路径上工作良好，但**在 `git commit --amend` 模式下形成循环**：

1. 用户写 v3.5.5 改动 → commit `529a122` → post-commit hook 触发 → lock.commit = `529a122`，agent.md 含 `529a122` hash
2. 用户 `git commit --amend` 补充 harness 文件 → 新 hash `6ea26e9`
3. post-commit hook 再触发 → 检测到 lock.commit (`529a122`) ≠ HEAD (`6ea26e9`) → 判定"漂移" → 重转
4. 工作区 dirty（agent.md + lock 又更新） → 必须再 commit → 循环

v3.5.5 release 时手动用 `--amend` 才规避该问题，但治标不治本。任何后续 amend 都会复发。

**本次做了什么：** 在 `scripts/build_harness.py` 幂等检查（4 维 commit/version/adapter/templateHash）**之前**新增 **tree-hash 一致性提前返回**：当 lock.commit 与 HEAD 的 commit hash 不一致，但**两者指向同一个 git tree**（即"amend/amend-like 操作，无内容变更"），则直接跳过重转。这利用了 git 的本质特性 —— amend 重新哈希 commit 对象但 tree 对象不变。配合 13 个单元测试覆盖 4 类场景（真实 amend 跳过 / lock==HEAD 全一致 / 不同 tree 正常重转 / 边界 unknown/empty/invalid hash 兜底）。

**达成的效果：** amend 后再触发 post-commit hook 时不再循环写盘，工作区保持干净，开发者无需 `--amend` 规避。修复**保持 v3.5.4 引入的自动分发闭环设计目标**（commit 后立刻同步），不动 hook 主流程、不挪到 CI、不加 `[skip-harness]` 逃生口 —— 用 5 行新逻辑 + 1 个新函数 + 1 个新测试文件根治。

## 触发原因

- 用户场景：v3.5.5 release 时 push 触发 post-commit hook → 又生成 harness 更新 → 工作区 dirty → 必须再 commit → 形成 2 个 noise commit（`529a122` + `6ea26e9`），最后用 `git reset --soft HEAD~1` + `git commit --amend` 合并才解决
- 根因：post-commit hook 调用 `mount_harness`，`build_harness.py` 第 307-329 行幂等检查只看 commit hash 字符串，不区分"真升级"和"amend"
- 设计哲学（用户决策 2026-06-27）：选方案 A（hook 自检，修根因），不选方案 B（挪 CI，工程量大且循环本质未消）/ C（`[skip-harness]` 逃生口，违背 v3.5.4 自动闭环本意）

## 影响范围

- **修改运行时行为（post-commit hook 触发时）**：amend 后再触发 hook 不再写盘；正常 commit / 升级 commit 行为不变（4 维检查仍生效）
- **新增 CLI / lib / schema**：❌ 无
- **版本号推进 3.5.5 → 3.5.6**：需 UC-01 三处一致（SKILL.md / paths.py / README.md:5）
- **无破坏性变更**：4 维检查逻辑完全保留；tree-hash 检查**仅在 lock.commit ≠ HEAD 时触发**，不影响 lock.commit == HEAD 的常规幂等路径
- **不涉及运行时逻辑外的影响**：不动 harness mount 协议、不动 hook 主流程、不动 distribute.py

- 真实 amend 回归测试（v3.5.7 之后）：用户 amend → 不再循环 commit。
