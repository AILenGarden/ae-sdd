# 2026-07-06 v3.9.0 — 嵌套状态模型（Nested State Model）

## Summary

- 新增**嵌套状态模型**：一个 state.json 内维护主流程所有子系列（prdState/drState/storyStates{N}），取代 v3.8.x 前的扁平"每 WorkItem 一个 state"模型。
- 新增**任意节点出发 + 向上归入**：PRD/DR/Story 都可作为顶层开 state；DR/Story 优先归入已存在的上层 state（如 DR 归入所属 PRD state 的 drState）。
- 新增**路由自动匹配/新建**：`/ae-sdd` 路由时 `classify.match_state()` 自动分析需求特征 → 扫描现有 state → 命中则重定位/归入，未命中则以当前主体为顶层新建。
- 新增**改已管理 Story 重定位 + 重置子状态**：`ae-sdd state relocate --story <ID>` 重定位到 Story 所属 state，并只重置该 Story 子状态到 story-generated（兄弟 Story 不动）。
- 新增**顶层主体命名规则**：只以最顶层主体特征命名（`PRD-{特征}` / `DR-{特征}` / `Story-{特征}`，多 Story 合并如 `Story-003-004-005`）。
- 保留 v1 扁平 state 完全兼容（`stateModel="flat"`），旧 workitem 不迁移、不动。

## Why

### 病灶（life 项目实证）

life 项目启动 Story-003/004/005 撰写任务时，`.ae-sdd/state.json` 镜像死锁在上一个任务 `STORY-002-BE/coding`，导致：

1. **注入污染**：`prompt_inject.py:180` 每条消息注入 `phase=coding / story=STORY-002-BE`，与用户实际在做的 Story-003/004/005 无关。
2. **路由污染**：`classify.py:174-197` 读 stale `currentStory` 的历史产物判当前任务规模。
3. **根因**：新任务从未跑 `ae-sdd state new` 登记成 workitem，镜像没人刷新。

## Migration

- **旧扁平 state 无需迁移**：v1 schema（`stateModel` 缺省或 `"flat"`）保留可读，所有读取点通过 `is_nested_state()` 分流。

- **改已管理 Story**：`ae-sdd state relocate --story <STORY-ID>` 自动重定位 + 重置子状态。
