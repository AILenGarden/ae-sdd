# 2026-07-15 | ae-sdd v3.11.2 - Hook 兼容带引号的 Python 与 ae-sdd 路径

## Summary

Claude Code 在 Windows 上可能生成 `python "C:/.../ae-sdd" state new ...`，或者同时给 Python 可执行文件和脚本路径加引号。旧版 PreToolUse Hook 由多套正则分别识别 state、memory、assets 和 readonly 命令，其中 `\S*ae-sdd\s+` 要求脚本名后直接跟空白，导致结束引号破坏匹配，合法命令被当成未知 Bash 并由 phase/歧义门禁拒绝。本次改为统一 token-aware 解析，使带引号与不带引号形式等价，同时保留所有 shell-control 防护。

## Design ledger impact

| Design ID | Impact |

## Root Cause

- `_STATE_WRITE_CMD_RE`、memory、assets、state-new/enter 和 pending-init 分别维护不一致的命令头正则。
- Python 后的脚本路径被双引号包裹时，`ae-sdd"` 不满足旧正则要求的 `ae-sdd` 后空白边界。
- 命令未进入 `state new` / `enter` 逃生口，随后被当前 phase 或 Work Item 解析拒绝；Hook 本身实际已经正常运行。

## Behavioral Invariants

- 只接受 basename 精确为 `ae-sdd`/`ae-sdd.py` 的脚本和受支持的 Python 解释器，不再用模糊前缀猜测。
- 未闭合引号解析失败并返回非 ae-sdd 命令，不抛出 Hook 异常。
- `&&`、`||`、`;`、`|`、单 `&`、`$()`、反引号、`>`、`<` 仍由既有安全检查阻断。
- 命令识别成功只进入既有业务检查，不绕过 Work Item、phase、memory 或 gates。
