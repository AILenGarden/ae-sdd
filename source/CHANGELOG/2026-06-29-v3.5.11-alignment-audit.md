## Summary

用户在 review-loop 复盘后提出体系级问题：「每次迭代都交给 AI 更新，为什么总是事后才发现文档和实现脱节？我们不是有实例化 SKILL 吗，失效了吗？」全局诊断（4 个 Explore agent 反向对账）揭示真相：用户设想的「实例化 SKILL（doc→CLI 代码生成器）」**从未被建成**——2026-06-18 拍板"做成工具而非 SKILL"指向 `ae-sdd sync-tools`，但 sync-tools 也从未实现，被塞进 `HISTORICAL_UNIMPLEMENTED` 历史集合标 warn。现有 dev-sync 只做"复制 .md"，update-check（UC-01~07）是窄面单向校验器（只查 CLI→doc，不查 doc→CLI；只查命令契约+版本号+门禁注册存在性，不查门禁内容真实性/state 字段存活性/状态机闭环），盲区里积累了 14 个 P0 病：review-loop dryCounter / 多 reviewer tier / G-RA-FLOW-VIOLATION 假门禁 / 7 道闸/16 质量闸/TC-TR 门禁撒谎 / 15 死字段 / 3 状态机未闭环 / run 幽灵命令等。

**本次根治**采用"全维对齐验证器 AA + AI 补齐工作流"路线（不再造代码生成器，因为校验器比生成器可靠 10 倍且天然幂等）：① 把 update-check 从 UC-01~07 升级到 UC-01~12，新增 5 维（UC-08 门禁承诺↔注册双向 / UC-09 门禁实现真实性抓 stub-pass / UC-10 state 字段存活性 / UC-11 状态机闭环 / UC-12 幽灵命令全捕获）；② 首跑分档处置（A 策略）：🔴error 档当场修（G-RA-FLOW-VIOLATION 假门禁 + run 幽灵命令），🟠 软门禁降级档（5 个核心 SKILL 加强度声明诚实区分软/硬门禁），🟡 死字段/状态机追踪档（留痕持续追踪不阻断启用）；③ AA 接入 `ae-sdd update-check` 作为 dev-sync 前置阻断，任何未来迭代 doc 改了不对齐 CLI 即报。从此"协议层承诺详尽但工具链零落地"的病根有了机械防线，不再靠用户事后发现。

## 触发原因

- 用户体系级反馈："每次都由我们来发现，是不是 ae-sdd-update-skill 的问题？每次迭代都只更新 doc 不更新 CLI 实例实现？我们不是有实例化 SKILL 吗，失效了吗？"——揭示 doc→CLI 对齐机制缺失的根因
- 全局诊断（4 个 Explore agent 反向对账）确认：用户设想的「实例化 SKILL（doc→CLI 生成器）」从未建成（2026-06-18 拍板做 sync-tools 工具，但 sync-tools 也从未实现，被塞进 HISTORICAL_UNIMPLEMENTED 标 warn）；dev-sync 只复制 .md，update-check UC-01~07 是窄面单向校验器有 2 个致命缺陷（单向 + 窄面）
- 14 个 P0 病的同病根确诊：协议层承诺详尽但工具链零落地——review-loop dryCounter / 多 reviewer tier / G-RA-FLOW-VIOLATION 假门禁 / 7 道闸 16 质量闸 TC-TR 门禁撒谎 / 15 死字段 / 3 状态机未闭环 / run 幽灵命令
- 工程现实：代码生成器路线（sync-tools）两次拍板两次落空，因为 LLM 把自然语言规则转译成 Python 保证幂等极难；改为校验器路线（读后比对天然幂等）是唯一能工程化的根治

## 影响范围

- **运行时逻辑变更**：G-RA-FLOW-VIOLATION 从"恒 stub-pass"变成真执行（首跑会跑 flow_violation_scan.py 8 条规则 R1-R8），这是行为变更——之前 RA 流程违规审计从未真正执行，现在会真实阻断。属于修复，符合预期
- **门禁强度**：未新增 GATE_REGISTRY 门禁（仍 26 个）；5 个 SKILL 的 [HARD]/道闸标注从"含糊的硬门禁"明确为"软门禁 report-only"，措辞诚实化但不改变 reviewer 实际执行（reviewer 仍需逐项判定，只是不再让 reader 误以为有 CLI 硬阻断）
- **AA 作为 dev-sync 前置**：UC-08~12 接入 update-check，error 级阻断 dev-sync，warn 级不阻断（死字段/状态机追踪档）。这是新增的机械防线
- **无破坏性变更**：现有命令契约/门禁/状态机字段不变；UC-08/10/11 的 warn 是新增追踪不阻断；UC-09 修假门禁是修复（让该阻断的真正阻断）；UC-12 删幽灵命令是清理（命令本就不存在）
- **版本号推进**：3.5.10 → 3.5.11，UC-01 三处一致（bump 已验证）
