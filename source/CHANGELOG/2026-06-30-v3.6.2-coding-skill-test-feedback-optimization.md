# v3.6.2 — CodingSkill 能力测试反馈优化（2026-06-30）

## 摘要

v3.6.1 落地 CodingSKILL 拆分后，用**全新 context 的 sub-agent**（未参与文档编写）按 §13 加载协议读两份文件、做 6 道真实编码题测试。6/6 合格，但暴露 4 个文档缺口。本版按测试反馈补强，**零破坏增量**（只加不删，不动 loader/注册机制）。

## 测试方法（确保反馈真实）

- 派全新 sub-agent（无写文档记忆）作为 CodeAnalysis 执行体
- 严格按共有 coding-skill §13.1 协议：①读共有能力库 ②按技术栈解析适配器 key ③读 Java3D 适配器 ④声明叠加覆盖范围 ⑤答题
- 6 题覆盖：分层判定 / 11维 CodingModel / CodeAnalysis 骨架+G-CODEPLAN-SRC / 骨架展开 / 异常根因4层 / 假修复+静态扫描
- 结果：6/6 全部合格（G-CODEPLAN-SRC 诚实标记机制成功抑制杜撰）；但 sub-agent 反馈 4 个"讲得不够用"的点

## 4 个测试反馈缺口 + 修复

| # | 缺口（sub-agent 反馈） | 严重度 | 修复 |
|---|----------------------|--------|------|
| 1 | **包路径前缀未固化**：§2.2 落点表用 `{domain}.{subdomain}` 模板，但 life 项目 base package 未在适配器内固化，AI 拼包路径时前缀只能标 `{待确认}` 查 assets | 🟡 P1 | 适配器新增 **§1.1bis base package 固化**（life 三条产品线 2c/admin/common 的 Java 包根 + 套用示例） |
