# v3.7.4 — WorkItem 级文档与状态隔离

日期：2026-07-01

## 背景

life 这类持续迭代项目会长期积累多个 PRD，同时也会把独立 BUG / 优化作为独立编码任务处理。旧 document-storage 与 state 规范默认以 Story 作为 Task/Coding/Test/CR 的分桶键，且主状态命令默认写 `.ae-sdd/state.json`，无法严格保证多个独立任务的目录与状态隔离。

## 变更

- `document_storage.resolve_path/save_doc/finalize_doc` 新增 `work_item_id` 参数。
- Task / Coding / Test / CR / Proposal 等产物改用 `{WORKITEM-ID}` 分桶；未显式传入时回退 `story_id/doc_id/task_name`，兼容旧调用。
- `ISSUE`、`TASK_REVIEW`、`TESTCASE_REVIEW`、`RA_GENERATE_PLAN`、`DR_SUPPLEMENT`、`CODING_ISSUE_LOG` 等已登记 intent 补齐 `_PATH_TEMPLATES` 实现。
- 事件类版本识别统一支持 `-vN-rM`、`-rN`、`-vN.M`、`-vN-to-vM`，ChangeLog 文件名去掉版本后缀，避免每轮报告生成独立 ChangeLog。
- `ae-sdd doc save/resolve/finalize` 新增 `--work-item`。
- `ae-sdd state read/write/next-step` 新增 `--work-item`；传入 `--work-item` 或 `--story` 时读写 `.auto-engineering/{WORKITEM-ID}/state.json`，并同步 `.ae-sdd/state.json` 作为 active mirror 兼容旧 gate/hook。
- `BUG-*` / `OPT-*` / `CONFIG-*` work item 或 `entryNode=BUG/OPT/CONFIG` 默认推断为微流程，避免缺陷/优化任务误走大流程。

## 文档

- `document-storage-skill.md` 路径模板、CLI/API 契约、intent 实现状态、重入 SOP 与调用矩阵已改为 WorkItem 口径。
- `source/SKILL.md` 的 state 路径、续接播报、收尾自检与产出物定位已改为 WorkItem 口径。
- `source/docs/ae-sdd-design.md` 已补充 WorkItem 级 state 与 document-storage 定位模型。
