# 2026-07-15 | ae-sdd v3.11.1 - Design Ledger 历史设计回填与迭代记录契约

## Summary

主设计文档原有 21 个系统级章节，但缺少统一的“问题、设计决策、预期价值、验证证据”索引，导致 LLM 和维护者需要反复阅读多个章节才能理解设计动机，也无法判断一次迭代影响了哪个设计。本次回填 D-001~D-023 历史设计，并将台账治理本身登记为 D-024，再用 CHANGELOG、UG-28 和 UC-20 固化以后每次迭代的记录方式。

## Design ledger impact

| Design ID | Impact |
|---|---|
| `updated: D-001~D-024` | 回填全部当前系统级设计，并记录 Design Ledger 治理自身的问题、决策、价值、证据和版本状态 |
| `D-007` | 明确 typed operation/lease 解决 LLM 理解成本、上下文读取、命令猜测、并发冲突和失败重试问题 |
| `D-014` | 新增 UC-20 真实性边界：只校验结构和证据存在，不把预期价值自动宣称为已测收益 |

## 触发原因

- 用户要求每一次迭代、每一个设计都记录其要解决的问题。
- 用户要求补录以前已有的设计，而不是只记录本次 CLI。
- 当前主设计文档有详细章节，但缺少一张可供 LLM 快速扫描的价值索引。

## 影响范围

- 新增文档治理和 update-check 结构检查，不改变现有 typed operation JSON、state、gate 或业务行为。
- 后续每次 changelog 必须填写受影响 D-xxx；无设计语义变化允许明确 N/A。
- 历史设计中的量化收益缺少前后基线时标记为“待补基线”，不编造性能结论。
