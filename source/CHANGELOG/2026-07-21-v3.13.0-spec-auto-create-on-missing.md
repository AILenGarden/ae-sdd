# v3.13.0 Spec 缺失自动派生（替代硬阻断）

## 背景

v3.12.1 的主流程监管器在 Step 3 路由时，遇到"新需求无任何产物且非 BUG"会直接
`🔴 阻断：【主流程监管器 ❌ 阻断】新功能开发必须以 PRD 为起点。`，要求用户手工补 PRD
后才能继续。实际项目中，这种硬阻断经常卡在入口：用户已经有明确意图，却被流程锁死。

## 决策

把"硬阻断等用户补 PRD"改为"主流程监管器按规模自动派 {series}-generate 子流程生成
入口 spec"。映射规则：

| 规模 | 入口 spec | 派生 series |
| --- | --- | --- |
| 大 | DR 缺失 → 先 RA（G-RA 前置）→ 再 DR | `requirement-analysis` → `dr-generate` |
| 大（DR 已在） | DR | `dr-generate` |
| 中 / 小 / 微 | Story（小/微走 Story-lite 深度） | `story-generate` |

豁免：`entry_node=OPTIMIZE/CODE_REVIEW/DOC_FORMAT` 三条微链按设计无 spec 直跑；
`entry_node=BUG/CONFIG` 微链复用既有"微任务不生成 spec"约定。

- `source/skill-fallbacks/SKILL.full.md`
  - Step 3 把"🔴 阻断"改为"按规模派生入口 spec"
  - §路由表末行 `🔴 阻断` 改为"按规模派生 spec"
  - §智能路由调用顺序后追加 v3.13.0 总则引用
  - frontmatter `version` 升至 `3.13.0`，description 增 v3.13.0 条目
- `source/SKILL.md`（slim entry）frontmatter `version` 同步升至 `3.13.0`
- `tools/lib/classify.py`
  - `Classification` 新增 `spec_strategy: Optional[dict]` 字段
  - 新增 `_has_dr_doc(project_root)` helper（仅返回布尔，复用 design rglob）
  - 新增 `_derive_spec_strategy(scale, entry_node, source, project_root)`：
    返回 `{"needs": bool, "entry_spec": ..., "series": ..., "auto_create": True,
    "reason": ...}`；三条微链 + BUG/CONFIG 豁免；大任务按 DR 是否存在分流
  - `classify()` 在返回前调用 `_derive_spec_strategy` 填入 Classification
- `tools/bin/ae-sdd` `cmd_classify`
  - JSON 输出追加 `spec_strategy`
  - 文本输出新增"Spec 自动派生"提示行
- `tools/lib/gates.py`
  - G-01 DR 缺失 hint：追加"或由主流程监管器按 classify.spec_strategy 自动派

  - G-02 Story 绑定/缺失 hint（`_story_binding_action`）：追加"或由主流程监管器
    按 classify.spec_strategy 自动派 story-generate"
  - G-STORY-CTX Story 文档缺失分支 hint：同上追加自动派生引导

## 不变量（保留）

- 所有机械门禁仍 fail closed——本次只改 hint 文案，不改 pass/fail 判定
- `L2-DISCIPLINE.md` 的"Story 必须包含接口/字段/主流程/数据模型、AC 和验证矩阵"
  条款不动（这是结果约束，入口派生不影响）
- G-CODEPLAN-SRC / G-14 / G-08（CodingPlan 前置门）不动
- Story-lite 模板深度规则（`coding-skill §5`）不动
- 三条微链（OPTIMIZE/CODE_REVIEW/DOC_FORMAT）按设计仍无 spec
- RA-generate 仍走 4 步子流程（含 Review），G-RA 等门禁照旧生效——自动派生不跳门
- 历史已生成 spec 文件只读兼容，不删除、不改写、不迁移

## 风险与缓解

- **风险**：自动派生让 AI 在纯讨论场景误派流程。
  **缓解**：`classify.spec_strategy` 受 entry_node 消歧前置门（coding-process
  §A1.4）保护；三条微链豁免覆盖最常见讨论场景；BUG/CONFIG 微链也豁免。
- **风险**：大任务自动派 RA 可能跳过用户对需求的理解。
  **缓解**：RA-generate 仍走完整 4 步子流程（含 Review 与 G-RA 门禁），用户
  审核点照旧生效，自动派生只替代"阻断等用户补 PRD"这一个动作。
