# 2026-07-15 | ae-sdd v3.11.2 - 显式 Work Item 恢复命令不再被歧义门禁自锁

## Summary

在包含多个活跃 Work Item 的项目中，`PreToolUse:Bash` 会先调用隐式 `resolve_default_state()`，随后才识别 `ae-sdd state write --work-item <ID> ...`。因此门禁给出的恢复建议本身也会先命中“Multiple ae-sdd work-item states exist”并被拒绝。此次修复让真实 ae-sdd 命令中的显式目标先于隐式候选解析，同时保留无显式目标时的 fail-closed 行为。

## Design ledger impact

| Design ID | Impact |
| --- | --- |
| `N/A` | N/A: no design semantics changed. `source/docs/ae-sdd-design.md` 已规定显式 `--work-item` 定位状态；本次修复 PreToolUse 调用顺序并用回归测试恢复该契约。 |

## Root Cause

- `tools/lib/gate_intercept.py::check_intercept()` 在 `_check_state_write()` 之前统一调用 `resolve_default_state()`。
- `--work-item` 只在后续状态写校验中使用，无法影响前置解析。
- 多 Work Item 歧义错误建议用户执行显式 `state write --work-item`，但调用顺序使这条建议无法执行，形成恢复路径自锁。

## Incident Attribution

本变更修复的是“命令已被识别且携带显式 `--work-item`，却仍先命中隐式歧义”的独立缺陷。后续对 `life` 现场复现确认，当次 `state new` 拒绝的直接触发条件是 Python 后的 ae-sdd 脚本路径带双引号，而旧前缀正则要求 `ae-sdd` 后直接出现空白；该兼容问题由 `2026-07-15-v3.11.2-quoted-command-prefix-compatibility.md` 单独记录和修复。两项修复可组合，但因果归属不得混写。

## Behavioral Invariants

- 未携带 `--work-item` 且存在多个活跃状态时，仍拒绝并要求用户选择目标。
- 显式目标不存在时直接拒绝，不回退到 session、唯一候选或最近状态。
- 显式选择只决定校验对象，不绕过状态迁移、phase 权限、memory 或 gates。
- readonly Bash 和重定向写入的既有判定保持不变。
- `source/docs/ae-sdd-design.md` 无需修改：其中“显式 `--work-item` 定位状态”的产品语义未变，本次修复使 PreToolUse 实现恢复一致。

## Impact

- 改变 PreToolUse Hook 的 Work Item 解析顺序，但不新增 CLI、状态字段、phase、文档路径或子 SKILL 职责。
- `ae-sdd-monitor` 只读投影的数据结构与状态语义不变，无需联动。
- 沿用当前 `v3.11.2` 母版版本，不修改 README 或其他版本锚点；无下游适配要求。
- 对无显式目标的多状态命令继续 fail-closed，无安全降级。
