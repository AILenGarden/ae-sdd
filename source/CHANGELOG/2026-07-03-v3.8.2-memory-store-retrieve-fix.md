# 2026-07-03 | ae-sdd v3.8.2 - 五层记忆存取断裂修复

## Summary

用户实战使用 ae-sdd 后发现五层记忆系统从未生成任何 memory 数据。根因排查确认存取两端均断裂：(1) 存端 memory gate 只挂在 `ae-sdd state write --phase` 单一触发点，Agent 不调 state write 直接写源码时 PHASE_PERMIT 放行，完全绕过 memory 门禁；(2) 取端 `prompt_inject.inject()` 从不读 `memory_store`，`memory enter` 内部虽调 `read()` 返回 entries 但只到 CLI stdout，没有任何机制把历史记忆注入 LLM 上下文——memory 沦为只写不读的黑洞。本次三端联动修复：存端补 PreToolUse hook 兜底、取端补 UserPromptSubmit 注入、一致性层补 `is_scope_active` 活跃态判断与 harness 元数据行数修正。

## 触发原因

- 用户实战跑完 ae-sdd 流程后发现全盘搜不到任何 `.jsonl` 记忆文件、`.ae-sdd/` 目录、`state.json`，确认 memory 系统从未真正运行。
- 排查确认：门禁代码本身正确（6 测试全过），但触发点单一（只挂 state write），Agent 不调 state write 就绕过；取端 prompt_inject 完全不读 memory_store，LLM 永远看不到历史记忆。
- 这是"设计文档完备、测试齐全、门禁已通电，但从未在真实流程中跑过"的典型断裂——基础设施层完备，编排层断线。

## 影响范围

- **存端行为变化**：关联 phase（ra/design/coding-plan/coding/review）的 Write/Edit/MultiEdit 操作现需先 `ae-sdd memory enter` 才能放行。未 enter 时 PreToolUse hook 物理拦截，deny reason 含完整修复命令。
- **取端行为变化**：memory enter 后的活跃 scope 下，每次 UserPromptSubmit 自动注入该 story 当前 phase 的最近 8 条 L1+L2 记忆。exit 后停止注入。
- **向后兼容**：`last_exit_at` 是新增字段，旧 `.stage` 文件无此字段时 `is_scope_active` 视为活跃（有 enter 无 exit）。非关联 phase（initialized/completed/paused）不受影响。
- **harness 元数据**：agent.md 引用源行重跑 `build_harness.py` 后自动反映真实行数，不再撒谎。
