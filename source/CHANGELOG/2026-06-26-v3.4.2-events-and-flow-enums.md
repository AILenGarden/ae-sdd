# 2026-06-26 | ae-sdd v3.4.2 - state.json events 操作日志 + flow_enums 枚举体系

## Summary

v3.4.0 引入 PRD 级 state.json + 11 phase 状态机后，子任务级操作可追溯性仍弱（phase 字段只记"当前在哪"，history 只记阶段切换，**无细粒度 audit trail**）。本次新增 `events` 操作日志字段（state.json schema v1→v2），提供路由 / 门禁 / 阶段切换 / 用户确认四类事件的 append-only 记录能力。配套新增 `tools/lib/flow_enums.py` 定义三枚举（FlowNode / FlowSkill / FlowEventType）+ FlowEvent 数据类 + 5 工厂函数。**业务调用方（router / state write / gate check）尚未接入 events.append_event()，本版本仅完成 schema + lib 层 + 32 个单元测试；调用方接入留待后续 PR**。

## 触发原因

- **运维场景痛点**：用户问"STORY-020-BE 昨天为什么 Phase 2 没走完？"时，AI 只能查 `phase` + `history`，无法还原"哪一步门禁拦截了、是哪个 gate_id、谁确认的"——缺乏细粒度 audit trail。
- **v3.4.0 PRD 级 state 已发布但子任务级追溯缺失**：PRD 级 state.json 聚合了所有 Story 状态，但单个 Story 内的"路由→门禁→确认→完成"全过程无结构化记录。
- **承接 v3.4.0 提案**：`source/CHANGELOG/2026-06-25-v3.4.0-proposal-node-relative-state-model.md` 已勾画"v2 schema + events 字段"方向（标注"提案，未实施"），本次落地 lib 层。

## 影响范围

- **运行时逻辑**：lib 层新增 `append_event` / `get_events`；state.json schema v1→v2（向后兼容：旧 state.json 无 events 字段时 `get_events()` 返回 `[]`）。
- **CLI 命令**：无新增（events 不暴露 CLI 调用面）。
- **门禁**：无新增/修改（events 不参与 22 门禁拦截判定）。
- **子 SKILL 边界**：无变化（events 不改变 SKILL 职责划分）。
- **版本号推进**：3.4.0 → 3.4.2（**跳过 3.4.1**，因 v3.4.1 已签收并发布"只改分发不升级 SOP"的语义边界，本次按 patch 命名规则在 v3.4.x 末位 +1）。
- **破坏性变更**：state.json schema v1→v2 是向后兼容扩展（仅新增 optional 字段），**不破坏**已有 v1 reader。
- **未闭环项（已知缺口）**：router / state write / gate check / SKILL orchestrator 五个调用点尚未接入 `append_event()`；本次 PR 仅完成 schema + lib + 测试。
