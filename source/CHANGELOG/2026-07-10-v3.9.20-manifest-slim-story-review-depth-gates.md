# 2026-07-10 | ae-sdd v3.9.20 - 三症同治：manifest 瘦身 + Story 已引用门禁 + Review 深度门禁

## Summary

用户反馈 ae-sdd 频繁出问题：(1) 加载 manifest 太慢（1000+ 行 token 膨胀）；(2) Story 不按要求加载上下文、不按标准做事；(3) Review 总是发现不了真实问题。

根因探查确认这三个症状是**同一个架构级病根**：ae-sdd 把流程纪律几乎全押在 LLM 自觉（prose），机械门禁要么只查文件存在、要么不存在。具体——bootloader 要求 LLM 读整份 52KB manifest（含 13k tokens 纯哈希垃圾）；G-STORY-CTX 只查 `bool(assets)` 文件存在不查是否真读了 + 小/微链豁免；Review 完全无深度门禁（"🔴 硬门禁"是装饰性标签，skill 自承 report-only），且 G-REVIEW-LOOP 把"连续零发现"当成功条件（奖励发现不了问题）。

统一解法：**"已读"无法机械验证，但"已引用"可以**——查产物证据，不查行为。本次拆双文件治 token 膨胀、G-STORY-CTX 升级为真"已引用"门禁、新增 G-REVIEW-DEPTH 禁裸✅+零发现举证。

## Notes

- 统一哲学：**查产物证据，不查行为**。不建立"读取痕迹"登记（被动登记 = 回到 LLM 自觉老路），G-STORY-CTX 的 standardsRef 直接查 Story 正文是否引用约束条目，G-REVIEW-DEPTH 直接查报告是否附证据。
- G-REVIEW-DEPTH 当前只覆盖 CodeReview 报告（category="CR"）；DR Review / Story Review 内容审查项仍 report-only，后续可扩展。
- 证据信号收紧：移除 `SQL`/`约束`/`标准` 等过泛词（易误命中表格行），只保留强定位信号（行号/file:line/报文/Mapper SQL/§引用）；window 收紧到当前行+下一行。
