# 2026-07-09 | ae-sdd v3.9.16 - Claude prompt 字段兼容与会话级 work-item 绑定

## 背景

life 项目存在多个 `.auto-engineering/*/state.json`。v3.9.13 起 gate 正确拒绝隐式选择 work-item，避免 A/B 会话串状态；v3.9.15 又把无副作用 `echo test` 等只读 Bash 放到 state 解析前放行。但实测 Write/Edit 仍被 `Multiple ae-sdd work-item states exist` 拦截。

根因不是 Write/Edit 工具本身，而是 `UserPromptSubmit` hook 没有建立 session 绑定：runtime-stats 中 `prompt-inject` 的 `promptLen=0`，说明新版 Claude Code payload 使用 `prompt` 字段时，旧入口只读取 `user_prompt`，导致 prompt-inject 看不到 `cs-ai-STORY-005-BE`，也就不会写 `.ae-sdd/session-context/`。

同时，life 的 work-item key 是 `cs-ai-STORY-005-BE` 这类项目特定完整 ID。旧正则会从中截出 `STORY-005-BE`，无法命中 `.auto-engineering/cs-ai-STORY-005-BE/state.json`。

## 改动

| 文件 | 改动 |
| --- | --- |
| `tools/bin/ae-sdd` | `prompt-inject` 兼容读取 `prompt`/`message`/`text`，并从 hook payload 的 `cwd` / `project_dir` / `projectDir` 定位项目；`gate-intercept` 同样支持 payload `cwd` |
| `tools/lib/work_item_context.py` | prompt 解析先匹配已存在 work-item state 中的真实标识（目录 key、workItemKey、stateMachineId、currentStory、storyId、storyStates 等），再回退到 STORY/R6 正则 |
| `tools/lib/prompt_inject.py` | 对 `STORY-005-BE` 与 `cs-ai-STORY-005-BE` 这类包含式别名做同一 Story 判断，避免绑定成功后又误报“未被任何 state 管理” |
| `tools/tests/test_prompt_inject_plugin.py` | 覆盖新版 `prompt` 字段、`session_id`、完整 work-item key `cs-ai-STORY-005-BE` 的 session-context 绑定 |
| `tools/tests/test_gate_intercept.py` | 覆盖多 work-item 下 session 绑定后的 Write 不再因歧义被拦；绑定到 `completed` 时仍按 phase 冻结拒绝 |
| `source/docs/ae-sdd-implementation-architecture.md` | 补充 `.ae-sdd/session-context/` 是会话级绑定缓存，不是全局 active state |

## 行为边界

- 不恢复 `.ae-sdd/state.json` 作为 active state、mirror 或 fallback。
- 不把 `completed` 阶段改成可写；绑定到已完成任务时，Write/Edit 仍应按 `phase=completed` 拒绝。
- 不放开带重定向的 Bash：`echo test > out.txt` 仍属于写入类操作，必须先由 session 绑定解析到唯一 work-item，再按 phase/memory gate 判定。

## 验证

- `python -m pytest tools/tests/test_prompt_inject_plugin.py tools/tests/test_gate_intercept.py -q`
- 安装后在 `D:\Item\life` 复测真实 Claude hook：带 `prompt` + `session_id` 的 UserPromptSubmit 会写入 `.ae-sdd/session-context/`，后续同 session 的 Write 不再报 work-item 歧义；绑定到 completed work-item 时拒绝原因变为 `phase=completed`。
