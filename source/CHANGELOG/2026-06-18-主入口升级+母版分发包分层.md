### 2.2 三层架构（v3.0 Layer 模型）

```
Layer 1: 母版（SSOT）
    source/                              ← 开发者编辑这里
    ↓ bash scripts/build-dist.sh
Layer 2: 实例化分发包
    dist/ae-sdd/                         ← 构建产物，git ignored
    ↓ bash scripts/install.sh
Layer 3: 用户安装
    ~/.claude/skills/ae-sdd/             ← Claude Code 实际加载

Layer 4: 项目实例（v3.0 P0 待实施）
    <project>/.ae-sdd/                   ← ae-sdd init 产出
```

## Why（设计动机）

v2.x 的 `source/ + plugins/ae-sdd/ + ~/.claude/skills/.../skills/ae-sdd/` 三目录结构存在两个根本问题：

1. **`plugins/ae-sdd/` 是"全树镜像"**：每次 sync 把根目录的 `.idea/`、`.gitignore`、`CHANGELOG/`、`docs/`、`logs/`、`scripts/` 全部复制过去——分发到用户机器上等于把仓库管理产物搬回家。
2. **维护者 vs 用户边界模糊**：仓库根改一行 → `plugins/ae-sdd/` 改一行 → 本地 skills 改一行，三处容易漂移且没人知道哪个是"权威"。

v3.0 用**双目录分层**解决：
- `source/` = 母版（SSOT），开发者只改这里
- `dist/ae-sdd/` = 构建产物，由 `build-dist.sh` 生成
- 用户装的是 dist，**与母版物理隔离**

加上**三层架构**（Layer 1 母版 → Layer 2 分发 → Layer 3 安装）显式建模，每层职责单一、转换工具明确。
