# 2026-07-16 | ae-sdd v3.11.4 - RA 门禁锁定当前 Work Item 的正式正文

## Summary

G-RA scanner 过去从项目根宽泛枚举所有 RA-like Markdown，导致 references、templates、CHANGELOG、dist 副本、GeneratePlan/Impact 等事件附件和其他 Work Item 的 RA 共同参与当前门禁。结果是当前正式 RA 已合格，流程仍被无关文档产生的 BLOCKER 锁住。

本次新增统一的 RA scan scope，将 Work Item 门禁改为先解析 selected RA，再以 `--file` 精确调用四个 scanner；根目录审计保留，但只枚举 formal RA candidates。与此同时补齐 CLI、构建分发、结构化错误、文档落地退出码和 update-graph 闭环。

## Design ledger impact

| Design ID | Impact |
|---|---|
| `D-005` | G-RA-1~6/FLOW 改为共享 state binding/latest formal resolver，消除不同门禁选择不同 RA 的路径漂移。 |

## 触发原因

- 用户实测当前 native workflow RA 单文件扫描 0 BLOCKER，但项目级 G-RA-6/FLOW 被第三方 guide、GeneratePlan、模板、CHANGELOG 和 dist 副本锁住。
- 四个 scanner 各自维护宽泛 `rglob` 规则，gate 又只传项目根，缺少 Work Item authoritative scope。
- PowerShell 连续执行命令时未检查中间 `$LASTEXITCODE`，后续成功把前序 `doc save` 的 exit 1 覆盖成最终 0，曾被误判为 CLI 自身返回码错误。

## 影响范围

- 改变 G-RA-1~6/FLOW 的 RA 选择与 scanner 调用范围；selected RA 自身的 blocker 语义不变，仍 fail closed。
- root audit 仍可用，但 RA-like 非权威文档不再进入候选；canonical 和 legacy formal RA 保持兼容。
- 新增一个 CLI 子命令和一个 runtime helper，无数据库、schema 或迁移；不手工修改 dist。
- 版本号不推进，沿用 v3.11.4；无破坏性参数变更，`--root` 兼容保留。
