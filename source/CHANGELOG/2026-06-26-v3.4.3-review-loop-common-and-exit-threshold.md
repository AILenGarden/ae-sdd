# 2026-06-26 | ae-sdd v3.4.3 - Review Loop 公共协议 + 退出阈值统一 3 轮 + 删除"每3轮暂停问人"

## Summary

排查发现 ae-sdd 的 review loop 体系存在三类系统性问题：① 退出阈值全仓不统一（1 轮/2 轮混用，无任何节点用 3 轮）；② story-review/dr-review/SKILL.md 三处"每 3 轮暂停问人"与"连续 N 轮无新增退出"自相矛盾（同一文件内退出条件 vs 人工暂停并存，AI 执行时困惑）；③ task-generate TR Review 无循环上限（只有"连续一轮无新增退出"，无"3 轮上限升级用户"，理论上 AI 可无限"自评通过"，是安全漏洞）。本次新建 `cross-cutting/review-loop-skill.md` 公共协议统一 loop 骨架（退出条件 3 轮 + 循环上限 3 轮 + Plan-first），6 个 review 节点退出阈值统一为"连续 3 轮无新增缺陷"，废弃"每 3 轮暂停问人"（违反 Loop Engineering 自评估原则），修复 task-generate 无上限漏洞。

## 触发原因

- **用户反馈**：用户设定是"一直自己挖掘缺陷并自修复，连续三轮找不到缺陷才退出"，但盘点发现全仓没有任何节点用 3 轮退出阈值（1 轮/2 轮混用），且 story-review/dr-review 的"每 3 轮暂停问人"与退出条件直接矛盾——设定从未正确落档。
- **Loop Engineering 对齐**：用户确认每个流程节点都是独立 Loop Engineering，"每 3 轮暂停问人"把退出权交给人，违反 Loop Engineering 自评估原则。删除后 AI 自评估达标即退出，3 轮仍有 🔴 才升级用户。
- **安全漏洞修复**：task-generate TR Review 无循环上限，AI 可无限"自评通过"，与用户担心的"审不出问题"直接相关。加 3 轮上限 + 升级用户兜底。
- **common 化**：之前各 review SKILL 各写各的退出条件/循环上限/暂停规则，文案被抄来抄去连矛盾一起抄。新建公共协议统一 loop 骨架，各 SKILL 只写专属配置。

## 影响范围

- **纯文档变更**：不涉及 CLI 工具代码或运行时逻辑，只改 SKILL 规则文本。
- **流程行为变化**：① 删除"每 3 轮暂停问人"后，story-review/dr-review 的 review 循环不再中途打断问人，AI 自评估达标（连续 3 轮无新增）即退出；② 退出阈值从 1/2 轮统一为 3 轮，循环时间变长（给 AI 最多自纠错机会）；③ task-generate TR 加 3 轮上限，超限升级用户。
- **版本号推进**：3.4.2 → 3.4.3（patch 级，规则统一 + 安全漏洞修复）。
- **无破坏性变更**：各 review 节点的检查项/A-E 阶段定义/Plan 载体不变，只统一 loop 骨架。
- **未闭环项（已知缺口）**：story-review L1213 vs L1225 的 Plan-first 内部矛盾（2026-06-06 重构遗留），本 PR 不处理，留待下个 PR。
