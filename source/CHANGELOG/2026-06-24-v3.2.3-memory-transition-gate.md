# 2026-06-24 | ae-sdd v3.2.3 - Memory Transition Gate

## Summary

Memory management is now enforced at the state transition layer. The previous
v3.2.2 rule required Skills and Agents to call `memory enter`, `memory write`,
and `memory exit`; v3.2.3 makes `ae-sdd state write --phase ...` verify that
the current associated phase has completed that lifecycle before the phase can
advance.

## Changes

| Area | Change |
|---|---|
| Memory | Added non-mutating `memory_store.check_exit_ready()` so gates can validate memory without writing an exit event |
| State transition | Added `tools/lib/memory_gate.py` shared by CLI and hook enforcement |
| CLI | `ae-sdd state write --phase <next>` now blocks when the current associated phase has no `memory enter` and later `memory write` |
| Hook | `gate_intercept` runs the same memory gate before entry-gate checks |
| Override | Added `--allow-empty-memory` maintenance override for explicit migrations and repairs |
| Docs | Updated memory layering, memory-management skill, toolset orchestration, README, and SKILL version |

## Enforced Phases

| State phase being left | Memory phase checked |
|---|---|
| `dr-generated`, `story-generated`, `story-reviewed` | `design` |
| `task-generated`, `task-reviewed` | `coding-plan` |
| `coding`, `test-running` | `coding` |
| `code-reviewed` | `review` |

`initialized` is intentionally not blocked by this gate because the first
downstream artifact may establish the initial story scope.
