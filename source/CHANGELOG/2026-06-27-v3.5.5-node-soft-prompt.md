# 2026-06-27 | ae-sdd v3.5.5 - 主会话职责收口 + 节点级上下文压力软提示

## Summary

**背景/痛点：** ae-sdd 长期存在两个使用痛点。① **主会话职责不清**：v3.5.4 及之前的默认是"单 Agent 串行做所有事"，主会话被迫读 23 个子 SKILL、读源码、写文档、做 walkthrough、跑测试 → 上下文爆炸；§🤖 章节虽然定义了 8 类 sub-agent 角色，但只在"何时启用"表的 6 类触发条件命中时才派活，单 Story 流程主会话承担了过多职责。② **节点级无上下文压力信号**：v3.3.0 引入 PRD 级 compact（`mavis session rotate --handoff-file`，事后收尾）+ v3.5.2 加 ⑦ter 自检 + v3.5.4 加 HS-8 compact 失败检测 — 但都是事后机制，**没有事前预警**，主会话跑到第 4 个审核点时已被吃满，AI 自己也感知不到继续硬扛。

**本次做了什么：** 两部分 —— ① **主会话职责收口**（v3.5.5 升级）：SKILL.md §🤖 章节新增"主会话职责边界"小节（主会话 = 路由 + 编排 + 汇总 + 讲解 + 用户对话，其他全部派 sub-agent），agent-orchestration-skill.md 新增 §8.5 默认单 sub-agent 模式 + §8.6 节点级派活清单（6 个审核点 → sub-agent 角色映射表）。② **节点级上下文压力软提示 CLI**（v3.5.5 新增）：新建 `ae-sdd context-pressure` 子命令（`tools/lib/context_pressure.py` + `tools/bin/ae-sdd:cmd_context_pressure`），5 信号采集（session.userConfirmedPhases / state.events / state.history / state.activeAgents / 落盘文档总字节）+ 与可配置阈值比对输出 low/medium/high/critical 评级；6 个审核点边界（1/1.5/2/2.5/4/5）必调一次，report-only 不阻断流程。SKILL.md 新增 `## ⏱️ 节点级上下文压力软提示` 章节，整体流程图 6 个审核点后加 ⏱️ 标记。

**达成的效果：** 主会话职责边界清晰（默认派 sub-agent，单 Story 也派），主上下文不再被读源码/写文档机械劳动压满；6 个审核点边界有客观信号预警剩余容量，critical 时给出推荐动作清单（PRD 收尾 / compact / 拆分 Story）由用户决定；与 v3.3.0 PRD 级 compact（事后收尾）互补不替代。落地强度按用户选定"SKILL 文字 + CLI + 测试"三件套：lib/dataclass + bin/subparser + tests/15 用例，全部真实物理实现，不重蹈 v3.5.4 修补的"声明但零实现"覆辙。

## 触发原因

- 用户需求（原话）："嗯..软提示吧，但是我觉得ae-sdd应该设计成这样，当前会话主处理流程事务，其余事务都交给sub-agent处理。" —— 用户明确选择软提示形式 + 主会话职责收口设计
- 探查发现的设计 gap：v3.5.4 §🤖 章节虽然定义了 8 类 sub-agent 角色（:726-810），但"何时启用"表（:691-703）的 6 类触发条件对单 Story 流程完全不命中 → 默认仍是单 Agent 直做，主上下文爆炸
- 探查发现的运行 gap：v3.3.0 PRD 级 compact + v3.5.2 ⑦ter 自检 + v3.5.4 HS-8 都是事后机制，6 个审核点边界无客观信号预警
- 衍生决策：主会话职责收口（默认派活）+ 软提示（不强制）→ 派生本 v3.5.5 设计

## 影响范围

- **新增 CLI 子命令**：`ae-sdd context-pressure [--story <STORY-ID>] [--json]`（report-only 不阻断）。现有 CLI 命令契约不变。
- **新增 AE 编排层节点**：6 个审核点边界必调 context-pressure（不阻断）。现有 14 门禁 / ⑦ter / HS-7/8 不动。
- **新增文档章节**：SKILL.md §🤖 主会话职责边界小节 + §⏱️ 新章节；agent-orchestration-skill.md §8.5/8.6。现有章节结构不变。
- **无破坏性变更**：软提示只新增预警，不替代 v3.3.0 PRD 级 compact；主会话职责收口是"默认派活"语义，用户可显式豁免（记录到 state.json.contextNote 可选）；现有微任务（类型 4）+ BUG/配置类主会话直做路径不变。
- **不涉及运行时逻辑变更**：state.json / session.json schema 不变（5 信号全为已有字段读取，无新 schema 必填）。
- **版本号推进 3.5.4 → 3.5.5**：需 UC-01 三处一致（SKILL.md / paths.py / README），已同步。
