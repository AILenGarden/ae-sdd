# 2026-07-10 | ae-sdd v3.10.0 - 砍 Task phase + Route 下移重分级

## Summary

ae-sdd 在 ClaudeCode/Codex 实现一个 Story 耗时长达 8 小时，根因是流程过于繁琐：Task 生成 + Task Review（TR-1~TR-7 review-loop，≥3 轮无新缺陷才退出）是一个完整文档+审查循环，但产出的骨架信息在 CodingProcess 中又被重新展开，存在冗余。

本次变更**砍掉 Task phase**，将骨架分解（类名/包路径/方法签名/≤10行伪代码）合并进 CodingProcess §A1.5，CodingPlan 不再依赖 Task 文档作为输入，直接从 Story+TestCase 派生。同时**Route 下移重分级**：大=DR入口、中=Story入口、小=CodingPlan入口（新增）、微=无文档。精简后流程为 `Story -> TestCase -> CodingPlan -> Coding -> Test -> Review（含实现报告）`。Review 4 个 skill（test-generate/test-review/coding-report/code-review）及全部 Review 门禁完整保留，质量保障不丢。

## 触发原因

- 用户反馈：ae-sdd 在 ClaudeCode/Codex 实现 1 个 Story 耗时 8 小时，流程太繁琐，要求精简为 Story->TestCase->CodingPlan->Coding->Test->实现报告
- Task Review 的 review-loop（G-05/G-06 + TR-1~TR-7 ≥3轮）是最大时间消耗点，而 Task 产出的骨架在 CodingProcess 中被重新展开，存在冗余
- Route 分级与实际入口产物脱节：原 大=PRD 层实际很少使用，用户从 DR/Story 入手更常见

## 影响范围

- **破坏性变更：scale 语义下移**。旧 state.json 的 scale 值需重新解释：旧 大(PRD)->弃用、旧 中(DR)->新 大、旧 小(Story)->新 中。旧含 task-generated/task-reviewed phase 的 state 可正常读取（gate 注册保留），但不会在主流程触发
- **门禁行为变更**：G-05/G-06/G-TASK-CTX 仍注册但不再在 PHASE_ENTRY_GATES 中触发（死代码，保留兼容）。新增 coding-process 入口门禁（大/中/小链 G-02/G-03/G-04/G-STORY-CTX/G-TESTCASE-CTX）
- **新增 FlowNode.BUG 枚举** + build_state_machine_name 支持 BUG/PLAN 顶层名
- **Skill 职责边界变更**：coding-process-skill 吸收 task-generate 的骨架分解职责；task-generate-skill 标 DEPRECATED
- 版本号推进 3.9.22 -> 3.10.0（UC-01 三处一致）
- Review 4 skill + 全部 Review 门禁 + CodingPlan 门禁（G-07/G-08/G-14/G-CODEPLAN-SRC）完整保留
