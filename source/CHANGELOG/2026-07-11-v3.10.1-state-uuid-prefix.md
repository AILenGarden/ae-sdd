# v3.10.1 - state 创建时带随机 UUID 前缀保证唯一性

**日期**：2026-07-11
**类型**：BREAKING（state 目录名格式变更）+ 向后兼容（旧 state 可读）

## 背景

用户要求：创建 state 时最前面带随机 UUID，保证唯一性，不存在全局 state。

现状确认：
- 全局 state（项目级 `.ae-sdd/state.json`）在 v3.9.13 已移除，`--project-state` 传入即抛错。
- state 标识由 `paths.build_state_machine_name()` 确定性派生（`PRD-IM-CS` / `DR-CS` / `Story-003-004`），无 UUID。
- 唯一性隐患：同业务名撞目录会互相覆盖（如两个 PRD 特征都叫 `IM-CS`）。

## 变更

### state.json schema 新增字段

| 字段 | 旧 | 新 |
|---|---|---|
| `stateMachineId` | `PRD-IM-CS`（=目录名） | `{uuid}-PRD-IM-CS`（带 UUID 前缀） |
| `stateMachineName` | 不存在 / =目录名 | `PRD-IM-CS`（纯业务名，供查找匹配） |
| `stateUuid` | 不存在 | `{uuid}`（冗余标识） |

`stateMachineName` 和 `stateUuid` **可选**（旧 state 缺失时从 stateMachineId/目录名推导）。

### 目录名格式

- 旧：`.auto-engineering/PRD-IM-CS/state.json`
- 新：`.auto-engineering/{uuid}-PRD-IM-CS/state.json`

### UUID 生成时机

UUID 只在**创建时生成一次**并持久化，不在确定性函数 `build_state_machine_name` 中生成（否则每次解析 features 产不同 UUID，永远找不到已存在 state）：

- `cmd_state_new`（用户创建入口）：`paths.generate_state_uuid()`
- `recursive_r2_absorb(generate_uuid=True)`（递归归入创建顶层）
- `_ensure_parent_nested_state(generate_uuid=...)`（递归创建父级）

### 查找匹配增强

- `find_work_item_state_path` 增加后缀匹配：传业务名 `PRD-IM-CS` 可命中 `{uuid}-PRD-IM-CS` 目录。
- `_state_matches_work_item` / `_state_identifier_values` candidates 加入 `stateMachineName` 字段。
- `find_nested_state_by_*`（按 story/dr/prd ID 查找）不受影响（已按 JSON 内容匹配）。

### 防重复创建

`cmd_state_new` 的防重复检查从 `sp.exists()` 改为 `find_work_item_state_path(work_item_key)` 后缀匹配，保证同业务名撞目录时不覆盖（UUID 前缀后 `sp.exists()` 永远 False，旧机制失效）。

## 改动文件

| 文件 | 改动 |
|---|---|
| `tools/lib/paths.py` | 新增 `generate_state_uuid`/`strip_uuid_prefix`/`has_uuid_prefix`；扩展 `work_item_state_path(state_uuid=)`/`find_work_item_state_path`（后缀匹配）/`_state_matches_work_item`（加 stateMachineName） |
| `tools/lib/state.py` | `init_nested_state(state_uuid=)` 拼接 stateMachineId + 写 stateMachineName/stateUuid；`recursive_r2_absorb(generate_uuid=)` + `_ensure_parent_nested_state(generate_uuid=)` 透传 |
| `tools/bin/ae-sdd` | `cmd_state_new` 生成 UUID + 防重复改后缀匹配 + 回填 stateMachineName/stateUuid；`_resolve_top_node_from_token` 用 stateMachineName/strip_uuid_prefix 派生 features |
| `tools/lib/prompt_inject.py` | `top_node[4:]`/`top_node[3:]` 切片改用 `strip_uuid_prefix` 后再切 |
| `tools/lib/work_item_context.py` | `_state_identifier_values` 加 stateMachineName |

## 向后兼容

1. 旧 state 目录（无 UUID 前缀）仍可读：`find_work_item_state_path` 精确匹配分支保留。
2. 旧 state.json（无 stateUuid/stateMachineName 字段）仍可读：字段可选，缺失时 `strip_uuid_prefix` 从 stateMachineId/目录名推导。
3. `init_nested_state` / `recursive_r2_absorb` 默认不生成 UUID（`state_uuid=None`/`generate_uuid=False`），测试和内部调用不受影响。
