# 2026-07-01 | ae-sdd v3.7.2 - 文档读写散点统一收敛到 document-storage 函数式调用

## Summary

ae-sdd 体系长期存在"声明合规、实现违规"的系统性矛盾：各子 SKILL 在 §前置调用中声明"写入前必须先调用 document-storage-skill，不手写路径"（A 类合规声明），但随后的存放表、产物清单、闸门、路由决策表中又硬写 `{工程根}/ae-sdd-doc/iterations/.../DR/...` 字面路径（C 类违规），形成路径模板的"多副本漂移"风险——改 SSOT 一处，子 SKILL 漂移 N 处。同时 D 类违规（直接引用 `{projectKey}.assets.md` 文件名而非走 `ae-sdd assets read` CLI）在 4 个文件中残留 6 处，与已有的"禁止直接读取 assets.md 全文"声明冲突。

本次全盘扫描 28 个 SKILL + SKILL.md 主入口，按 A/B/C/D/E 五类逐节点判定读写方式，识别出 8 个文件共 ~45 处 C/D 类违规。通过 3 种改造模式（存放表→API 调用列+SSOT 指针、产物清单/闸门→API 调用断言、assets.md 引用→`ae-sdd assets read` CLI），将所有子 SKILL 中的字面路径副本消除，单一权威源收敛到 `document-storage-skill.md §2.2/§3.2`。同时在 intent 枚举表补注册 `PRD`/`ISSUE` 两个 intent，确保 `requirement-analysis-skill` 生成 PRD/Issue 时调用 `save_doc(intent=...)` 有合法 intent。

## 触发原因

- 用户需求："请全盘扫描 ae-sdd，找出所有【读 ae-sdd 输出/关联的文档】、【输出/更新文档】的节点。全部改成统一调用 document-storage-skill（函数式调用）"
- 系统性矛盾：各子 SKILL 声明"禁止硬编码路径"但存放表/产物清单中又硬写字面路径，形成"声明合规、实现违规"
- SSOT 漂移风险：路径模板散落在 5 个子 SKILL 中各持副本，改 SSOT 一处漂移 N 处
- intent 缺口：requirement-analysis-skill 生成 PRD/Issue，但 intent 枚举表未注册 `PRD`/`ISSUE`，改造后调用 `save_doc(intent="PRD"/"ISSUE")` 缺合法 intent

## 影响范围

- **纯文档修订**：无代码逻辑变更，无工具链改动，无门禁行为变更
- **SSOT 一致性**：改造后所有子 SKILL 零字面路径副本，单一权威源在 document-storage-skill.md §2.2/§3.2
- **版本号推进**：v3.7.1→v3.7.2，3 处一致性（SKILL.md frontmatter + paths.py + README.md:5）
- **新增 intent**：`PRD`/`ISSUE` 补注册到 document-storage §15.1.1
- **无破坏性变更**：不改变已有门禁、子 SKILL 职责边界、文档存放路径（路径模板本身未改，只改子 SKILL 引用方式）
- **不改的文件**：document-storage-skill.md（SSOT，路径定义本身）、docs/migration-guide.md（迁移工具说明）、CHANGELOG/（历史记录）、story-generate/review/update + testcase-generate/review + dr-update（已合规）
