# 2026-06-27 | ae-sdd v3.5.4 - 迭代检查硬化为 CLI + P0 撒谎项修复

## Summary

**背景/痛点：** v3.5.3 把"设计-实现一致性迭代检查"固化为人工 SOP（ae-sdd-update-skill.md），但 SOP 步骤 2/3/4 仍是全人工粗筛（grep HARNESS/grep SKILL/grep stop_check + 读代码），工作量大、漏检风险高。同时 2026-06-27 首次迭代检查发现 6 项 🔴 文档撒谎（HS-4/6/7/8 物理拦截声明实为零、SKILL.md v3.0 sync-tools/rules.yaml 幽灵命令残留、document_storage.py 实现未接入）和 3 项 🟡 部分一致（F-1 只覆盖 G-08、HS-10 靠文本兜底、health 误报）。

**本次做了什么：** 两部分 —— ① P0 修复：HS-7/8 补物理实现（HS-7 PreToolUse 拦截 prd-complete 实时跑 4 层 AND + HS-8 Stop hook 检测 compact 卡住态，HS-4/6 诚实自认降级待 events/testCodeAuditedAt 落地后补物理拦截），删 SKILL.md 幽灵命令段（v3.0 残留）。② 迭代检查硬化：新建 `ae-sdd iteration-check` 子命令跑 IC-1~4 机器粗筛（report-only 不阻断），接管 SOP 步骤 2/3/4 人工粗筛——补 UC-01~07 自动检查的 4 类盲区。

**达成的效果：** HS-7/8 文档声明从"靠 SOP"升级为真物理拦截（HS-7 堵住 `cmd_state_prd_complete` 跳 4 层 AND 漏洞，HS-8 堵住 compact 失败时旧 state.json 被覆盖）；迭代检查从全人工升级为"机器粗筛 + 人工复核语义"，消除粗筛工作量；SKILL.md 幽灵命令段清除。

## 触发原因

- 用户需求（原话）："要，而且还要确认这个流程能不能硬化。"
- 2026-06-27 首次人工迭代检查实证：6 项 🔴 文档撒谎 + 3 项 🟡 部分一致，证明 UC 自动检查存在结构性盲区，需补人工/Agent 深度核对 SOP + 硬化 CLI。
- 用户决策：选项 B（新建 iteration-check 子命令）+ 全部补物理实现。后者实施中发现 HS-4/6 依赖尚不存在的标记机制（events 接入 + testCodeAuditedAt），强行补读取校验会"永远拦死"，故 HS-4/6 改为降级声明（与 HS-3/5 对齐）。

## 影响范围

- **HS-7 物理拦截影响**：任何 `ae-sdd state prd-complete` 命令执行前会被 PreToolUse 拦截，实时跑 4 层 AND 校验。无 `prd-check-complete` 证据或 4 层未全过 → 阻断。cmd_state_prd_complete 内部"简化"注释的漏洞被堵。
- **HS-8 物理拦截影响**：session 结束时（Stop hook）检测 PRD 级 `prdStatus=awaiting_compact` 无 `summary.md` → 阻止停止 + 报警"compact 失败，旧 state.json 已保留"。compacted 状态或有 summary.md 放行。
- **新增 CLI 子命令**：`ae-sdd iteration-check [--project] [--json]`，report-only 不阻断 dev-sync。产出 4 类检查的结构化报告（findings + severity + location + detail）。
- **SKILL.md §🛠️ 工具 API 速查重写**：删 v3.0 幽灵命令表（assets check/generate/update/audit + sync-tools + state validate/show/diff/lock + run/quick + Node.js ESM/.mjs/rules.yaml 描述）。保留正确命令清单（资产/状态机/路由/门禁/Toolset Layer/维护）。
- **HS-4/6 降级声明**：HARNESS.md 措辞改为"声明但无物理实现，靠 XX 兜底"（与 HS-3/5 对齐）。无物理拦截语义变化，仅文档诚实。
- **版本号推进 3.5.3 → 3.5.4**：需 UC-01 三处一致（SKILL.md / paths.py / README），已同步。
- **无破坏性变更**：HS-7/8 物理拦截只对"该被拦"的情况阻断，正常流程不受影响；iteration-check 只产出报告不阻断；HS-4/6 降级声明不改变现有流程。
- **按 ae-sdd-update-skill §边界判定表归位**：SKILL 维护工作流 + tools/ 实现 + 门禁物理实现 → 全部由本 PR 处理，符合"维护规则"职责。
