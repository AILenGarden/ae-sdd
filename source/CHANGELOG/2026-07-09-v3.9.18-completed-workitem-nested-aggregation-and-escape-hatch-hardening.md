# 2026-07-09 | ae-sdd v3.9.18 - 修复 v3.9.17 两处缺陷：nested 多 Story 误判完结 + 逃生放行命令注入

## Summary

v3.9.17 落地后，对该改动做了一轮独立对抗式 Code Review，发现两处真实缺陷：
（1）`resolve_default_state()` 的 completed 过滤复用 `get_active_phase()`，该函数在
nested state 下只看 `activeStory` 指向的那一个 Story，若该 Story 完成后 `activeStory`
未前移到下一个未完成 Story，会把仍有活儿要干的整条 work-item 误判为"已完结"而
排出候选池；（2）新增的 `ae-sdd state new`/`enter` 逃生放行复用的 `_CHAIN_RE` 单命令
判定不识别单个 `&`、`$()`、反引号，攻击者可用
`ae-sdd state new --id X & rm -rf .ae-sdd/` 之类的命令夹带任意 shell 命令，越过该
放行点之后的全部 phase 权限检查（含 `completed`/`paused` 等零权限 phase）。本次
分别用聚合校验替换单点判断、用更完整的单命令语法检测堵住命令注入通道。

## Changes

| Area | Change |
|---|---|
| `tools/lib/state.py` | 新增 `is_work_item_completed(state)`：flat 直接看 `phase`；nested 通过 `_iter_story_projection_records()` 聚合全部 Story 子状态（含 `drStates[*].storyStates`），仅当全部 `completed` 才判定整体完结，无任何 Story 子状态时回退 `get_active_phase()` |
| `tools/lib/work_item_context.py` | `resolve_default_state()` 的候选过滤由 `get_active_phase(c.data) != "completed"` 改为 `not is_work_item_completed(c.data)` |
| `tools/lib/gate_intercept.py` | `_CHAIN_RE` 增补匹配单个 `&`（用环视与 `&&` 区分）、`$(`、`` ` ``，堵住命令替换/后台执行夹带绕过；同时影响所有复用该正则的放行点（只读 Bash、`memory`、`assets generate`、`state new`/`enter`） |
| `tools/lib/gate_intercept.py` | `state new`/`enter` 逃生放行额外叠加 `_REDIRECT_RE` 检测，禁止夹带重定向（该放行点独立于 phase 权限之外，风险面比其余放行点更宽，需要更严的单命令判定） |
| `tools/tests/test_state.py` | 新增 `TestIsWorkItemCompleted`：flat/nested 单 Story/nested 多 Story（含 sibling 未完成、全部完成、PRD 下 `drStates` 嵌套、无 Story 记录回退）共 8 个用例 |
| `tools/tests/test_cli_state_work_item.py` | 新增用例：同一 work-item 内 `activeStory` 指向已完成 Story 但另一 Story 未完成时，隐式解析仍应命中该 work-item |
| `tools/tests/test_gate_intercept.py` | 新增用例：`activeStory` 指向已完成 sibling 时 `resolve_default_state()` 不再误判整体完结；`state new`/`enter` 逃生放行对 `&`/`$()`/反引号/重定向夹带全部拒绝放行 |

## 触发原因

- v3.9.17 合入前按标准流程做了一轮独立 Code Review（非用户报告，自查发现）。
- Review 定位到 `get_active_phase()` 的设计目标是"当前活跃 phase"（服务于逐 story
  聚焦时的 phase 权限判断），并非"整条 work-item 是否完结"，`resolve_default_state()`
  误用其语义做完结判断，在 nested 多 Story 场景下会产生假阴性完结误判。
- Review 同时指出新增逃生放行点独立于 phase 权限之外、无条件放行，其复用的
  `_CHAIN_RE` 命令边界判定本就不识别 `&`/`$()`/反引号（该 gap 在只读 Bash/`memory`/
  `assets generate` 等既有放行点也存在，但风险面较窄；本次一并加固共享正则，
  使全部放行点同时受益）。

## 影响范围

- 涉及运行时门禁逻辑（`gate-intercept` PreToolUse hook 的隐式 work-item 完结判定与
  逃生放行的命令合法性判定），不涉及文档路径或子 SKILL 职责边界调整。
- 破坏性变更：`resolve_default_state()` 在"nested work-item 的 activeStory 已完成但
  仍有未完成 sibling Story"场景下，返回值从"误判整体完结→排出候选池"变为"识别为
  仍活跃候选"；显式 `--work-item`/session 绑定/mentioned 解析路径行为不变。
- `_CHAIN_RE` 加固后，此前能被单个 `&`/`$()`/反引号绕过判定为"单条命令"的场景现在
  会被视为链式命令，交回后续正常检查；不影响不含这些字符的合法单条命令。
- `tools/lib/paths.py` 的 `build_state_machine_name`/`_extract_story_number`
  在 story-id 不匹配 `STORY-\d+` 时会退化为原始字符串拼路径，理论上存在路径穿越
  隐患；该问题与本次改动的两个文件无关，是预先存在的缺口，本次未修复，仅在此
  记录以便后续单独处理。
- 版本号推进：`3.9.17` → `3.9.18`（需配合 `dev_sync.py` 同步到全局安装的 skill
  副本才会在 `D:\Item\life` 等下游项目生效；此前已同步的 v3.9.17 副本仍带有本次
  修复的两处缺陷，需重新同步覆盖）。
