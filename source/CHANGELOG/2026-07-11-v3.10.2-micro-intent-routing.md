# v3.10.2 — micro 意图分流路由（优化/审查直调单能力）

**日期：** 2026-07-11
**版本：** 3.10.1 → 3.10.2
**主题：** `/ae-sdd 优化这部分实现` / `/ae-sdd CodeReview 这段` 进无文档微任务、按意图只调相应能力，不再误进自更新、也不走完整 Coding 全链。

---

## 背景（用户诉求）

用户反映：调用 `/ae-sdd 请帮我优化这部分实现` 时，希望 ae-sdd 直接进无文档微任务、调用相应能力（优化→coding；审查→code-review），而不是走完整 设计→评审→实现 流程，也不要误进自更新。

调查发现 4 个真实缺口：

| # | 缺口 | 证据 |
|---|------|------|
| 1 | **"优化"误路由 self-update** | 路由表里"优化"只匹配 `优化ae-sdd → update-skill`（SKILL.full.md 路由表）。`/ae-sdd 优化这部分实现` 会被判为"优化 ae-sdd"，进自更新流程 |
| 2 | **"审查/CodeReview"不是路由触发词** | 全体系里"CodeReview"只是 Phase 3 下游节点，从未作为路由入口触发词 |
| 3 | **micro 链无意图分流** | micro 进 CodingProcess 走完整 §A1.5 骨架分解→CodeAnalysis→CodePlan→Execute，无"只调单能力"分支 |
| 4 | **code-review 硬准入拦死无文档审查** | 第零步必读 5 产物（Story/CodingPlan/CodingReport/TestReport/资产），缺了直接禁止继续 |

**路由是文档驱动**（LLM 读 SKILL.md 路由表判定，classify.py 的 classify() 未参与路由），故改动以文档层为主、机制层最小补足。

### 机制层（代码）

**`tools/lib/classify.py`**
- entry_node 推断链（L353-386）新增两条分支：
  - `优化/重构/改进` + **代码上下文** + **非 self-update 上下文** → `entry_node="OPTIMIZE"` + `scale="微"`

- 新增关键词常量：`_OPTIMIZE_KEYWORDS` / `_REVIEW_KEYWORDS` / `_SELFUPDATE_CONTEXT_KEYWORDS` / `_CODE_CONTEXT_KEYWORDS`

## 设计决策记录

**为何要求 OPTIMIZE 搭配代码上下文词？**
"重构"同时是 SCALE_KEYWORDS["大"] 的关键词。若 OPTIMIZE 无条件触发，`大重构整个架构` 会被误降为微。要求代码上下文词（代码/实现/这段/方法/service 等）+ 排除宏观词（模块/架构/逻辑），使"优化这部分实现"命中而"大重构整个模块"不命中。

**为何 micro-review 不额外要求代码上下文词？**
审查天然是代码语境（codereview/审查/评审代码 本身指向代码），且不与 SCALE_KEYWORDS 冲突。

**为何复用微链 phase 序列而不新增？**
新增 phase 序列会扩散到 6+ 文件（PHASE_FLOWS/VALID_SCALES/PHASE_ENTRY_GATES/_infer_scale/子链表/ROUTE_ROWS）。复用现有微链 + gate 跨步豁免只需改 gate_intercept 一处，改动面最小（方案 A）。
