# 2026-07-15 | ae-sdd v3.11.2 - 微任务 CodingPlan 门禁分级

## Summary

微任务原本与大型 Story 共用同一组 CodingPlan 门禁，导致 standalone Work Item 因缺少 Story 和 14 项大型计划关键词被误拦。此次统一 G-07、G-08、G-14 与 G-CODEPLAN-SRC 的 CodingPlan 定位，微任务从 Work Item 分桶读取计划并校验范围、实现顺序、风险/回滚、验证四个维度；完整任务仍保留原有严格规则。同时固化 GBK 父环境下 CLI 输出必须可按 UTF-8 严格解码的回归测试。

## Design ledger impact

| Design ID | Impact |
|---|---|
| `D-005` | CodingPlan 门禁新增 full/micro profile，避免微任务被大型 Story 规则误拦。 |
| `D-013` | Plan-first 保持不变，但微任务改用与规模匹配的四维轻量计划契约。 |
| `D-015` | 增加 GBK 父环境下 UTF-8 CLI 输出的可重复验证证据。 |

## Changes

| Area | Change |
|---|---|
| `tools/lib/gates.py` | 统一按 Work Item-first、唯一 Story fallback 定位 CodingPlan；为微任务实现四维轻量 G-07/G-08 规则，并让 standalone 微任务的 G-14 返回可审计 N/A。 |
| `tools/tests/test_gates.py` | 增加微任务 Work Item 定位、缺维度阻断、模板标题兼容、G-14/G-CODEPLAN-SRC 分支和 GBK 父环境 UTF-8 输出回归测试。 |
| Coding skills/template | 区分 Tier 1 微任务与 Tier 2/3 完整计划的填写义务和门禁 profile。 |
| Design/architecture docs | 同步 D-005、D-013、D-015、门禁职责与运行时编码契约。 |
| Version/readme | 推进母版版本到 `3.11.2` 并记录用户可见变化。 |

## 触发原因

- 用户反馈两个文件的微重构已完成计划设计，却被 G-14/G-08/G-CODEPLAN-SRC 的 Story 与 14 关键词假设阻断。
- Windows GBK 父环境曾使 UTF-8 门禁输出被错误解码，需要用字节级严格解码测试防止回归。
- 用户明确选择“走快速通道”；该授权只绕过完整链入口，不取消 Plan-first、测试、CodeReview 和变更账本。

## 影响范围

- 改变 `scale=微` 时 G-07/G-08/G-14/G-CODEPLAN-SRC 的门禁行为；非微任务行为保持严格且向后兼容。
- 不改变 Story/TestCase 文档存放协议，也不降低已有父 Story 时的 AC 对齐要求。
- update graph 规则集合不变；现有 UG-02、UG-08、UG-28 已覆盖 gates、测试、设计、架构、changelog 与分发链。
- 版本推进到 `3.11.2`；无数据迁移和破坏性 CLI 参数变化。
