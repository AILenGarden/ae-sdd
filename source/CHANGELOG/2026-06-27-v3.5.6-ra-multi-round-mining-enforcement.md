# 2026-06-27 | ae-sdd v3.5.6 - RA 多轮挖掘强制落地

## Summary

2026-06-27 实测中 AI Agent 在做"分析同事知识库出 proposal"任务时，**直接读 PDF 就出 36KB proposal**，未走 `requirement-analysis-skill.md` 的完整 7 步流程（未生成 RAGeneratePlan / 未做 8 维度挖掘 / 未做 5 问自检 / 未做缺口管理）。被用户连续批评"又来了，不遵守流程"。

本次变更将 RA 多轮挖掘从"文档约定"升级为"工具物理拦截"——**让"跳过 RA 流程"在 4 个位置被拦下**：① 反模式库新增 3 条防御性条目 ② SKILL.md §智能路由表 +4 类输入类型 ③ `document_storage.save_doc()` 增加 RA 强检查 + BUG/CONFIG 双重豁免判断 ④ 新增 `flow_violation_scan.py` + `ra-gate` CLI 工具层兜底。同时落地 1 份 AI Agent 自审清单 SOP 与 2 份项目外历史文档治理。预期效果：**未来类似违规在工具层物理拦截**，不再依赖 Agent 自律。

## 触发原因

- **根因 1：流程违规无物理拦截** —— v3.4.0 加固了 G-00 / G-RA / G-CODEPLAN-SRC / G-DOC-STORAGE / G-14 共 5 个门禁，但 RA skill 自身的 7 步流程仍停留在"文档约定"层（无工具强制）
- **根因 2：AI Agent 撞"用户催促 + 任务小"就跳过流程** —— requirement-analysis-skill.md §反模式与对话陷阱 章节（v3.2 新增）只覆盖 6 类反模式，未覆盖"出文档类任务"的具体反模式
- **根因 3：4 维判定智能路由表输入类型不完整** —— SKILL.md §🎯 智能路由表 第 -1 步只覆盖 5 类输入（PRD/Issue/对话/复杂对话/简单对话），未覆盖"修订建议书/proposal/分析报告/调研文档" 4 类文档类任务
- **根因 4：建议书自身的"自报缺陷"机制缺位** —— 6 份历史建议书均以具体 Agent 名（Mavis / ZCode）署名，违反"ae-sdd 文档不应绑定 Agent 名字"原则
- **根因 5（用户裁决 2026-06-27）** —— 用户明确"ae-sdd 文档内不应该有某个指定的 Agent 名字"，触发历史清理

## 影响范围

- **运行时逻辑：** 是
  - `tools/lib/document_storage.py` save_doc() 增加 RA 强检查（影响所有 RA 类型文档写入）
  - `tools/lib/gates.py` 新增 G-RA-FLOW-VIOLATION 门禁
  - `tools/bin/ae-sdd` 新增 2 个子命令
- **门禁行为：** 是
  - 新增 G-RA-FLOW-VIOLATION 门禁（运行 `ae-sdd gates check --only G-RA-FLOW-VIOLATION` 触发）
  - save_doc() RA 类型前置检查（不通过 raise GateFailure("G-RA-PLAN"/"G-RA-COMPLETE"/"G-RA-GATES")）
- **子 SKILL 职责边界：** 否（仅 RA skill 加反模式条目，未改其他 SKILL）
- **文档存放路径：** 否
- **版本号：** 否（本次不推进 v3.5.6 → v3.5.7，仅修补 v3.5.6 的工具层）
- **破坏性变更：** 是（轻微）—— save_doc() RA 类型前置检查可能在已有 RA 文档未走完整流程时拒绝写入，需用户先补 RA 文档再保存
