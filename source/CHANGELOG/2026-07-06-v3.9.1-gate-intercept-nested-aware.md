# 2026-07-06 | ae-sdd v3.9.1 - gate_intercept 嵌套 state 感知修复

## Summary

v3.9.0 引入嵌套状态模型后，`gate_intercept.py` 的 `check_intercept` 漏迁了 4 处顶层 `phase`/`currentStory` 读取，未跟随 `prompt_inject.py` 迁移到 `get_active_phase`/`get_active_story` 统一接口。嵌套 state 顶层无这两个字段，导致 hook 永远看到 `phase=initialized`（∈ `_DESIGN_PHASES`），对所有 `src/` 写入误拦为"设计阶段禁止写入源码目录"——无论 `activeStory` 子状态实际是否 `coding`。本次将 4 处读取改为统一接口，并补 `test_nested_state.py` 对 `check_intercept` 的嵌套 state 回归用例。

> 本 CHANGELOG 仅覆盖 gate_intercept 嵌套状态感知修复部分。同批发布的「上下文加载门禁硬化（G-DR-CTX/G-STORY-CTX/G-TESTCASE-CTX/G-TASK-CTX）」见 `2026-07-06-v3.9.1-context-gates.md`。两者同属 v3.9.1。

## 触发原因

- v3.9.0 嵌套状态模型发布时，`prompt_inject.py:184` 迁移到了 `get_active_phase`/`get_active_story` 统一接口，但 `gate_intercept.py` 的 phase 读取路径漏迁（CHANGELOG `2026-07-06-v3.9.0` 第 46-47 行可证：prompt_inject 迁移有记录，gate_intercept 只记录了关卡2 STORY-ID 归属校验新增，未提及 phase 读取迁移）。
- `test_nested_state.py` 仅覆盖 `state.py`/`classify.py`/`paths.py`，无 `gate_intercept.check_intercept` 用例，故回归未被发现。
- 用户实证：使用 ae-sdd 时反复在编码阶段被 gate-intercept 拦截，提示"设计阶段禁止写入源码目录"，需手动创建 micro 状态推进到 coding 才能解锁。

## 影响范围

- 涉及运行时门禁行为：修复后嵌套 state 项目的 `src/` 写入按 `activeStory` 子状态真实 phase 评估，不再被误判为 `initialized`。
- 不改变 flat state（v1）行为：`get_active_phase`/`get_active_story` 对 flat dict 透明返回顶层值。
- 不改变门禁语义、子 SKILL 职责边界、文档存放路径。
- 版本号推进 v3.9.0 → v3.9.1（SemVer patch，Bug 修复），UC-01 三处（SKILL.md / paths.py / README.md）已同步。
- 无破坏性变更。
- 设计文档 N/A：本修复是 Bug 修复，不改变 `source/docs/ae-sdd-design.md` 的设计语义（嵌套 state 模型设计已在 v3.9.0 文档化），`source/docs/ae-sdd-implementation-architecture.md` 的实现边界未变（gate_intercept 仍是 hook 拦截实现，仅读取方式从顶层改为统一接口）。
