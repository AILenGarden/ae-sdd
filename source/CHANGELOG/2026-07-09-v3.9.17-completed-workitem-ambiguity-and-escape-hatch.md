# 2026-07-09 | ae-sdd v3.9.17 - 已完成 work-item 退出隐式候选池 + state new/enter 逃生放行

## Summary

life 项目 runtime-stats 三日日志分析（950 条 hook 记录，296 次拒绝）定量确认：一个已 `completed` 的 work-item（`cs-ai-STORY-005-BE`）会持续占据 `resolve_default_state()` 的隐式候选池，导致仍在跑的其它 work-item 被误判为"多任务歧义"而拒绝；若某个项目当下*唯一*一条 `.auto-engineering/*/state.json` 恰好是 `completed`，还会被单候选兜底直接选中，进而被 `PHASE_PERMIT["completed"] = frozenset()` 冻死整个会话。本次改动让隐式默认解析忽略已完成的候选，并为其挤出的 `NoWorkItemStateError` 自救路径（`ae-sdd state new` / `ae-sdd enter`）单独开逃生通道，避免"建议的脱困命令自己也被拦"的二次死锁。

## Changes

| Area | Change |
|---|---|
| `tools/lib/work_item_context.py` | `resolve_default_state()` 用 `state_mod.get_active_phase()` 过滤掉 `phase == "completed"` 的候选后才做单候选兜底/歧义判定；显式提及解析（`resolve_mentioned_state`）不受影响，仍可定位到已完成的 work-item |
| `tools/lib/gate_intercept.py` | 新增 `_STATE_NEW_OR_ENTER_CMD_RE` / `_is_ae_sdd_state_new_or_enter_cmd()`，在 `resolve_default_state()` 调用前放行单条（非链式）`ae-sdd state new` / `ae-sdd enter` 命令，二者只新建/领取新工作项，不读写既有 state |
| `tools/tests/test_cli_state_work_item.py` | 原 `test_state_read_without_work_item_blocks_when_multiple_sources_exist` 拆分为「1 活跃+1 completed → 应直接解析到活跃项」与「2 活跃 → 仍应歧义拒绝」两个用例 |
| `tools/tests/test_gate_intercept.py` | 新增：唯一候选为 completed 时隐式解析报 `NoWorkItemStateError` 而非误选；`state new`/`enter` 在该场景下放行；链式命令不走逃生通道 |

## 触发原因

- 用户反馈"ClaudeCode 工具天天被 hook 拦截"，定位到 `D:\Item\life` 项目。
- 对 `.ae-sdd/runtime-stats/*.jsonl` 逐条分类：66% 拒绝来自单个已完成 work-item 造成的 `phase=completed` 冻结窗口；18% 来自"Multiple ae-sdd work-item states exist"歧义（其中大半已被 v3.9.16 的 session 绑定修复自然消解，残余部分正是已完成任务陪跑候选池所致）。
- 代码核查确认 `list_work_item_states()`/`resolve_default_state()` 不区分 phase，`PHASE_PERMIT["completed"]` 也没有为"新建/进入下一任务"命令开白名单。
