# v3.5.10 — 实战适配能力测试暴露 10 项 Gap 集中修复

> **日期：** 2026-06-28
> **版本：** 3.5.9 → 3.5.10
> **触发：** 在 `D:\Item\life-fixture\`（life 工程副本独立 git 仓库）上对 ae-sdd v3.5.9 做端到端实战适配能力测试，暴露 14 个 Gap；本次集中修复其中 10 项可改母版的 Gap（Gap-001 SKILL.md 被平台截断属 ZCode 平台问题、Gap-002/003/009 属 fixture/项目侧问题不改母版）。

## 修复清单

### Gap-014 🔴 阻断 — classify 4 维判定 scale 误判

**问题：** `classify --text "实现 IM 知识库匹配和预约功能"` 判定为 `规模=微`，导致路由跳过 DR/Story/Task 直接进 coding。但实际这是跨 im/cs/spi/notification 5+ 子工程的 PRD 级需求（fixture 已有 529 行 RA v1.1 + 9 blockingGaps + 30 AC）。

**根因：** `classify.py` 的 scale 维度只靠"行数推断 + 关键词匹配"，完全不读项目已有产物。短文本需求被一律判微。

**修复：**
- `tools/lib/classify.py`：新增 `project_context` 参数 + `_infer_scale_from_project_context()` 函数。当传入项目根路径时，按优先级读 `.ae-sdd/state.json` 的 currentStory → `.auto-engineering/{storyId}/state.json` 的 blockingGaps → RA 文档行数 → Story/Task 文档存在性，用"已有产物规模"覆盖"行数推断"。置信度 0.7~0.9。
- `tools/bin/ae-sdd`：`classify` 子命令新增 `--project` 参数。
- 向后兼容：不传 `--project` 时 fallback 到原行为。

**验证：** `classify --text "实现 IM 知识库匹配和预约功能" --project /d/Item/life-fixture` → `scale=大（置信度 0.9）`，建议下一步 `requirement-analysis`（不再是误判的 coding）。

---

### Gap-010 🔴 阻断 — 三层 plugin 注册表全部缺失

**问题：** `ae-sdd plugin list` 在干净机器上恒报 "⊘ L1/L2/L3: 注册表不存在（跳过）→ 0 个插件"。v3.5.0 声明的 plugin 机制在生产环境不可用。

**根因：** install.py / distribute.py 从不生成任何 registry.yaml 文件。三层注册表设计存在但"安装后空空如也"。

**修复：**
- `scripts/distribute.py`：新增 `_ensure_l2_global_registry_skeleton()`，在分发链末尾自动在 `~/.ae-sdd/plugins/registry.yaml` 生成 L2 全局空骨架（`plugins: []`）。幂等：已存在则不覆盖。
- `tools/lib/plugin_loader.py`：`_parse_registry` 循环里识别 `enabled: false` 跳过（为 L3 默认注册表的 example 插件留扩展点，默认禁用不污染 count）。

**验证：** dev-sync 后 `~/.ae-sdd/plugins/registry.yaml` 存在；`plugin list` 显示 "∅ L2-global: 0 个插件"（区分"注册表存在但 0 插件"vs"⊘ 不存在"）。

### Gap-012 🟠 严重 — HS-12 谎报校验只覆盖 G-08

**问题：** `iteration-check IC-2` 报 "F-1 交叉验证仅覆盖 1 个 gate（G-08），其余 82 个 gate 谎报不校验"。AI 可伪造 G-09/G-10 等 gate 的 ✅ 声明不被发现。

**根因：** `stop_check.py` 的 `_G08_CLEAR_RE` 只硬编码 G-08 一个 gate 的 CLEAR 正则。

**修复：**
- `tools/lib/stop_check.py`：新增通用 `_GATE_CLEAR_RE`（匹配 G-00~G-14 + G-RA-1~5 共 19 个可谎报 gate）+ `_VERIFIABLE_GATE_IDS` 白名单 + `_normalize_gate_id()`。`_verify_gate_claims()` 改为循环对每个命中的 gate 跑真实 check，谎报任一即阻断。
- `tools/lib/iteration_check.py`：IC-2 检测逻辑识别新的 `_GATE_CLEAR_RE` + `_VERIFIABLE_GATE_IDS` 模式，覆盖 ≥5 个 gate 时降级为 info。

**验证：** `iteration-check` IC-2 从 warn 降级为 info（"已扩展覆盖 14 个 gate"）。

---

### Gap-013 🟠 严重 — document_storage 误判死代码

**问题：** `iteration-check IC-3` 报 "模块 'document_storage' 已实现但全树零 import（死代码）"。但 document_storage.py 是 v4.1 新增的"AI Agent 调用面 API"，设计上由 LLM Agent 通过 SKILL 文档调用（resolve_path/save_doc），不期望被 CLI/gates 内部 import。

**根因：** IC-3 不知道"AI Agent 调用面 API 模块"和"CLI/gates 内部模块"的区别。

**修复：** `tools/lib/iteration_check.py`：IC-3 新增 `_AGENT_API_MARKERS` 白名单（"AI Agent 调用"/"LLM 调用"/"Agent 调用面"/"给 LLM"等），模块 docstring 含标记时零 import 降级为 info（"属设计预期，非死代码"）。

**验证：** `iteration-check` IC-3 从 warn 降级为 info。

---

### Gap-005 🟠 严重 — G-RA-1/2/3 选错文档版本

**问题：** `gate ra-required` 报 G-RA-3 "缺失 §8.5/§8.6 衍生章节"，但 fixture 的 RA v1.2 明明已补这些章节。G-RA-3 扫的是 v1.1 不是 v1.2。

**根因：** `gates.py` 用 `max(ra_files, key=lambda p: p.stat().st_mtime)` 选最新 RA。但 cp -r 复制 / 打包分发会刷平所有文件 mtime，`max(mtime)` 选出不确定的 RA 文档。

**修复：** `tools/lib/gates.py`：新增 `_select_latest_ra()` 函数，优先按文件名版本号（`-v1.2` > `-v1.1` > `-v1.0`）选最新；版本号缺失或相同时 fallback 到 mtime。替换 G-RA-1/G-RA-2/G-RA-3 三处 `max(ra_files, key=mtime)`。

**验证：** `gate ra-required` G-RA-1 显示 "最新 RA-IM-KB-APPOINTMENT-v1.2.md"（不再是 v1.1）。

### Gap-004 🟠 严重 — G-01 glob 误报

**问题：** G-01 报 "design/ 目录无 DR 文档"，但 fixture `design/story/be/` 下有 `STORY-001-BE-CodingReport.md` 等子目录产物。

**根因：** `gates.py` 的 `check_g01` 用 `design.glob("*DR*.md")` 只扫 design/ 根一层，不递归子目录。

**修复：** `tools/lib/gates.py`：`check_g01` 改用 `design.rglob("*DR*.md")` 递归扫描 + 排除 CodeReview/CodingReport/TestReport 等非 DR 报告类文档。

**验证：** fixture 上 G-01 不再误报"design/ 无 DR 文档"。

---

### Gap-008 🟠 严重 — G-PATH 只扫母版不扫项目侧

**问题：** G-PATH 报 "扫描 80 个母版 .md，无硬编码产出路径"，但项目侧 AGENTS.md/CLAUDE.md/.ae-sdd/memory 如果硬编码 `d:\tmp\` 或 `design/story/be/` 等越界路径（实测 life 项目 MEMORY.md 残留旧路径），G-PATH 扫不到。

**根因：** G-PATH 设计本意是"防止母版 SKILL 自身漂移"，但项目侧记忆文档劫持 config 路径是 G-DOC-CONSISTENCY 的盲区补充场景，G-PATH 应扩展覆盖。

**修复：** `tools/lib/gates.py`：`check_g_path` 在母版扫描后，新增扫描项目侧 `.ae-sdd/**/*.md` + `AGENTS.md` + `CLAUDE.md` + `MEMORY.md` + `.harness/memory/**/*.md`，检测 `_PATH_VIOLATION_RE` 命中。

**验证：** fixture 上 G-PATH 显示 "扫描 80 个母版 .md + 47 个项目侧记忆 .md"。

### Gap-006 🟡 一般 — G-RA-4 输出不友好

**问题：** G-RA-4 报 "RA 真实性扫描发现 31 个 BLOCKER（共 206 项）：['masked-gap', 'missing-timeliness', 'vague-ellipsis']"——只列 rule 名，AI 拿到结果不知道改哪个文件哪一行。

**修复：** `tools/lib/gates.py`：`check_ra_authenticity` (G-RA-4) 从 findings 抽前 5 条具体定位（file:line:snippet），加到 message 的 "示例定位" 字段。

**验证：** fixture 上 G-RA-4 输出含 "示例定位：['ae-sdd-doc/.../RA-...-v1.0.md:73 — ...']"。

### Gap-007 🟡 一般 — G-DOC-STORAGE 不区分历史/新增

**问题：** G-DOC-STORAGE 报 4 个"游离"文件，但 fixture 是 cp -r 复制来的，历史文件本来就该在。CLI 不能区分"历史遗留"和"新产出的游离文件"。

**修复：** `tools/lib/gates.py`：`check_g_doc_storage` 新增 `git ls-files "*.md"` 拿"已被 git 跟踪的 .md"清单，已跟踪文件视为历史产物跳过；仅对"未跟踪 + 新产出"的游离文件报。git 不可用时回退到原行为。

**验证：** fixture 上 G-DOC-STORAGE 显示 "扫描 377 个 .md，无游离产物"（之前误报 4 个）。

### Gap-011 🟡 一般 — SKILL.md 残留 v3.0 sync-tools 关键词

**问题：** `iteration-check IC-1` 报 "过时技术栈关键词 'sync-tools'，定位: SKILL.md:51"。v3.0 之后已全面 Python CLI 化，sync-tools 工具已不存在。

**验证：** `iteration-check` IC-1 显示 "0 项"（无发现）。
