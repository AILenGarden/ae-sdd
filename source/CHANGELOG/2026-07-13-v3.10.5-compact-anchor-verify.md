# 2026-07-13 | ae-sdd v3.10.5 - compact anchor coverage verification

## Added

- `runtime_verify` now compares each child SKILL's `core.compact.md` against its `fallback/SKILL.full.md` for structural anchor coverage. Anchors present in the fallback but silently dropped by `render_core_compact`'s `max_lines` truncation or `_is_core_structural` scoring are surfaced as **warnings** (non-blocking). This borrows the validate-after-compress idea from caveman-compress's `validate.py`, mapped to ae-sdd's static compile pipeline.
- Anchor regex is aligned 1:1 with `compile_skill_runtime.py:_is_core_structural` (`G-[A-Z0-9-]+|RA-G\d+|TR-\d+|TC-\d+|TV-\d+`), so the verifier and compiler share a single definition of "structural anchor".

## Fixed

- `runtime_verify` child SKILL four-tuple check (`manifest/boot/outline/fallback`) was missing `core` -- `core.compact.md` had no existence or hash verification at all. `core` is now part of the checked set, and `core_sha256` is verified against the file (mirroring the existing `fallback_sha256` check).

## Verification

- `test_runtime_verify`: 10 tests pass (7 existing + 3 new: anchor-loss warning, core-missing issue, clean-pass-silently).
- Full suite: 836 tests pass (833 baseline + 3 new).
- `runtime verify dist/ae-sdd`: ok=True, 11 subskills report anchor-loss warnings (69 tokens total), confirming the feature surfaces real pre-existing truncation loss without blocking delivery.
