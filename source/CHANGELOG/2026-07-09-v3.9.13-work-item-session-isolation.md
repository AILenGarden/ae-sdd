# v3.9.13 - work-item/session state isolation

Date: 2026-07-09

## Problem

Parallel ae-sdd sessions could inherit each other's workflow state because
`.ae-sdd/state.json` was still treated as an implicit active state source or
legacy mirror. Session A could update the project-global mirror to `Story-004`;
session B then entered ae-sdd for `Story-005` and the prompt/gate hooks still
injected and enforced the `Story-004` phase.

The nested R2 implementation also stopped too early: `Story -> DR -> PRD`
created/used a DR-local state instead of resolving to the true PRD root state.

This also made small and micro work inconsistent: `state new --id BUG-*`
defaulted to the large chain, and nested Story states did not persist `scale`.

## Change

- Added `tools/lib/work_item_context.py` as the shared resolver for isolated
  work-item state files.
- Project-level `.ae-sdd/state.json` is no longer a supported active state,
  mirror, or fallback. State resolution uses only task-scoped
  `.auto-engineering/{WORKITEM-KEY}/state.json` files plus session bindings.
- `ae-sdd init` no longer creates `.ae-sdd/state.json`. Project initialization
  creates only project configuration/assets; workflow state starts with
  `ae-sdd state new` under `.auto-engineering/{WORKITEM-KEY}/state.json`.
- `G-00` no longer treats missing project/work-item state as an incomplete
  project skeleton. State is required by task execution paths, not by project
  initialization.
- In multi-work-item projects, implicit state reads now fail closed with a
  candidate list instead of consuming any project-global state.
- Prompt injection resolves a mentioned Story/work-item from the user prompt and
  binds it to the hook session when a session key is available.
- PreToolUse gate interception resolves state through the same session/work-item
  resolver, so stale project mirrors no longer lock code tools to an unrelated
  Story phase.
- `state read`, `state write`, `state next-step`, `context-pressure`,
  review-loop commands, review consensus, and file-lock commands now reject
  ambiguous or missing work-item defaults unless `--work-item`, `--story`, or
  a session binding identifies the task. `--project-state` is rejected.
- `state new` now defaults by entry semantics:
  - `BUG` / `OPT` / `CONFIG` / `TASK` -> `scale=微`
  - `STORY` -> `scale=小`
  - `DR` -> `scale=中`
  - `PRD` -> `scale=大`
- Nested states created by `state new` persist `scale`, `projectKey`,
  `workItemKey`, and `currentWorkItem` metadata.
- PRD-root nested states now use `drStates{}` instead of a single `drState`.
  A Story whose DR belongs to a PRD resolves to the PRD state and records the
  Story under `drStates[DR-ID].storyStates[STORY-ID]`, with top-level
  `storyStates` retained only as a compatibility index.
- `runtime_stats` and the mirror-health diagnostic no longer consume
  project-global state. Runtime scale is read from the resolved work-item state;
  a legacy project-level state file is reported as a cleanup/migration item.

## Compatibility

`.ae-sdd/state.json` is intentionally not read or written by the state resolver,
prompt hook, gate hook, health check, or state CLI. Existing files at that path
are ignored for active workflow purposes; remove them during project cleanup.
