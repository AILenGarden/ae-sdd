# 2026-07-06 | ae-sdd v3.9.2 - 修复设计阶段 ae-sdd memory 命令死锁

## Summary

v3.8.2 引入 memory gate（存端兜底 + 转换门禁）后，设计阶段 6 个 phase（ra/design/coding-plan/review 四个记忆域覆盖的阶段）推进前必须完成 `ae-sdd memory enter/write/exit`。但这三个是 Bash 命令，而这些 phase 的 `PHASE_PERMIT` 不含 Bash（设计意图：设计阶段本不该跑任意 Bash）。结果 AI 在设计阶段执行 `ae-sdd memory enter` 时，在 `check_intercept` 主流程 step 6 被 phase permit 拦死——"必须先跑 memory 但 memory 命令跑不了"的死锁。

`ae-sdd state write` 在 step 3 有特殊通道（命中即放行，独立于 PHASE_PERMIT），memory 命令族漏了同等待遇。本次为 `ae-sdd memory <subcmd>` 补 step 3c 特殊通道：命令头匹配 `ae-sdd memory`（覆盖全部 8 个子命令 enter/write/exit/read/search/promote/summarize）且非链式命令（防 `ae-sdd memory enter && rm -rf` 误放）即放行。

## 触发原因（根因诊断）

- **v3.8.2 加 memory gate 时漏开口子**：memory gate 把 ra/design/coding-plan/review 四个记忆域设为关联节点，要求进入下一 phase 前 `check_exit_ready` 通过（即完成 enter→write→exit）。但同一批改动未给 `ae-sdd memory` 命令在 `check_intercept` 开放行通道。
- **死锁结构**：设计阶段 6 个 phase（ra-generated / dr-generated / story-generated / story-reviewed / task-generated / code-reviewed）的 `PHASE_PERMIT` 均不含 Bash（gate_intercept.py:64-79），AI 跑 `ae-sdd memory enter` 走 hook 主流程：step 3 不命中（不是 state write）→ step 4 不命中（不在只读白名单）→ step 5.5 不命中（只对 Write/Edit/MultiEdit）→ step 6 被拦。无放行路径。
- **为什么之前没爆**：① 快速通道（`.quick_channel` 文件存在即全放行）掩盖了症状，用户卡住时走快速通道绕过；② `ae-sdd` 自身仓库等无 `.ae-sdd/` 的目录，hook 第 803 行直接放行，走不到 memory gate；③ `coding/coding-process/test-running` 因含 Bash 不受影响——一旦熬过设计阶段进入编码就通了，bug 症状被自然消化。
- **缺失的回归测试**：`test_gate_intercept.py` 此前只覆盖 `state write` 经 memory gate 拦截的路径（`test_memory_gate.py:56-65`），未覆盖"设计阶段跑 `ae-sdd memory` 命令本身被 PHASE_PERMIT 拦"的场景，故 bug 长期未被发现。

## 设计决策

- **给 memory 命令开特殊通道 vs 放开 PHASE_PERMIT 的 Bash**：选前者。设计阶段不含 Bash 是正确的（该阶段只产设计文档，不该跑任意 Bash）；memory 命令作为"流程自管理命令族"（只动 `.ae-sdd/memory/`，不改 state.phase、不碰源码）单独开口子，与 step 3 对 `state write` 的处理同构，不破坏 PHASE_PERMIT 的语义边界。
- **放行全部 8 个子命令 vs 仅 enter/write/exit**：选全部。read/search/summarize 是只读，本就该放；promote 是跨层提升，也只动 memory 目录。语义统一为"memory 命令族"，比把只读子命令拆到 `BASH_READONLY_PREFIXES` 更内聚，且避免 `memory write` 被错误归类为只读。
- **链式命令防护**：用现有 `_CHAIN_RE`（`&&`/`||`/`;`/`|`/换行）判定，含分隔符则不快速放行，交回 step 4-6 正常检查。防止 `ae-sdd memory enter && rm -rf .ae-sdd/` 借 memory 通道绕过危险命令拦截——与 v1.4 修链式 Bash 绕过白名单同一思路。
- **不动 step 5.5 `_check_memory_entered`**：那是"写源码前检查 memory scope active"的正确门禁（堵 Agent 不调 memory 直接写源码绕过 gate 的漏洞），不是 bug，本次保留。
- **不修 dist/**：dist 是分发产物，由同步流程（build_dist.py / sync）生成，本次只改 tools/ 源与 source/ 文档。

## 影响范围

- **行为修复**：设计阶段 6 个 phase（ra-generated / dr-generated / story-generated / story-reviewed / task-generated / code-reviewed）现在可正常跑 `ae-sdd memory enter/write/exit`，死锁解除。AI 无需用户手跑 `!` 前缀命令。
- **不改变**：PHASE_PERMIT 结构、step 5.5 存端兜底语义、state write 特殊通道、快速通道机制、memory_store 文件格式。
- **无破坏性变更**：链式防护保证危险命令不借通道绕过；只读子命令本就放行；coding 阶段（含 Bash）行为不变。
- **版本号推进** v3.9.1 → v3.9.2（SemVer patch，Bug 修复），UC-01 三处（SKILL.md / paths.py / README.md）同步。
