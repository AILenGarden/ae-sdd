# v3.6.0 — 主流程监管器 + 流程偏移检测（2026-06-30）

## 摘要

实现"主流程监管器"概念：ae-sdd 不再只是文字流程规范，而有了可执行的流程编排实体
（UserPromptSubmit hook Python 逻辑），能自动检测 AI 的流程偏移行为并分级矫正。

## 三个设计决策

| 决策 | 内容 |
|------|------|
| 1B | 废弃 `◆ STATE:` / `◆ LOADED:` 自报标记，完全依赖产物核查（gates check）判定流程合规 |
| 2B | 主流程监管器实体 = `UserPromptSubmit hook` Python 逻辑（`prompt_inject.py` + `flow_monitor.py`） |
| 3  | `paused` 新增为一级 phase（任何 phase 可跳入，不在 PHASE_FLOWS 子链中） |

## 新增文件

### `tools/lib/flow_monitor.py`（新建，~270行）

偏移检测 + 矫正消息生成纯计算模块：
- `DriftResult` 数据类（drift_type / severity / gate_id / gate_passed / gate_message / phase / correction_count）
- `get_phase_gate_map()` — phase → gate_id 映射（B1/B3 产物核查的判定依据）
- `detect_drift(state, ade_sdd)` — Layer1 产物核查（gates check subprocess）+ Layer3 矫正次数升级
- `build_correction_message(drift)` — severity 1/2/3 三级矫正文本生成
- `should_escalate(state)` — 快速判断是否需要 pause_state()
- 设计：纯计算模块，不直接写 state.json；全流程 try/except 降级放行

## 修改文件

### `tools/lib/state.py`

**新字段（state.json schema 变更）**：
- `pausedFromPhase` — paused 前的 phase，resume 时恢复目标
- `pauseReason` — `level3-escalation` | `user-rejected` | `user-manual`
- `correctionCounts` — 各 phase 矫正次数计数（键=phase，值=int）

**`set_phase()` 更新**：
- `paused` 特殊处理：绕过 PHASE_FLOWS 子链校验，自动记录 `pausedFromPhase`
- 其余 phase 沿用原逻辑

**`next_step_suggestion()` 更新**：
- `phase=paused` 时返回恢复目标 + pause_reason 中文说明

**5个新函数**：
- `pause_state(state, pause_reason, by)` — 暂停流程（幂等）
- `resume_state(state, by)` — 恢复到 pausedFromPhase（幂等）
- `increment_correction(state, phase)` — 矫正计数 +1，返回新值
- `get_correction_count(state, phase)` — 读取指定 phase 矫正次数
- `reset_correction_count(state, phase)` — 重置矫正次数（用户 ⚠️ 反馈时）

### `tools/lib/stop_check.py`（精简，v2.0）

**删除**：
- `_STATE_HEADER_RE` / `_LOADED_RE` / `_PHASE_REQUIRED_LOADED` 常量（自报标记，决策 1B）
- `_verify_gate_claims()` 函数（gate 自报交叉验证）
- `_check_loaded_marker()` 函数（LOADED 标记校验）

**`check_output()` 重写**：
- 职责简化为：① 空响应/结构性截断检测 → 重试；② PRD compact 失败（HS-8）→ 重试；③ 其余放行
- 流程合规性检测已全部转移到 `UserPromptSubmit hook`（`flow_monitor` + `prompt_inject`）

**保留**：
- `MAX_RETRY` / `_RETRY_FILE_NAME` / 重试计数基础设施
- `extract_last_assistant_text()` 工具函数
- `_check_compact_failure()` HS-8 检测（PRD compact 场景独立，与流程合规无关，保留价值）

### `tools/lib/gate_intercept.py`

- 新增 `"paused": frozenset()` 到 `PHASE_PERMIT`（paused 阶段禁止所有写操作）

### `tools/lib/prompt_inject.py`

**删除**：
- `◆ LOADED:` 自报标记提醒注入（lines 181-185，对应 C3 软层校验，决策 1B 废弃）

**新增 `_run_flow_monitor(ade_sdd, state)` 函数**：
- 每轮 `UserPromptSubmit` 调用 `flow_monitor.detect_drift()` 运行产物核查
- severity >= 1：递增 `correctionCounts[phase]` + 写 state.json
- severity == 3：同时调 `state.pause_state()` 写 `phase=paused`
- 生成矫正文本追加到 `additionalContext`
- 全流程 try/except，任何异常降级返回 None 不阻断主流程

**`inject()` 更新**：
- 末尾调用 `_run_flow_monitor()`，将矫正文本追加到 lines 列表

### `source/SKILL.md`（v3.6.0）

**§🔴 第一动作 完全重写**：
- 旧内容：2 步（领凭证 + G-00）
- 新内容：**5 步标准启动序列**（工作区初始化 / G-00 / 双层路由 / 监管器执行 / 收尾）
- 新增：续接播报格式 + SKILL 调用声明格式
- 新增：新需求无 PRD 强制阻断规则

**新增 §🎛️ 主流程监管器执行协议**（在 §G-00 与 §G-RA 之间）：
- 每系列 sub-step 0~5 标准执行循环
- 流程偏移与矫正对照表（B1~B4 / Level 1~3）
- `ae-sdd state write --resume` 恢复命令

## 破坏性变更

| 项目 | 影响 |
|------|------|
| `◆ STATE:` 自报不再需要 | 现有已写入自报头的 SKILL 不影响功能（stop_check 不再校验），但可逐步清理 |
| `◆ LOADED:` 提醒删除 | coding/coding-process 阶段不再要求 AI 写 LOADED 标记 |
| `◆ GATE:` 交叉验证删除 | AI 谎报 gate 不再被 Stop hook 拦截；改由产物核查（更可靠）替代 |

## 向后兼容

- `state.json` 旧格式（无 `pausedFromPhase`/`pauseReason`/`correctionCounts`）：`read_state()` 返回空模板时自动填充默认值
- `set_phase()` 旧调用不受影响（paused 是新增特判，不影响原有 phase 切换逻辑）
- `PHASE_FLOWS` / `_NEXT_STEP_MAPPINGS` 保持不变（paused 不在子链中，特判处理）
