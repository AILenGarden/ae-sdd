# 测试用例生成策略模板

## 核心原则（🆕 v3.6.3 假设驱动·覆盖兜底）

> **范式升级：** 从"覆盖全场景"升级为「**假设驱动 + 覆盖兜底**」双原则。解决"测试用例覆盖不全 / 无价值用例多 / 挖不出真实BUG"三大顽疾。

**双原则：**

| 原则 | 含义 | 地位 |
|------|------|------|
| **🔴 假设驱动（主线）** | 先挖掘"这个 Story 最可能踩什么坑"，每个用例尽量围绕证伪某个缺陷假设设计 | 价值主线 — 决定用例能否挖出真实 BUG |
| **🟢 覆盖兜底（查漏）** | 跑三层覆盖矩阵（类型策略 + 通用维度 + 测试分层），补充假设挖掘未覆盖的盲区 | 完整性保证 — 防止结构性遗漏 |

**为什么不能只靠"覆盖全场景"？** 一个完美的 N×(N-1) 状态机转换矩阵可以 100% 填满，却完全错过"两个并发请求在特定时序下导致状态丢失"——覆盖率达标 ≠ 能发现 bug。覆盖矩阵保证的是**结构完整性**，不是**缺陷发现力**。

**三类用例分级（贯穿 generate/review/模板）：**

| 类型 | 特征 | 价值 | 门禁 |
|------|------|------|------|
| **证伪用例**（主价值） | 围绕证伪某个 H-{N} 缺陷假设设计，必填假设 ID | 高 — 直接针对 bug 假设 | 占比 ≥ 成熟度阈值（40%/25%），generate + review 双重把关 |
| **正向覆盖用例**（基础价值） | 覆盖 AC 正常路径 + 主要异常路径 | 合理 — 验证正常流程 | 每个 AC 至少 1 条 |
| **覆盖兜底用例**（查漏价值） | 三层矩阵查出的盲区补充 | 查漏 — 矩阵驱动 | 数量纳入公式下限 |
| **纯凑数用例** | 无假设 + 无 AC 覆盖 + 非矩阵盲区 | 无 | 🔴 剔除 |

## 通用缺陷假设库（🆕 v3.6.3 — 假设驱动的主素材库）

> **定位：** 本库是 testcase-generate「第一步半：缺陷假设挖掘」的**通用素材源**，供"自上而下匹配"使用。素材提炼自 CodeReview T1-T5 真实场景强制 + DB 反模式 + 分层职责红线 B1-B4 + 领域经典 bug 模式（**不**含 D1-D8 测试伪造手段，那属 CodeReview 测试真实性校验职责）。
>
> **使用方式：** testcase-generate 拿本库逐条对照当前 Story，判定"这条假设在本 Story 可能触发吗？"，命中的进入假设清单。本库是**通用基线**，项目特有坑由 §项目特有坑信号源指引补充。

## 覆盖兜底：三层覆盖矩阵（原核心策略，降级为查漏工具）

> **🆕 v3.6.3 定位调整：** 本节以下的三层覆盖（类型策略 + 通用维度 + 测试分层）原是 testcase 的唯一主线，现降为「**覆盖兜底查漏工具**」——在假设驱动的证伪用例生成后，用本矩阵补充结构性盲区。
>
> **使用顺序：** testcase-generate 先做缺陷假设挖掘（主线）→ 生成证伪用例 → 再用本矩阵查漏（兜底）。不要跳过主线直接填矩阵。

**三层覆盖：**
- **第一层：按 Story 类型选策略** — 覆盖功能路径
- **第二层：通用覆盖维度** — 每个 Story 都必须做
- **第三层：测试分层** — 单元/接口/集成/端到端，各层验证不同目标

## 第三层：测试分层策略

> 第三层决定每个用例在哪个层级执行。先定义分层，再在第一层和第二层中标注每个用例的测试层级。

### 分层定义

| 层级 | 验证目标 | 外部依赖 | 执行速度 | 工具 |
|------|---------|---------|---------|------|
| L1 单元测试 | 业务逻辑正确性 | 全部 Mock | 快（ms级） | JUnit + Mockito |
| L2 接口测试 | HTTP 层行为（状态码、参数校验、序列化、异常映射） | Mock Service 层（`@MockBean`） | 中（s级） | **真实 HTTP：`SpringBootTest(webEnvironment=RANDOM_PORT)` + `TestRestTemplate`**（MockMvc 仅作降级，见下方原则） |
| L3 集成测试 | 真实数据库交互（事务、索引、SQL） | 真实 DB（H2/TestContainers） | 中（s级） | SpringBootTest + @Transactional |
| L4 端到端测试 | 多 Story 协作的完整业务路径 | 真实 DB + Mock 外部服务 | 慢（s级） | SpringBootTest(RANDOM_PORT) + TestRestTemplate + WireMock |

> ### 🔴 强制原则：能走真实 HTTP 的接口测试，必须走真实 HTTP
>
> **L2/L4 凡是验证 HTTP 接口行为的用例，默认必须经过真实 HTTP 栈**——即 `@SpringBootTest(webEnvironment = RANDOM_PORT)` 启动真实嵌入式容器 + `TestRestTemplate`（或 Boot 2.1+ MVC 的 `WebTestClient`）发起真实端口上的 HTTP 请求。Service 层用 `@MockBean` 隔离即可，不影响走真实 HTTP。
>
> **为什么不用 MockMvc 当默认：** MockMvc 直接调 `DispatcherServlet`，**不开真实端口、不走真实网络、不经过真实容器**。它会放过只有真实 HTTP 才暴露的问题：真实序列化/反序列化往返、过滤器与拦截器链、容器级异常处理、真实 HTTP 状态码、连接与编码行为。这与"核心落库禁止全 Mock"是同一条原则——能用真实链路验证的，就不用模拟链路。
>
> **MockMvc 仅在以下情形作为降级**，且必须在用例备注里写明降级原因：
> - 遗留工程框架版本过老，无法启动嵌入式容器跑 `RANDOM_PORT`；
> - 真实容器启动存在已知阻塞且短期无法解决（须附问题记录链接）。
>
> 降级用 MockMvc 时视为"未完全验证 HTTP 层"，需在测试报告中标注，不得标"HTTP 层已验证通过"。

### 各层级验证重点

#### L1 单元测试

| 验证内容 | 示例 |
|---------|------|
| 业务逻辑分支 | if/else 每个分支都走到 |
| 状态流转规则 | 合法/非法转换判定 |
| 异常抛出 | 条件满足时抛出正确异常 |
| 方法调用顺序 | 钩子按注册顺序调用 |
| 数据转换 | Converter 字段映射正确 |

**不验证：** HTTP 状态码、参数校验注解、数据库约束、事务回滚

#### L2 接口测试

| 验证内容 | 示例 |
|---------|------|
| HTTP 状态码 | 正常 200、签名失败 401、参数错误 400 |
| 参数校验注解生效 | @NotBlank、@Pattern、@Size 拦截无效入参 |
| 请求反序列化 | JSON → Request 对象映射正确 |
| 响应序列化 | Response 对象 → JSON 格式正确 |
| 异常映射 | 业务异常 → 对应错误码和 HTTP 状态码 |
| @SkipAuth 生效 | 无 Token 也能访问 |

**不验证：** 数据库实际写入、事务回滚、真实业务逻辑

#### L3 集成测试

| 验证内容 | 示例 |
|---------|------|
| 唯一索引幂等 | 重复 source_event_id 插入被拦截 |
| 事务回滚 | 异常时数据不落库 |
| SQL 正确性 | 复杂查询条件返回正确结果 |
| 级联更新 | 更新 session 时 latest_message_at 正确 |
| 自动填充 | created_date、last_updated_date 自动写入 |
| 数据隔离 | 测试数据不污染其他测试 |

**不验证：** HTTP 层、外部服务调用

#### L4 端到端测试

| 验证内容 | 示例 |
|---------|------|
| 完整业务路径 | 用户发消息 → 回调落库 → 未读数+1 → 钩子触发 |
| 多 Story 协作 | STORY-001 注册身份 → STORY-002 发消息 → STORY-012 工单重开 |
| 外部服务交互 | 调用融云 SDK 发送消息（WireMock 模拟） |
| 数据最终一致性 | 全链路执行后各表数据状态正确 |

**不验证：** 真实外部服务（用 WireMock/Mock Server 替代）

### 用例层级分配规则

| 场景 | 应在哪层测试 | 原因 |
|------|------------|------|
| 业务逻辑分支（if/else） | L1 | 快速验证，无需外部依赖 |
| 状态机合法/非法判定 | L1 | 纯逻辑 |
| HTTP 参数校验（@NotBlank 等） | L2 | 需要 Spring MVC 框架参与 |
| HTTP 状态码映射 | L2 | 需要异常处理器参与 |
| 唯一索引幂等 | L3 | 需要真实数据库 |
| 事务回滚 | L3 | 需要真实事务管理器 |
| SQL 执行计划 | L3 | 需要真实数据库 |
| 完整业务流程 | L4 | 需要多组件协作 |
| 外部 API 调用 | L4 | 需要 Mock Server |

## 第一层：按 Story 类型选策略

### 场景类型识别

> 一个 Story 可能同时属于多种类型，需叠加对应策略。

| Story 类型 | 识别特征 | 覆盖策略 |
|-----------|---------|---------|
| 状态机 | 包含状态流转、transition、状态枚举 | 完整转换矩阵 + 多步序列 |
| CRUD | 增删改查接口 | 正常 + 边界 + 异常 |
| 回调/Webhook | 外部系统推送、幂等处理 | 签名 + 幂等 + 数据一致 + 重试 |
| 定时任务 | 定时触发、批量处理 | 正常 + 空跑 + 边界 + 并发 + 异常 |
| 集成/编排 | 调用多个服务、事务编排 | 全成功 + 逐环节失败 + 回滚 |

### 策略一：状态机

**覆盖要求：** N×(N-1) 条单步路径 + 关键多步序列

#### 单步转换矩阵

1. 列出所有状态枚举值
2. 生成完整转换矩阵（每个状态 → 其他所有状态）
3. 标注每条路径：合法 / 非法
4. 合法路径：验证状态变更 + 副作用（关联表同步、事件发送）
5. 非法路径：验证拒绝 + 状态不变 + 错误码

```markdown
| 当前状态 \ 目标状态 | STATE_A | STATE_B | STATE_C | STATE_D |
|-------------------|---------|---------|---------|---------|
| STATE_A | — | ✅ 合法 | ❌ 非法 | ✅ 合法 |
| STATE_B | ❌ 非法 | — | ✅ 合法 | ✅ 合法 |
| STATE_C | ❌ 非法 | ❌ 非法 | — | ❌ 非法 |
| STATE_D | ❌ 非法 | ❌ 非法 | ❌ 非法 | — |
```

#### 多步序列

覆盖关键业务路径的端到端流转：

| 序列 | 说明 |
|------|------|
| 初始 → 中间态 → 终态（正常结束） | 完整生命周期 |
| 初始 → 中间态 → 终态（超时结束） | 超时路径 |
| 初始 → 中间态 → 重开 → 中间态 → 终态 | 重开路径（如有） |

#### 额外覆盖

- 初始化（create）：验证初始状态
- 并发流转：两个请求同时流转同一资源
- 幂等：相同流转请求重复提交

---

### 策略二：CRUD

**覆盖要求：** 每个操作覆盖正常 + 边界 + 规则 + 权限

| 操作 | 必覆盖场景 |
|------|-----------|
| Create | 正常创建、必填字段缺失、唯一约束冲突、关联数据不存在 |
| Read | 存在返回、不存在返回空/404、分页边界（page=0、超大page） |
| Update | 正常更新、目标不存在、乐观锁冲突、字段校验失败 |
| Delete | 正常删除、目标不存在、有关联数据时拒绝删除 |

---

### 策略三：回调/Webhook

**覆盖要求：** 签名 + 幂等 + 数据一致性 + 字段校验 + 异常恢复

| 场景分类 | 必覆盖场景 |
|---------|-----------|
| 签名 | 有效签名、无效签名、缺少签名头、过期时间戳 |
| 幂等 | 首次处理、重复处理（相同事件ID） |
| 数据一致 | 关联数据存在、关联数据不存在（如 session 不存在） |
| 字段校验 | 必填字段缺失、枚举值非法、字段超长 |
| 异常恢复 | DB 写入失败（触发重试）、部分成功 |

---

### 策略四：定时任务

| 场景分类 | 必覆盖场景 |
|---------|-----------|
| 正常执行 | 有待处理数据、批量处理正确 |
| 空跑 | 无待处理数据，任务正常结束 |
| 边界 | 刚好到达阈值、刚好未到达 |
| 并发 | 多实例同时触发（分布式锁） |
| 异常 | 处理中某条数据失败，不影响其他数据 |

---

### 策略五：集成/编排

| 场景分类 | 必覆盖场景 |
|---------|-----------|
| 全链路成功 | 所有服务调用成功 |
| 逐环节失败 | 第1步失败、第2步失败、...、第N步失败 |
| 事务回滚 | 失败时前序操作是否正确回滚 |
| 超时 | 某个服务调用超时 |
| 降级 | 非核心服务失败时是否降级处理 |

## 第二层：通用覆盖维度

> 无论 Story 属于哪种类型，以下维度都必须覆盖。

### 维度一：输入字段边界

**对接口契约中的每个字段做等价类划分：**

| 字段类型 | 有效等价类 | 无效等价类 | 边界值 |
|---------|-----------|-----------|--------|
| String（必填） | 正常值 | null、空串、纯空格 | 1字符、最大长度、最大长度+1 |
| String（枚举） | 枚举内的值 | 枚举外的值、null、空串 | — |
| Long（必填） | 正数 | null、0、负数 | 1、Long.MAX |
| Long（ID） | 存在的 ID | 不存在的 ID、null、0 | — |
| List | 非空列表 | null、空列表 | 1个元素、最大允许数 |

**生成规则：**
- 每个字段至少 1 条有效值用例 + 1 条无效值用例
- 有明确长度限制的字段，增加边界值用例

---

### 维度二：权限与鉴权

| 场景 | 必覆盖 |
|------|--------|
| 正常权限 | 有权限用户正常操作 |
| 无权限 | 无权限用户调用，返回 403/权限错误码 |
| 跨资源 | 操作非本人资源（如坐席操作他人工单） |
| @SkipAuth 接口 | 不需要权限用例，但需要替代验证（如签名） |

---

### 维度三：并发

| 场景 | 必覆盖 |
|------|--------|
| 同一资源并发写 | 两个请求同时修改同一条记录 |
| 乐观锁冲突 | 版本号不一致时的处理 |
| 分布式锁竞争 | 获取锁失败时的处理 |
| 幂等重复提交 | 相同请求短时间内重复提交 |

**适用条件：** Story 涉及写操作且可能被并发调用时必须覆盖。

---

### 维度四：关联数据状态

**对 Story 中每个"查询关联数据"的步骤，覆盖关联数据的各种状态：**

| 关联数据 | 必覆盖状态 |
|---------|-----------|
| 存在且状态正常 | 正常路径 |
| 不存在 | 异常路径（抛异常/返回错误码） |
| 存在但状态异常 | 如 session 已关闭、用户已禁用 |

**生成规则：** 主流程中每个"查询"步骤，都要有"查不到"的反向用例。

---

### 维度五：多步序列（端到端）

**覆盖关键业务路径的完整链路：**

| 类型 | 说明 |
|------|------|
| 正常完整路径 | 从创建到结束的完整生命周期 |
| 异常中断路径 | 中间某步失败后的状态一致性 |
| 重试恢复路径 | 失败后重试是否能恢复 |

**适用条件：** Story 涉及多步操作或状态流转时必须覆盖。

---

### 维度六：字段组合

**当多个字段之间存在业务约束时，覆盖组合场景：**

| 场景 | 示例 |
|------|------|
| 合法组合 | senderType=USER + msgType=TEXT |
| 非法组合 | senderType=USER + msgType=SYSTEM（系统消息不应由用户发送） |
| 条件依赖 | 当 status=RESOLVED 时 closedReason 必填 |

**生成规则：** 识别接口契约中字段间的隐含约束，生成组合用例。

## 用例数量自检

### 第一层（类型策略）最少用例数

| Story 类型 | 公式 |
|-----------|------|
| 状态机 | N×(N-1) + 多步序列数 + 初始化 + 并发 |
| CRUD | 操作数 × 4 |
| 回调 | 签名(4) + 幂等(2) + 数据一致(N) + 字段(N) + 异常(2) |
| 定时任务 | 5 |
| 集成 | 1 + N |

### 第二层（通用维度）最少用例数

| 维度 | 公式 |
|------|------|
| 输入字段边界 | 字段数 × 2（有效+无效） |
| 权限 | 2~3（正常+无权限+跨资源） |
| 并发 | 2~3（有写操作时） |
| 关联数据状态 | 查询步骤数 × 2（存在+不存在） |
| 多步序列 | 关键路径数 |
| 字段组合 | 有约束的字段组合数 |

### 总用例数

**总用例数 = 第一层 + 第二层（去重后）**

> 第一层和第二层可能有重叠（如回调策略的"字段校验"与通用维度的"输入字段边界"），去重后取并集。
