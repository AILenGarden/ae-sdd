# Story 前端接口契约标准（①bis）

## 适用范围

- 只要 Story 涉及前端页面、组件、表单、列表、详情、弹窗、上传、轮询、SSE、WebSocket、联调或状态展示，就必须引用本标准。
- 如果 Story 确实不涉及前端交互，可以在 Story 中标注 `不涉及`，但必须说明原因，不得默认跳过。

## 必填维度

1. 契约完整性
2. 调用流程与依赖
3. 状态展示
4. 错误码与异常
5. 边界场景
6. 联调支持

## 每个接口条目至少包含

- 方法与路径
- 请求头
- 请求体
- 响应体
- 错误码
- 调用时机
- 状态流转
- 前端展示或提示
- 联调说明

## 审核规则

- 生成阶段负责把 6 个维度填全，Review 阶段只校验完整性、可联调性和与 DR / 原型的一致性。
- 任一维度缺失，都视为该 Story 的前端契约未完成。
- 只有在 Story 已明确写出前端契约章节，或明确说明 `不涉及` 时，Review 才能通过。

## 建议模板

> 接口契约统一放在 `story-template.md` 的 `## 接口契约` 章节，先按“新增接口 / 复用与既有接口”分组，再在组内使用 `REST-N` / `SPI-N` 独立编号。REST 接口块融合后端契约与前端视角；SPI 保持服务间协议中立。下方为最小接口条目结构，完整结构以 `story-template.md §接口契约` 为准。

```markdown
## 接口契约

### 新增接口

### REST-1：{METHOD} {/path}
（REST 八段契约 + 前端视角）

### SPI-1：{签名}
（协议中立的 Request / DTO + 错误与降级）

### 复用 / 既有接口

### REST-2：{METHOD} {/path}
（完整 REST 契约 + 现状证据 + 直接复用 / 既有扩展 / 回归验证 + 本次变更边界）
```

## 与技能的关系

- `source/skills/phase1-design/story-generate-skill.md` 负责把本标准填入 Story。
- `source/skills/phase1-design/story-review-skill.md` 负责检查本标准是否完整。
