# 模板排版规范（Template Layout Standard）

> **🔴 强制：** 本规范是 `source/templates/` 下所有 Markdown 模板的排版 SSOT（Single Source of Truth）。所有模板在创建或修改时必须遵守本规范，违反即视为排版缺陷。
>
> **适用范围：** `source/templates/**/*.md`（22 个模板）。YAML 配置模板（`*.yaml`）不适用本规范。
>
> **配套：** `ae-sdd-update-skill.md` 维护本规范；模板修改后跑 `grep` 自检（见 §11 验证清单）。

---

## 1. 必填/选填标记 `🔴 强制`

标题尾部用反引号标记必填性，格式：`` `必填` `` / `` `选填（条件）` `` / `` `🔴 强制` ``。

**✅ 正确：**

```markdown
## 接口契约 `必填`
### 联调信息 `选填（有前端对接时必填）`
### ①bis 6 维度自检 `🔴 全部通过才能视为本章节完成`
```

**❌ 错误：**

```markdown
## 接口契约（🔴 必填）           ← 全角括号内联
## 接口契约 [已确认]              ← 方括号标注
## 接口契约-SPI/API               ← 无标记
### 接口契约 `核心`               ← 非标准词汇
### 接口契约 `按需：有错误时`      ← 非标准词汇
```

**标记词汇表（仅允许以下 4 种）：**

| 标记 | 含义 | 用法 |
|------|------|------|
| `` `必填` `` | 章节必须填写 | 核心章节 |
| `` `选填（条件）` `` | 满足条件时必填 | 非核心章节，条件写在括号内 |
| `` `选填` `` | 可选 | 辅助章节 |
| `` `🔴 强制` `` | 强制执行（非"填写"语义，用于自检/约束类章节） | 自检清单、红线声明 |

## 2. 表格分隔符 `🔴 强制`

Markdown 表格分隔行统一用 `| --- |` 格式：每列的分隔符前后各一个空格。

**✅ 正确：**

```markdown
| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | Long | 用户 ID |
```

**❌ 错误：**

```markdown
|字段|类型|说明|          ← 无空格
|------|------|------|    ← 紧凑无空格
|----|----|               ← 短横线且无空格
```

> **理由：** 带空格的分隔符在所有 Markdown 渲染器中表现一致，且源码可读性更好。

---

## 3. 章节分隔线 `🔴 强制`

每个 `##` 二级章节之间用 `---` 分隔。文档末尾（最后一章后）**不**加 `---`。

**✅ 正确：**

```markdown
## 1. 元信息 `必填`

（内容）

---

## 2. 用户故事 `必填`

（内容）

---

## 3. 范围 `必填`

（内容，文档结束，无尾随 ---）
```

**❌ 错误：**

- 章节间无 `---`（如 prd-template 原状态）
- 文档末尾多余 `---`（如部分 project-assets 模板）

> **`###` 三级章节之间：** 不强制 `---`（三级章节属同一二级章节内，用空行分隔即可）。

---

## 4. 占位符 `🔴 强制`

统一用 `{占位符}` 花括号格式。

**✅ 正确：**

```markdown
# STORY-{number}-{title}
- Story ID：{STORY-ID}
| 字段 | 类型 | 说明 |
```

**❌ 错误：**

```markdown
# STORY-<number>-<title>          ← 尖括号
- Story ID：（STORY-ID）           ← 全角括号
- Story ID：XXX                    ← 裸 XXX
- Story ID：待填写                 ← 中文文字占位
```

**命名规范：**
- 英文标识符用大写下划线：`{STORY-ID}` / `{PRD-ID}` / `{DR-ID}`
- 中文描述性占位用中文：`{一句话描述}` / `{角色}`（用于自然语言占位，非标识符）
- 可选标记不用 `?` 后缀（如 `{STORY-ID?}`），改在标题用 `` `选填` `` 标记

---

## 5. 章节编号 `🔴 强制`

纯阿拉伯数字编号：`## 1.` / `## 2.`，子节 `### 1.1` / `### 1.2`。

**✅ 正确：**

```markdown
## 1. 元信息 `必填`
## 2. 用户故事 `必填`
### 2.1 包含
### 2.2 不包含
## 3. 范围 `必填`
```

**❌ 错误：**

```markdown
## 一、元信息                     ← 中文数字
## §1. 元信息                     ← § 前缀
## 1.5 元信息                     ← 小数子章（无 1.1-1.4）
## §0.5 元信息                    § 前缀 + 小数
## 八.5、标题                     ← 中文+小数混搭
### 9-bis / ### 9-ter            ← 拉丁后缀
```

**例外：** 文档内引用历史章节名（如"§接口契约"作概念引用）不受此限；但模板自身的章节标题必须用阿拉伯数字编号。

## 6. 示例引导 `🟡 一般`

统一用 `> 示例：` 引用块引导示例。

**✅ 正确：**

```markdown
> 示例：
>
> | 字段 | 类型 | 说明 |
> | --- | --- | --- |
> | id | Long | 用户 ID |
```

**❌ 错误：**

```markdown
**填写示例：**                  ← 加粗引导而非引用块
### 实例：xxx 项目               ← 示例作独立章节（除非跨多节）
（示例直接跟在表格后无引导语）
```

> **例外：** 集中型附录（如 codereview 的"附录 A：填示例"）可保留为独立章节，因为其示例跨多节。

---

## 7. 强制规则锚点 `🟡 一般`

强制规则/红线统一用 `> **🔴 强制：**` 引用块 + 加粗格式。

**✅ 正确：**

```markdown
> **🔴 强制：** 每个字段都必须填写四维，禁止留白。
```

**❌ 错误：**

```markdown
**红线：** 每个字段...           ← 非引用块
> **强制规则**：每个字段...      ← 无 🔴 emoji
> - 🔴 每个字段...               ← 列表项形式
```

## 8. emoji 语义 `🟢 建议`

全模板统一 emoji 语义，同一语义用同一 emoji：

| emoji | 语义 | 典型用法 |
|-------|------|---------|
| 🔴 | 阻断/强制/必填 | 强制规则、阻断型问题 |
| 🟠 | 严重 | 严重型问题 |
| 🟡 | 一般/警告 | 一般型问题、软提示 |
| 🟢 | 建议/通过 | 建议型、通过状态 |
| ✅ | 完成/通过 | 已完成、测试通过 |
| ❌ | 失败 | 测试失败、不可用 |
| ⚠️ | 警告/注意 | 注意事项 |
| 🆕 | 新增 | 新版本新增内容 |

> emoji 用于正文/表头/引用块，**不用于**标题标记位（标题标记位用反引号 `` `必填` ``，不用 emoji）。

## 9. 文档头部声明 `🟡 一般`

统一头部格式：H1 标题 → `>` 引用块含"适用场景"+"精简规则"（可选"集成规范"）。

**✅ 正确：**

```markdown
# STORY-{number}-{title}

> **适用场景：** 需要前端对接的 Story（绝大多数 Story）。
>
> **精简规则：** 纯后端无前端交互的 Story 可在前端章节标注"不涉及"。

---

## 1. 元信息 `必填`
```

**❌ 错误：**

- 头部仅键值对元信息，无"适用场景"引导语（如 project-assets 三个 topic 原状态）
- 头部用普通段落而非 `>` 引用块（如 slim-entry 原状态）

> **frontmatter：** 有 YAML frontmatter 的模板（`---` + `name:` + `description:`）保留 frontmatter，头部声明放在 frontmatter 之后。

---

## 10. 末尾收尾 `🟢 建议`

文档末尾（最后一章后）**不**加 `---`，文档自然结束。

**✅ 正确：**

```markdown
## 9. 附录

（内容，文档结束）
```

**❌ 错误：**

```markdown
## 9. 附录

（内容）

---                    ← 多余的尾随分隔线
```

---

## 11. 验证清单 `🔴 强制`

模板修改后必须跑以下 grep 自检（全部应为 0 或符合预期）：

```bash
# 1. 表格分隔符无空格（应为 0）
grep -rn "|---|\||----|\||-----|\||------|" source/templates/

# 2. 全角括号/方括号标记（应为 0）
grep -rn "（🔴 必填）\|（🔴 维度\|\[已确认\]" source/templates/

# 3. 尖括号占位符（应为 0，HTML 标签除外）
grep -rn "<[A-Za-z]" source/templates/

# 4. 中文数字/§前缀章节编号（应为 0）
grep -rn "^## §\|^## 一、\|^## 二、" source/templates/

# 5. 文档末尾多余 ---（人工抽查）
```

## 12. 与现有标准的关系

| 现有标准 | 关系 |
|---------|------|
| `story-generation-standard.md` §2.5 章节映射表 | 引用模板章节名，不依赖编号——编号变更不影响 |
| `story-frontend-contract-standard.md` | 建议模板格式已对齐本规范 §5/§6 |
| `gates.py:_check_source_trace()` | 依赖"标题含'接口契约'字样"，不依赖编号——安全 |
| `review_loop.py` Tier 维度名 | 用维度名（如"接口契约"），不依赖编号——安全 |
