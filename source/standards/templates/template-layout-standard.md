# 模板排版规范（Template Layout Standard）

> **🔴 强制：** 本规范是 `source/templates/` 下所有 Markdown 模板的排版 SSOT（Single Source of Truth）。所有模板在创建或修改时必须遵守本规范，违反即视为排版缺陷。填写义务默认由模板内声明表承载；采用独立撰写指南的模板遵守 §1.1.1 的外部指南模式。
>
> **适用范围：** `source/templates/**/*.md`（22 个模板）。YAML 配置模板（`*.yaml`）不适用本规范。
>
> **配套：** `ae-sdd-update-skill.md` 维护本规范；模板修改后跑 `grep` 自检（见 §11 验证清单）。

---

## 1. 必填/选填标记

> **🆕 v3.9.12 起变更：** 必填/选填标记从「标题尾部后缀」迁移到「文件顶部集中声明表」；需要将 SOP 与模板分离时，可采用 §1.1.1 的独立撰写指南模式。标题保持纯语义，不再承载填写义务标记。

### 1.1 集中声明表（默认模式）

采用默认模式的模板必须在元信息之后、使用说明/目录（如有）之后、首个正文章节之前放置一张《填写声明表》，集中声明所有章节的填写义务。标题行不再标注任何必填/选填后缀。对于包含元信息章节的文档模板，元信息必须紧跟 H1，作为 H1 后第一个语义块；不含元信息章节的模板沿用其适用的头部声明模式。

**✅ 正确：**

```markdown
## 1. 元信息

（文档类型、ID、来源、作者、日期、状态等）

---

## 填写声明表

> 本模板采用"两大段"结构：本表集中声明所有章节的**填写义务**，正文每章节按"骨架 + 示例"两段组织。
> 章节标题不再标注 `必填/选填`；判定依据统一查此表。

| § | 章节 | 填写义务 | 适用条件 |
| --- | --- | --- | --- |
| 1 | 元信息 | 🔴 必填 | 全部 |
| 2 | 设计目标 | 🔴 必填 | 全部 |
| 6 | 关键时序 | 🟡 选填（条件） | 有跨服务复杂交互时 |

**填写义务图例：**
- 🔴 **必填** — 必须填写，不能为空，不能删章节
- 🟡 **选填（条件）** — 仅当"适用条件"成立时必填；条件不成立可整节删除

---

## 2. 第一个正文章节
```

正文章节标题保持干净：

```markdown
## 接口契约
### 新增接口
### REST-1：{METHOD} {/path}
### SPI-1：{接口签名}
### 复用 / 既有接口
```

**❌ 错误（v3.9.12 前的旧做法，已废弃）：**

```markdown
## 接口契约 `必填`                       ← 标题尾部后缀（已废弃）
### 联调信息 `选填（有前端对接时必填）`    ← 标题尾部后缀（已废弃）
## 接口契约（🔴 必填）                    ← 全角括号内联
## 接口契约 [已确认]                       ← 方括号标注
```

### 1.1.1 独立撰写指南模式（模板与 SOP 分离）

当模板需要只承载结构、而将必填/选填、撰写原则、来源要求和 Review 口径放入独立撰写指南时，可以不在模板内放置《填写声明表》。此模式必须同时满足：

1. 模板通过稳定的 section ID 或等价机器可读标识声明章节边界；
2. 独立指南按相同 ID 覆盖所有需要填写义务的章节，并成为这些规则的唯一权威来源；
3. 模板文件显式指向该指南，生成、Review、Update 流程通过统一资源路由读取指南正文；
4. 模板正文不得复制指南中的必填/选填清单、撰写原则或 Review SOP。

Story 模板采用本模式，配套指南为 `source/standards/story/story-writing-guide.md`。其他模板未显式声明采用本模式时，仍遵守 §1.1 的默认模式。

### 1.2 填写义务标记词汇表（仅允许以下 2 种，用于声明表「填写义务」列）

| 标记 | 含义 | 用法 |
|------|------|------|
| 🔴 **必填** | 章节必须填写 | 核心章节 |
| 🟡 **选填（条件）** | 满足条件时必填 | 非核心章节，条件写在「适用条件」列 |

> **注：** 旧词汇表中的 `` `🔴 强制` ``（自检/约束类章节）已合并入 🔴 **必填**。子章节（### 级）也进声明表，用 `└` 缩进表示层级。

### 1.3 保留不迁移的情况

以下场景的"必填/选填"字眼**不迁移到声明表**，保持原样：
- 表格行内的"必填"列头（如 `| 字段 | 类型 | 必填 | ...`）—— 这是表格自身语义
- 引用块（`>` 开头）内的规则说明（如 `> **🔴 必填规范...**`）
- 行内说明文案里的"必填"（如占位符 `` `{必填。描述...}` `` 内的文字）
- 接口块内部的子标题行内标注（如 `**状态展示建议** \`🔴 仅...时必填\``）—— 适用条件依赖具体接口上下文，不适合集中化

## 2. 表格分隔符

Markdown 表格分隔行统一用 `| --- |` 格式：每列的分隔符前后各一个空格。

**✅ 正确：**

```markdown
| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | Long | 用户 ID |
```

**❌ 错误：**

```markdown
|字段|类型|说明|          ← 无空格
|------|------|------|    ← 紧凑无空格
|----|----|               ← 短横线且无空格
```

> **理由：** 带空格的分隔符在所有 Markdown 渲染器中表现一致，且源码可读性更好。

---

## 3. 章节分隔线

每个 `##` 二级章节之间用 `---` 分隔。文档末尾（最后一章后）**不**加 `---`。

**✅ 正确：**

```markdown
## 1. 元信息

（内容）

---

## 2. 用户故事

（内容）

---

## 3. 范围

（内容，文档结束，无尾随 ---）
```

**❌ 错误：**

- 章节间无 `---`（如 prd-template 原状态）
- 文档末尾多余 `---`（如部分 project-assets 模板）

> **`###` 三级章节之间：** 不强制 `---`（三级章节属同一二级章节内，用空行分隔即可）。

---

## 4. 占位符

统一用 `{占位符}` 花括号格式。

**✅ 正确：**

```markdown
# STORY-{number}-{title}
- Story ID：{STORY-ID}
| 字段 | 类型 | 说明 |
```

**❌ 错误：**

```markdown
# STORY-<number>-<title>          ← 尖括号
- Story ID：（STORY-ID）           ← 全角括号
- Story ID：XXX                    ← 裸 XXX
- Story ID：待填写                 ← 中文文字占位
```

**命名规范：**
- 英文标识符用大写下划线：`{STORY-ID}` / `{PRD-ID}` / `{DR-ID}`
- 中文描述性占位用中文：`{一句话描述}` / `{角色}`（用于自然语言占位，非标识符）
- 可选标记不用 `?` 后缀（如 `{STORY-ID?}`），改在《填写声明表》用 🟡 **选填（条件）** 标记（v3.9.12 起）

---

## 5. 章节编号

纯阿拉伯数字编号：`## 1.` / `## 2.`，子节 `### 1.1` / `### 1.2`。

**✅ 正确：**

```markdown
## 1. 元信息
## 2. 用户故事
### 2.1 包含
### 2.2 不包含
## 3. 范围
```

**❌ 错误：**

```markdown
## 一、元信息                     ← 中文数字
## §1. 元信息                     ← § 前缀
## 1.5 元信息                     ← 小数子章（无 1.1-1.4）
## §0.5 元信息                    § 前缀 + 小数
## 八.5、标题                     ← 中文+小数混搭
### 9-bis / ### 9-ter            ← 拉丁后缀
```

**例外：** 文档内引用历史章节名（如"§接口契约"作概念引用）不受此限；但模板自身的章节标题必须用阿拉伯数字编号。

---

## 6. 示例引导

统一用 `> 示例：` 引用块引导示例。

**✅ 正确：**

```markdown
> 示例：
>
> | 字段 | 类型 | 说明 |
> | --- | --- | --- |
> | id | Long | 用户 ID |
```

**❌ 错误：**

```markdown
**填写示例：**                  ← 加粗引导而非引用块
### 实例：xxx 项目               ← 示例作独立章节（除非跨多节）
（示例直接跟在表格后无引导语）
```

> **例外：** 集中型附录（如 codereview 的"附录 A：填示例"）可保留为独立章节，因为其示例跨多节。

---

## 7. 强制规则锚点

强制规则/红线统一用 `> **🔴 强制：**` 引用块 + 加粗格式。

**✅ 正确：**

```markdown
> **🔴 强制：** 每个字段都必须填写四维，禁止留白。
```

**❌ 错误：**

```markdown
**红线：** 每个字段...           ← 非引用块
> **强制规则**：每个字段...      ← 无 🔴 emoji
> - 🔴 每个字段...               ← 列表项形式
```

## 8. emoji 语义

全模板统一 emoji 语义，同一语义用同一 emoji：

| emoji | 语义 | 典型用法 |
|-------|------|---------|
| 🔴 | 阻断/强制/必填 | 强制规则、阻断型问题 |
| 🟠 | 严重 | 严重型问题 |
| 🟡 | 一般/警告 | 一般型问题、软提示 |
| 🟢 | 建议/通过 | 建议型、通过状态 |
| ✅ | 完成/通过 | 已完成、测试通过 |
| ❌ | 失败 | 测试失败、不可用 |
| ⚠️ | 警告/注意 | 注意事项 |
| 🆕 | 新增 | 新版本新增内容 |

> emoji 用于正文/表头/引用块/《填写声明表》，标题保持纯语义不加任何标记（v3.9.12 起，标题标记位后缀已废弃）。

## 9. 文档头部声明

统一头部顺序：对于包含元信息章节的模板，使用 H1 标题 → 元信息（必须是 H1 后第一个语义块）→ 使用说明/适用场景/目录（可选）→ 《填写声明表》（默认模式）→ 第一个正文章节；不含元信息章节的模板使用 H1 → 适用场景/精简规则/目录 → 《填写声明表》（如适用）→ 第一个正文章节。头部说明可使用 `>` 引用块表达"适用场景"+"精简规则"（可选"集成规范"）。

**✅ 正确：**

```markdown
# STORY-{number}-{title}

## 1. 元信息

- 文档类型：Story
- Story ID：{STORY-ID}
- 来源 PRD：{PRD-ID}
- 来源 DR：{DR-ID}
- 作者：{作者}
- 状态：Draft

---

> **适用场景：** 需要前端对接的 Story（绝大多数 Story）。
>
> **精简规则：** 纯后端无前端交互的 Story 可在前端章节标注"不涉及"。

---

## 填写声明表

> （v3.9.12 起，填写义务集中于此表，标题不加后缀）

| § | 章节 | 填写义务 | 适用条件 |
| --- | --- | --- | --- |
| ... | ... | ... | ... |

---

## 2. 第一个正文章节
```

**❌ 错误：**

- 对包含元信息章节的模板，H1 后先出现目录、使用说明、填写声明表或其他正文，元信息未作为第一个语义块
- 元信息缺失核心字段（如文档类型、ID、来源、作者、状态）
- 头部说明需要引用块时却使用普通段落（如 slim-entry 原状态）

> **frontmatter：** 有 YAML frontmatter 的模板（`---` + `name:` + `description:`）保留 frontmatter，头部声明放在 frontmatter 之后。

---

## 10. 末尾收尾

文档末尾（最后一章后）**不**加 `---`，文档自然结束。

**✅ 正确：**

```markdown
## 9. 附录

（内容，文档结束）
```

**❌ 错误：**

```markdown
## 9. 附录

（内容）

---                    ← 多余的尾随分隔线
```

## 11. 验证清单

模板修改后必须跑以下 grep 自检（全部应为 0 或符合预期）：

```bash
# 1. 表格分隔符无空格（应为 0）
grep -rn "|---|\||----|\||-----|\||------|" source/templates/

# 2. 全角括号/方括号标记（应为 0）
grep -rn "（🔴 必填）\|（🔴 维度\|\[已确认\]" source/templates/

# 3. 尖括号占位符（应为 0，HTML 标签除外）
grep -rn "<[A-Za-z]" source/templates/

# 4. 中文数字/§前缀章节编号（应为 0）
grep -rn "^## §\|^## 一、\|^## 二、" source/templates/

# 5. 标题尾部必填/选填后缀（v3.9.12 起应为 0）
grep -rnE "^#{1,4} .*(\`必填|\`选填|\`🔴)" source/templates/

# 6. 文档末尾多余 ---（人工抽查）
```

## 12. 与现有标准的关系

| 现有标准 | 关系 |
|---------|------|
| `story-generation-standard.md` §2.5 章节映射表 | 引用模板章节名，不依赖编号——编号变更不影响 |
| `story-frontend-contract-standard.md` | 建议模板格式已对齐本规范 §5/§6 |
| sourceTrace 门禁检查 | 依赖“标题含‘接口契约’字样”（子串匹配），不依赖编号；统一 `## 接口契约` 章节继续兼容。章节内先按“新增接口 / 复用与既有接口”分组，组内保留 `SPI-N` / `REST-N` 独立编号。 |
| review loop Tier 维度名 | 用维度名（如"接口契约"），不依赖编号——安全 |
