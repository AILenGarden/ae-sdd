# 业务文档写作密度规范（Document Density Standard）

> 适用范围：AI 生成的 RA / DR / Story / TestCase 等业务文档正文密度。
> 标准版本：`ae-sdd-doc-density/v1`。
> 资源路由：`DOC_DENSITY_STANDARD`（通过 `resolve_read_resource` 加载）。
> 维护：`ae-sdd-update-skill.md` 经 `update-graph.json` UG-30 联动。

## 0. 与相邻规范的边界（不重叠）

本规范只管"业务文档正文写多密"。下列相邻规范各管各的，不适用本规范：

| 相邻规范 | 管辖范围 | 与本规范关系 |
| --- | --- | --- |
| `standards/skill-source-slimming-standard.md` | `source/SKILL.md` 与 `source/skills/**/*.md` 的加载体积（slim entry + fallback 变换） | 互不重叠；本规范不管方法论文件维护 |
| `ae-sdd-update-skill` 的「极简描述原则」 | SKILL.md / 子 SKILL / `source/docs/*.md` 等方法论维护文件 | 互不重叠；本规范不管方法论文件维护 |
| `standards/toolsets/memory-layering.md` compact slice 高密度原则 | compact slice 编译产物风格 | 互不重叠；本规范不管 memory 层 |
| 「输出核心原则」（输出诚实性 / 基于事实 / 禁止编造） | 内容真值性 | 正交维度；本规范**不定义**输出核心原则 |

本规范**不替代**各 generate SKILL 的章节写作指南（DR 模板粒度要求、`story-writing-guide.md`），只提供横切的密度红线。章节"写什么"由写作指南决定，"写多密"由本规范决定；冲突时以本规范红线为准。

## 1. 目标

每行都承载可执行判断。砍掉四类膨胀：

- 重复登记（同一信息全文档多次出现）
- 背景叙事（"为什么这样设计"的故事性铺垫）
- 扩张式散文（能表格化的内容写成完整段落）
- 完整 JSON 示例（dump 整段响应体当示例）

保留语义的同时压到 AI 与 Reviewer 都能一屏判断的密度。

## 2. 硬性约束 D-1 ~ D-7

违反任一条 = Review 缺陷（🟡 一般型起步，影响核心章节升级为 🟠 严重型）。

| 编号 | 约束 | 阈值 | 计数口径 |
| --- | --- | --- | --- |
| D-1 | 单节正文散文行数 | ≤ 30 行 | 只计散文行；表格 / Mermaid 图 / 代码块不计入；超出需拆子节或表格化 |
| D-2 | 单条决策 / 规则 / 理由 | ≤ 3 行 | 超出压成 `key: value` 或单行短语 |
| D-3 | 示例段 | 单行 `key: value` | 禁 ≥ 2 行叙事性示例；复杂示例用最小有效表 |
| D-4 | 接口块子结构数 | ≤ 5 | 基本信息 / 请求 / 响应 / 错误 / 示例；超出合并同类 |
| D-5 | JSON / 代码示例行数 | ≤ 5 行 | 只放最小有效示例；禁完整 dump |
| D-6 | 表格优先 | 可表格化的禁止用散文 | 清单、字段表、决策对比、状态流转均走表格 |
| D-7 | 重复登记 | 同一信息全文档最多 1 处 | 多处出现改为互引指针（"详见 §X.Y"） |

## 3. 反模式清单（命中即停）

| # | 反模式 | 表现 | 修复 |
| --- | --- | --- | --- |
| AP-1 | 背景叙事 | "为了支持 XX 业务，我们需要……面临 YY 约束……因此决定……" | 删背景，只留决策结论 + 1 行依据 |
| AP-2 | 重复登记 | 同一字段 / 错误码 / 状态在 ≥ 2 处完整定义 | 留权威处 1 份，其余改"详见 §X.Y" |
| AP-3 | 扩张式必填 | 写作指南逐项罗列"必须覆盖 A/B/C/D/E/F/G" | 合并为"必须覆盖：签名、字段、错误、降级"等聚合短语 |
| AP-4 | 完整 JSON 示例 | dump 整段请求体 / 响应体当示例 | 改 ≤ 5 行最小有效示例，或单行字段表 |
| AP-5 | 明文鼓励散文 | 模板指引写"不只是映射表""需要详细说明"等 | 改为"表格为主，必要时补 1 行说明" |
| AP-6 | 跨章贯穿示范叙事 | 用一个虚构业务（如 IM 客服系统）在每章都跑一遍完整叙事 | 示例改为单章单点 `key: value`，不跨章贯穿 |

## 4. 写作前 5 问自检

每节落笔前默问，任一答"是"→ 删除或改写：

| # | 问题 | 答是时的动作 |
| --- | --- | --- |
| 1 | 这段是"为什么这样设计"的背景叙事？ | 删，或压成 1 行脚注 |
| 2 | 这段能用表格代替长段落？ | 改表格 |
| 3 | 这段重复了另一节已有的内容？ | 改成"详见 §X.Y"指针 |
| 4 | 这段示例 ≥ 2 行叙事？ | 压成单行 `key: value` |
| 5 | 删掉这句，AI 还能正确执行任务？ | 删 |

## 5. 写作后验收（DR / Story Review 时核对）

- [ ] D-1 ~ D-7 全过
- [ ] AP-1 ~ AP-6 零命中
- [ ] 写作前 5 问全答"否"
- [ ] 可表格化内容表格覆盖率 100%
- [ ] 所有示例均为单行或最小有效表
- [ ] 无完整 JSON dump
- [ ] 同一信息全文档无 ≥ 2 处完整定义

## 6. 适用边界（不管清单）

本规范明确**不管**以下事项，避免职责越界：

1. 不管源 SKILL.md / 子 SKILL 的加载体积（归 slimming standard）
2. 不管方法论文件维护密度（归极简描述原则）
3. 不管 compact memory slice 风格（归 memory-layering）
4. 不管输出诚实性 / 基于事实 / 禁止编造（归「输出核心原则」，另案）
5. 不管章节"写什么"（归各 generate SKILL 的写作指南）
