## 批 2：Task 3 + Task 6 - memory 重设计 + 编译

### 核心改造：memory 从"5层原文索引"重构为"业务实体树+编译文档容器"

#### 现状 vs 目标
| 维度 | 现状 | 目标 |
|---|---|---|
| 用途 | 5层各有用途(scratch/事件流/跨项目pattern/冷归档混入) | 只管上下文，存编译后的 compact 文档 |
| 内容 | 原文短索引(每条≤180字符JSONL) | 编译后的 compact.md 文档 |
| 分层 | phase×story×task 粗粒度(无PRD/DR维度) | prd/dr/story/testcase/coding/common 业务实体平级分层 |
| phase维度 | 5个phase各一jsonl文件 | 丢弃phase维度，按业务实体分层 |
| 隔离 | L1按story，L2 project全共享 | 各实体独立目录，common存项目级可复用约束 |
| 生命周期 | L1/L2永久留存，L0 session后可删 | 子流程结束删自己的(临时上下文)，common保留；从0重建先clean_all，回归先读无则建 |
| enter/exit | 生命周期门禁(check_state_transition) | 废弃，子流程启动=隐式enter(编译+写)，结束=隐式exit(删) |
| 旧内容 | - | 全废弃不迁移；L3 pattern迁项目资产，L4 archive迁独立归档目录 |

#### 新 memory 目录结构
```
.ae-sdd/memory/
├─ common/                  # 项目级可复用约束(必须轻)，跨子流程保留
│  └─ context.compact.md    # BigDecimal/幂等/禁大事务/架构规范/公共模板引用
├─ prd/{PRD-ID}/            # RA/PRD子流程的工作上下文
│  ├─ boot.compact.md       # 锚点/当前阶段/下一步/产物路径
│  ├─ context.compact.md    # 关键决策/约束/需求摘要
│  ├─ pending.compact.md    # 待决项/存疑项
│  └─ manifest.json         # 校验:source hash + fingerprint
├─ dr/{DR-ID}/              # DR子流程的工作上下文(同上4文件)
├─ story/{Story-ID}/        # Story子流程的工作上下文
├─ testcase/{Story-ID}/     # TestCase子流程的工作上下文
└─ coding/{Story-ID}/       # Coding子流程的工作上下文
```

**存储格式**：compact.md 文件（Markdown 表格/列表，可读可审查，符合编译器"不做密文"原则）+ manifest.json 校验。废弃 JSONL。

## 批 3：Task 5 + Task 1 - 3层Agent模型 + compact 闭环

### Task 5：3层Agent模型

#### 现状（2层，§8.5）vs 目标（3层）
```
现状: 主会话(root) ──派活──> sub-agent（执行单节点任务）
      root 既当指挥官又当士兵(读子SKILL/读源码/写文档) -> 上下文爆炸

目标: 主流程会话 ──委托──> 子流程Agent(物理独立session) ──派活──> sub-subAgent
      主流程: 只管主流程编排 + 监管子流程 + 用户对话 + 主state
              不读子SKILL正文、不读源码、不写流程文档
      子流程Agent: 接管1个系列(RA/DR/Story/TestCase/Coding)
        ├─ 物理独立 session（mavis spawn / 新 workflow）
        ├─ 拥有对应实体 memory（Task 3）
        ├─ 自己起 sub-subAgent 执行 generate/review
        └─ 交付物汇总回主流程
      sub-subAgent: 执行单系列内子任务
```

**5大子流程串行委托**：主流程按 RA->DR->Story->TestCase->Coding 依次委托子流程Agent。每个子流程Agent(物理独立session)接管1个系列，完成后交回主流程，主流程再委托下一个。

## 风险与缓解

1. **批 2 memory 重写破坏性大**：废弃 5 层 + enter/exit + JSONL，影响 memory_store/memory_gate/prompt_inject/gate_intercept/CLI 全链路。
   - **缓解**：分 3 批递进，批 2 独立可测；旧 memory 全废弃不迁移（用户已确认），无迁移风险。

2. **批 3 物理独立 session 依赖 runtime 能力**：mavis 支持 spawn，claude-code/codex 可能不支持。
   - **缓解**：复用现有 §8.4.5 降级机制--环境不支持物理 spawn 时降级为逻辑隔离并标注 `agentMode: "logical-isolated"`，自动化模式禁止降级。

3. **memory 编译质量**：总结+编译可能丢失关键细节。
   - **缓解**：保留 fallback 路径--memory 不足时回读源上下文（document-storage 永久存储）；manifest.json 记录 source hash 可检测漂移；common 严格限大小防臃肿。

4. **compact-trigger 修复改变行为**：当前只写不读是"无害半成品"，补读端会改变行为。
   - **缓解**：读端仅在子流程Agent + memory 存在时触发，主流程/无 memory 时走原逻辑（state.json 重建），向后兼容。

5. **5大子流程串行委托与现有 phase 状态机**：现有状态机是 initialized->ra->dr->story->testcase->coding->completed，与5大子流程串行一致，但子流程Agent接管后主流程不直接推进 phase。
   - **缓解**：子流程Agent完成后回传，主流程确认交付物 + 人工审核 ✅ 后才 `state write --phase <next>`。phase 推进权仍在主流程。
