# 三症同治：manifest 瘦身 + Story 真"已引用"门禁 + Review 深度门禁

## 根因诊断（已探查确认）

三个症状是同一个架构级病根的三面——**ae-sdd 把流程纪律几乎全押在 LLM 自觉（prose），机械门禁要么只查文件存在、要么不存在**：

| 症状 | 根因（证据） |
|---|---|
| manifest 加载慢 | `dist/ae-sdd/SKILL.md` bootloader Load 第 1 步要求 LLM 读整份 52KB manifest（≈14,849 tokens），其中 `subskills` 哈希 + `generated_files` 152 路径 + `source.checksums` 122 哈希 ≈ **13,000 tokens 纯垃圾**（只有 runtime_verify.py 用，LLM 不需要） |
| Story 不加载上下文/不按标准 | `G-STORY-CTX` 只查 `bool(assets)`/`bool(constraints)`（文件存在），**不查 agent 是否真读了**；小/微链完全豁免（scales 只有 {大,中}） |
| Review 发现不了真实问题 | **Review 无任何上下文门禁**（code-review 的"🔴 硬门禁"是装饰性标签，skill L21-24 坦承 report-only）；无"非零发现/必引证据"门禁；`G-REVIEW-LOOP` 反而把"连续 3 轮零发现"当**成功条件**（奖励发现不了问题） |

## 统一设计哲学

关键洞察：**"已读"无法机械验证（agent 读没读进上下文，查不到），但"已引用"可以**——查产物正文是否引用了上下文文档的可验证条目。现有 `_check_source_trace`（gates.py:2689）已经证明了这条路（查 Story 接口契约表"来源"列）。三个门禁统一用"**查产物证据，不查行为**"。

## 改动清单

### ① manifest 拆双文件（治 token 膨胀，低风险）

**目标**：LLM 读的 manifest 从 ≈14,849 tokens 降到 ≈2,000 tokens，省 ≈13k tokens，且不破坏 UC-15。

1. **`scripts/compile_skill_runtime.py`**：在写 `manifest.json`（机器用，保留全部哈希/校验）后，**额外写 `runtime/manifest-index.json`**（LLM 用）。index 只含：
   - `schema: "ae-sdd-runtime-index/v1"`、`version`、`runtime_fingerprint`
   - `entry`、`load_order`（6 个 compact 路径）
   - `subskills`：每条只保留 `{name, entry, manifest, boot, outline, fallback}` 5 个路径字段（**删 sha256/fingerprint/heading/ref counts**）
   - `gate_count`、`subskill_count`
2. **bootloader 模板**（`compile_skill_runtime.py:render_bootloader` L600）：Load 指令第 1 步从 `Read runtime/manifest.json` 改为 `Read runtime/manifest-index.json`。manifest.json 仍存在，但只供 `runtime verify` 用，不再要求 LLM 读。
3. **`tools/lib/runtime_verify.py`**：**不动**（它读的是 manifest.json，字段齐全，UC-15 字节级幂等不受影响——新增的 index 文件是确定性产物，snapshot 多一个稳定条目而已）。

### ② G-STORY-CTX 升级为真"已引用"门禁（治 Story 不加载，中风险）

**目标**：Story 门禁从"查文件存在"升级为"查产物引用证据"。

1. **`gates.py` `_check_context_loaded`**：现有 `constraints`/`assets` 检查（L2615/2623 的 `bool(...)`)旁，**新增产物引用校验**——用 `current_story` 正文 grep 是否引用了约束文档条目。复用 `_check_source_trace` 模式，新增 `_check_standards_referenced(story_text, required_standards)`：检查 Story 正文是否出现至少 N 项约束文档的条目 ID/章节名（如 database.md 的"分库分表"、security.md 的"参数化查询"）。**有引用 = 视为已加载并遵循**。
2. **取消小/微豁免**：`CONTEXT_GATE_REGISTRY` 的 `G-STORY-CTX` scales 从 `{大,中}` 扩到 `{大,中,小,微}`。小/微用更轻的证据要求（引用 ≥1 项而非 N 项）。
3. **state.py 不改**——不建立"读取痕迹"登记（被动痕迹会回到 LLM 自觉老路），完全靠产物证据。

### ③ 新增 G-REVIEW-DEPTH 门禁（治 Review 浮于表面，中风险）

**目标**：Review 不能裸✅，必须附证据；实质性输入下零发现需证排查过。

1. **`gates.py` GATE_REGISTRY 新增 `G-REVIEW-DEPTH`**（blocker），`check_g_review_depth`：
   - **禁裸✅**：扫描 CodeReview/StoryReview/DRReview 报告，每个 ✅ 项必须附客观证据（grep `file:line` / 报文 / test-output / 文档章节引用）。裸✅ → FAIL。
   - **零发现举证**：若报告结论为"无阻断/严重问题"，必须含"已排查 N 处"的证据段（列出排查过的文件/维度）。纯"无问题"三字结论 → FAIL。
2. **`gate_intercept.py` 相位绑定**：`code-reviewed` / `story-reviewed` / `dr-reviewed` 转换增加 `G-REVIEW-DEPTH`。
3. **三个 review skill 的 fallback**（code-review/story-review/dr-review `.full.md`）：把各自"🔴 硬门禁"标签对应的 prose 章节升级为指向 `G-REVIEW-DEPTH` 的真硬门禁引用（删除"当前为软门禁 report-only"的自我坦白）。

### ④ 级联固化（保证不复发）

- **`source/standards/update-graph.json`** 新增 UG-24（manifest 编译契约）/ UG-25（上下文/Review 门禁），trigger 指向 compile_skill_runtime.py / gates.py / review skills，checks 指向 UC-15（manifest 一致性）+ UC-02（门禁注册）。
- **`tools/lib/update_graph.py`** 新增 UC-18 `check_uc18_manifest_index_contract`：校验每次 build 后 `manifest-index.json` 存在且只含白名单字段（防回归——谁要是不小心把哈希塞回 index，UC-18 拦下）。
- **CHANGELOG**：v3.9.20 一版一文件。

## 不做（边界）

- ❌ 不删 `manifest.json` 的任何字段（runtime_verify.py 依赖，UC-15 要它）
- ❌ 不建立"读取痕迹"登记机制（被动登记 = 回到 LLM 自觉，治标不治本）
- ❌ 不改 `G-REVIEW-LOOP` 的退出逻辑（风险高，且 G-REVIEW-DEPTH 已覆盖"零发现"问题；loop 保持现状）

## 验证

1. `python -m py_compile` 编译器 + gates + update_graph
2. `bash scripts/build-dist.sh` → 确认 `dist/ae-sdd/runtime/manifest-index.json` 生成且小（<3KB）
3. token 量化：对比 index vs full manifest 字符数（应省 ≈13k tokens）
4. `pytest tools/tests/test_gates.py tools/tests/test_update_graph.py` → 现有测试绿 + 新增 G-REVIEW-DEPTH / UC-18 / manifest-index 测试绿
5. `ae-sdd update-check` → UC-15/UC-02/UC-18 全绿
6. `ae-sdd runtime verify` → 确认 manifest.json 字段齐全、UC-15 字节级幂等不破

## 风险与取舍

- **中风险点**：②③改了门禁逻辑，可能让既有项目过不了门禁。缓解：门禁失败信息给明确 fix 提示；先用一个真实 Story/Review 跑一遍验证误报率。
- **manifest 拆双文件**：UC-15 是字节级快照比对，新增 index 文件只要确定性（同输入同输出）就不破——风险低。
- 范围较大（4 个改动组），建议分步实施+分步验证：先①（独立、低风险、立竿见影省 token），再②③（门禁，需回归测试），最后④级联。每步跑测试确认不破前一步。
