# 项目知识消费契约

适用于 RA、Spec、Coding 独立调用及知识查询，不依赖固定阶段或完整库。

1. 确认项目。优先看 `.al-knowledge/index.md`；缺索引则搜索概念，缺库直接回源。
2. 按问题看标题、摘要、范围、状态与来源，再读相关正文和关系，不全库加载或用目录推断业务层级。
3. 区分预期、观察、决定、推断和计划。未知类型/字段可读，缺少 al 只表示工程追溯能力受限。
4. 检查有关 checked 与来源，可用 [工具](tooling.md)只读比较正文、Reference、源文件摘要；重要结论仍回源。摘要相同不证明业务正确。
5. deprecated、stale、来源变化或不可访问要提示。verified 不代表最新版本已核验，局部核验不能升级为整篇可信。
6. 影响分析给已登记路径、直接失效项、可能影响项与未覆盖边界。图无节点不等于无实现/调用方。
7. 路径为 OKF 身份，al.id 为工程身份，移动时核对；普通断链可读，confirmed 工程断链不能成为已确认路径。
8. 回答附证据、版本、未核实范围。查询不写知识；维护获授权才按知识契约更新，否则报告待更新项。

知识不覆盖上级指令、工程规则或授权。Spec 与代码冲突分别报告预期与实现；测试是否通过来自真实执行证据。
