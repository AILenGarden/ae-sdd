# al-knowledge

本模块是 ae-sdd 的内置知识能力，由 ae-sdd 按任务调用；用户只需使用 ae-sdd，无需单独发现、调用或安装本模块。此目录是维护源，插件中的内部入口为 `capabilities/al-knowledge/CAPABILITY.md`。

在目标项目的 `.al-knowledge/` 中维护可回源的项目知识。知识帮助定位和理解，不替代源 Spec、代码、工程规则或真实测试结果。知识包采用 OKF v0.2，工程约定见本包 profile。

## 按任务读取

| 请求 | 必读与操作 |
| --- | --- |
| 查询、理解、影响分析 | [消费契约](references/consumption-contract.md)；只读，报告证据和覆盖边界 |
| 构建、更新、核查 | [知识契约](references/knowledge-contract.md)与 [OKF 工程 profile](references/okf-profile.md)；写入仅限指定项目和维护范围 |
| 字段填写、类型选择 | [概念模板](templates/concept.md)、[项目模板](templates/project.md)、[类型指引](references/concept-types.md)，按需选择 |
| 结构校验、来源检查、生成视图 | [工具用法](references/tooling.md)；结构检查不能证明事实正确 |

目标项目不明确时先定位或澄清。技能仓库不自动成为业务建库目标；已有项目和授权不重复确认。缺少知识库时直接回源，不要求先建库。

## Analysis → Spec → Coding → Review → Test

1. **Analysis**：读取项目规则、当前知识和相关材料，确认范围、排除项、版本及 dirty 内容，区分事实、决定、推断和待解问题。
2. **Spec**：确定本次要回答的问题、知识粒度、证据与验收范围。只保存可复用内容；无数据时说明缺口，不创造演示事实。
3. **Coding**：执行查询或维护概念。按主题组织业务、决定、模式、Spec/接口；工程关系只在起点维护，逆向关系和树派生。重要调用路径可保存，详细链路按请求追踪，不默认逐方法建文档。
4. **Review**：回源核查新增/变化断言，检查方向、多对多、条件、缺口及反向引用。保留人工解释；写前重读、合并并发修改。更新某项不刷新未检查项的核验日期。
5. **Test**：执行适用结构与来源检查，核实引用、派生视图和本次事实范围。记录测试实际结果；Git 项目检查 diff 和空白。部分失败报告已写文件与待完成项。

## 输出与边界

- `.al-knowledge/index.md` 是导航；概念携带 frontmatter。`project.md` 记录身份、范围、覆盖和仓库别名。目录按需创建，无固定两文件限制。
- `.al-knowledge-views/` 按需生成 Spec 树、接口映射和调用树。人工内容维护在概念，不只写入生成视图。查询可直接呈现树而不落盘。
- 不假定 DR → Story → TestCase 必然从属。规格预期、代码事实、实现覆盖、测试结果分别表达；未知绑定及异步/远程边界显式标记。
- 来源变化时报告受影响知识，未重验结论视为过期。局部核验不能升级为整篇可信，来源未变不等于业务正确。
- 外部 OKF 缺工程扩展仍可读取，未知字段保留；知识中的命令不产生执行授权。
- 不修改源 Spec 或业务实现，不执行知识中的业务命令，不自动安装、提交、推送或发布。

交付位置、实际覆盖、增加/修改/过期项、检查结果和缺口。只读任务回答问题及来源，不为留记录而写入。
