## 1. 执行摘要

### 1.1 业务背景（JTBD）

**用户任务**：
- **功能性任务**：用户雇佣登录功能来"快速进入系统，访问个人数据"
- **情感性任务**：用户期望"安全感"（数据不被他人访问）
- **社交性任务**：无（登录是基础功能，无社交属性）

**核心痛点**：
- 当前方案：传统用户名+密码登录
- 不足1：用户忘记密码，找回流程复杂，导致流失
- 不足2：新用户注册需要设置密码，门槛高
- 期望进步：无需记忆密码，快速登录

### 1.2 核心目标（Impact Mapping）

| 业务目标 | 量化指标 | 当前值 | 目标值 | 时间 | 度量方式 |
|----------|----------|--------|--------|------|----------|
| 提升新用户注册转化率 | 注册完成率 | 60% | 75% | 3个月 | Google Analytics |
| 降低用户流失率 | 忘记密码导致的流失 | 15% | 5% | 3个月 | 用户行为日志 |
| 提升用户活跃度 | 7日留存率 | 45% | 55% | 3个月 | 数据分析平台 |

### 1.3 项目范围

**包含（In Scope）**：
- 手机号+验证码登录（核心功能）
- Token自动续期（提升用户体验）
- 登录日志记录（安全审计）

**不包含（Out of Scope）**：
- 第三方登录（微信/支付宝）→ Phase 2
- 密码登录（保留现有功能，不增强）→ Phase 2
- 生物识别登录（指纹/人脸）→ Phase 3

### 1.4 关键假设

- 用户手机号覆盖率 > 95%（实际调研：98%）
- 阿里云短信服务稳定可用（SLA 99.5%）
- 用户接受验证码5分钟有效期（行业标准）

### 1.5 约束条件

**技术约束**：
- 后端：Java 17 + Spring Boot 3.x
- 数据库：MySQL 8.0
- 缓存：Redis 7.0

**业务约束**：
- 合规要求：符合《个人信息保护法》（手机号加密存储）
- 短信成本：0.05元/条，月预算10万元（200万条）

**资源约束**：
- 开发周期：3周
- 人力：后端2人 + 前端1人 + 测试1人

### 3.3 用户故事

#### US001：手机号快捷登录

**用户故事**：
```
As a 新用户
I want to 使用手机号+验证码登录
So that 无需记忆密码，快速进入系统
```

**验收条件**：
```gherkin
Scenario: 正常登录
  Given 用户已获取验证码 "123456"
  And 验证码未过期（5分钟内）
  When 用户输入手机号 "13800138000" 和验证码 "123456"
  And 点击"登录"按钮
  Then 系统返回Token（有效期7天）
  And 跳转到首页

Scenario: 验证码错误
  Given 用户输入错误验证码 "999999"
  When 点击"登录"按钮
  Then 系统提示"验证码错误，剩余重试次数 2 次"
  And 用户可重新输入

Scenario: 验证码过期
  Given 验证码已过期（超过5分钟）
  When 用户输入验证码
  Then 系统提示"验证码已过期，请重新获取"

Scenario: 账号已锁定
  Given 用户错误输入5次验证码
  When 用户第6次尝试登录
  Then 系统提示"验证码错误次数过多，账号已锁定1小时"
```

**INVEST检查**：
- ✅ **Independent**：不依赖其他未完成故事
- ✅ **Negotiable**：实现方式可讨论（验证码位数6位还是4位可商）
- ✅ **Valuable**：预计提升新用户注册转化率15%
- ✅ **Estimable**：5 Story Points
- ✅ **Small**：5天可完成（后端3天 + 前端2天）
- ✅ **Testable**：有明确验收标准

**业务价值**：
- 降低注册门槛 → 提升转化率15%
- 减少"忘记密码"导致的流失 → 降低流失率10%

**技术风险**：
- 风险：短信网关不稳定，验证码发送失败
- 概率：中
- 影响：高
- 缓解措施：接入备用短信通道（腾讯云）

**依赖**：
- 第三方服务：阿里云短信（dysmsapi.aliyuncs.com，SLA 99.5%）

### 3.4 用例详述

#### UC001：用户登录

**用例ID**：UC001  
**用例名称**：用户手机号快捷登录  
**简述**：用户通过手机号+验证码完成身份认证，获得访问系统的权限

**参与者**：
- **主要参与者**：注册用户（新用户/老用户）
- **次要参与者**：阿里云短信网关

**前置条件**：
- 用户已完成注册（手机号已验证）
- 用户状态为"正常"（sys_user.status = 1）
- 短信网关服务可用

**后置条件**：
- **成功场景**：
  - 系统生成JWT Token（有效期7天）
  - Token存储到Redis（key: `user:token:{userId}`）
  - 记录登录日志（sys_login_log：userId/IP/时间/设备）
  - 用户进入已认证状态
- **失败场景**：
  - 系统不改变用户状态
  - 记录失败日志（含失败原因）

**触发条件**：用户打开登录页面，点击"手机号登录"

**主成功场景**：
1. 用户访问登录页（/login）
2. 用户输入手机号（11位，1开头）
3. 系统前端实时校验手机号格式
4. 用户点击"获取验证码"按钮
5. 系统调用后端接口 `POST /api/v1/auth/sms-code`
6. 系统生成6位随机验证码（SecureRandom）
7. 系统存储验证码到Redis（key: `sms:code:{mobile}`, TTL: 300s）
8. 系统调用阿里云短信网关发送验证码
9. 系统返回"验证码已发送"（不返回验证码内容）
10. 用户收到短信，输入验证码
11. 用户点击"登录"按钮
12. 系统调用 `POST /api/v1/auth/login`
13. 系统从Redis读取验证码
14. 系统校验验证码正确性（忽略大小写）
15. 系统查询用户信息（sys_user表，按mobile查询）
16. 系统生成JWT Token（payload: userId, username, roles, expireAt）
17. 系统存储Token到Redis（key: `user:token:{userId}`, TTL: 7天，覆盖旧Token）
18. 系统删除已使用的验证码（Redis DEL `sms:code:{mobile}`）
19. 系统记录登录日志（异步，避免影响RT）
20. 系统返回Token和用户信息（脱敏：mobile显示为138****8000）
21. 前端存储Token到localStorage
22. 前端跳转到首页（/home）

**扩展场景**：
```
2a. 手机号格式错误
  2a1. 前端实时校验，输入框标红
  2a2. 提示"请输入正确的手机号"
  2a3. 禁用"获取验证码"按钮
  2a4. 返回步骤2

4a. 用户60秒内重复点击"获取验证码"
  4a1. 系统检查Redis key `sms:sent:{mobile}`是否存在
  4a2. 若存在（TTL>0），返回"验证码已发送，请60秒后重试"
  4a3. 前端按钮置灰，显示倒计时
  4a4. 返回步骤10

8a. 短信网关调用失败
  8a1. 系统捕获异常（SocketTimeoutException）
  8a2. 系统重试3次（指数退避：1s, 2s, 4s）
  8a3. 若仍失败，切换备用短信通道（腾讯云）
  8a4. 若仍失败，返回"验证码发送失败，请稍后重试"
  8a5. 系统记录告警日志（severity: HIGH）
  8a6. 用例失败

14a. 验证码错误
  14a1. 系统增加错误计数（Redis INCR `login:fail:{mobile}`, TTL: 3600s）
  14a2. 系统读取错误次数
  14a3. 若错误次数 < 5，返回"验证码错误，剩余重试次数 X 次"
  14a4. 若错误次数 ≥ 5，设置锁定标记（Redis SET `login:lock:{mobile}`, TTL: 3600s）
  14a5. 返回"验证码错误次数过多，账号已锁定1小时"
  14a6. 用例失败

14b. 验证码已过期
  14b1. 系统发现Redis key `sms:code:{mobile}`不存在
  14b2. 返回"验证码已过期，请重新获取"
  14b3. 用例失败

15a. 用户不存在
  15a1. 系统查询sys_user表，结果为空
  15a2. 返回"用户不存在，请先注册"
  15a3. 用例失败

15b. 用户状态异常（已禁用）
  15b1. 系统发现sys_user.status = 0
  15b2. 返回"账号已被禁用，请联系客服"
  15b3. 系统记录异常登录日志（status='FAILED', reason='USER_DISABLED'）
  15b4. 用例失败

15c. 账号已锁定
  15c1. 系统检查Redis key `login:lock:{mobile}`存在
  15c2. 返回"账号已锁定，请X分钟后重试"
  15c3. 用例失败
```

**业务规则**：
- **BR001**：验证码有效期5分钟
- **BR002**：验证码长度6位数字
- **BR003**：同一手机号60秒内只能发送1次验证码
- **BR004**：验证码错误次数≥5次，锁定1小时
- **BR005**：Token有效期7天
- **BR006**：同一用户同时只能有1个有效Token（新登录使旧Token失效）
- **BR007**：验证码使用后立即删除（一次性）

**性能需求**：
- 获取验证码接口：P95 < 300ms（含短信网关调用）
- 登录接口：P95 < 200ms, P99 < 500ms
- 并发支持：登录接口QPS ≥ 1000

**安全需求**：
- 验证码使用SecureRandom生成（不可预测）
- Token使用HS256签名（密钥定期轮换）
- 手机号加密存储（AES-256-GCM）
- 日志脱敏（手机号显示为138****8000）
- 审计日志不可篡改（只读权限）

- 稳定性测试：300并发，持续24小时，检查内存泄漏

### 4.2 安全需求（STRIDE分析）

| 威胁类型 | 具体威胁 | 防护措施 | 验证方法 |
|----------|----------|----------|----------|
| **S**poofing | 攻击者伪造Token登录 | JWT签名验证 + Token黑名单 | 渗透测试 |
| **T**ampering | 请求参数被中间人篡改 | HTTPS强制（TLS 1.3） | 抓包测试 |
| **R**epudiation | 用户否认登录行为 | 登录日志（userId/IP/时间/设备） | 日志审计 |
| **I**nformation Disclosure | 手机号/验证码泄露 | 手机号加密存储 + 日志脱敏 | 代码审查 |
| **D**enial of Service | 暴力破解/接口刷量 | 限流（同一IP每秒10次）+ 验证码（错误5次触发） | 压力测试 |
| **E**levation of Privilege | 越权访问他人账号 | Token校验 + 用户ID绑定 | 安全扫描 |

- **限流策略**：同一IP每秒10次请求
