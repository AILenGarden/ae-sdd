# al-ra 输出契约

RA 输出的目标是形成可信的需求分析结果，而不是替代其他分析或设计工作。

## 状态

- `draft`：仍在整理事实、行为或证据。
- `clarification-needed`：存在必须确认的缺口或冲突。
- `analysis-ready`：目标、范围、行为、规则和关键数据语义已形成闭合分析。
- `blocked`：关键未知会改变需求正确性、范围、安全或兼容性，无法继续。

## 证据类型

| 类型 | 规则 |
|---|---|
| `Fact` | 可由输入或现有系统证据直接验证 |
| `Decision` | 责任人已经确认的业务选择 |
| `Assumption` | 暂时采用且必须可追踪、可撤销 |
| `Proposal` | 分析候选，不是事实或已确认决定 |
| `Risk` | 可能造成错误、遗漏、冲突或不可验证 |
| `Open Question` | 必须向责任人确认的问题 |

## Ready 最小条件

- 目标、范围、角色和关键行为明确；
- 关键规则、状态和异常行为可描述；
- 关键数据的来源、权威性、约束和去向明确，或已列开放问题；
- 证据、假设和冲突显式可见；
- 结论可以被观察或验证。

## 推荐写法

```text
Fact：当前订单状态由订单记录提供（来源：...）。
Open Question：缓存中的状态是否允许作为取消判断依据？
Proposal：可以将重复请求视为同一业务操作，但这只是分析候选，不是已确认规则。
```
