# ALCoding 变更历史

## 2026-08-28

- 初始化 ALCoding v0.1.0：插件化代码能力系统（多语言/多项目/多架构）。
- 知识提取：编码知识自 ae-sdd `skills/phase2-coding/coding-skill`（正本 sha256 `111a92e1`），评审知识自 ae-sdd `skills/phase3-review/code-review-skill`（正本 sha256 `85f15689`）；剥离 ae-sdd 流程编排/CLI/中央注册表依赖。
- 架构：内核（解析与叠加协议）+ core 双库（coding-core/review-core）+ 三轴插件（language/architecture/project）× 双能力（coding/review）；注册式接入（目录即注册）、热加载（每次调用实时扫描）、插入零改内核。
- 首批插件：java-spring-coding（coding）、java-spring-review（review）、ddd、mvc、agent（0.1.0-draft 草案）、project/_template。
- 取代同日早先创建的独立版 al-coding（已删除，其内容并入 core + java/ddd 插件）。
- 追加：全局注册表定稿——registry.yaml 升级为全局登记簿（插件清单 + provides 路由 key + enabled 开关 + 外部 path 登记），加载改为"registry 登记 ∩ 目录存在 ∧ enabled"对账制；plugin.yaml 保留元数据（matches/overlays），两文件字段不重叠防双源。
- 追加：**global 全局层注册类型**——axis 新增 global（无 matches、无条件生效、不走匹配），叠加位次在三特化轴之后、core 之前（project > language > architecture > global > core）；provides 命名 `coding:global:{name}` / `review:global:{name}`。首批全局插件：enterprise-redlines（企业级编码红线，源自用户 AGENTS.md 黄金法则）。
- 追加：**固化与扩展契约定稿**——core 为固化基线（运行期不可被插件增删改，基线变更走版本演进 + CHANGELOG）；插件新增 `extends` 通道（追加全新章节，编号不撞 core），与 `overlays`（特化既有章节）并列，二者至少其一非空。见 plugin-spec §3bis、domain-rules §3 首条。
- 修复：能力模型改为 `capabilities` 数组；加载协议先按当前调用能力过滤，再进行 matches/特异度/priority 裁决。架构插件同时服务 coding 与 review，消除 Java coding/review 同轴平局和评审阶段缺失架构红线的问题。
- 重构：主 `SKILL.md` 收缩为能力识别与资源装配入口；新增 `framework/loading-contract.md` 承载注册表对账、能力过滤、匹配、组装、能力视图与失败处理协议。入口改用标准 Codex Skill 名称 `al-coding`，版本移入 `metadata.version`。
- 修正：收窄 `coding-core` 的架构无关红线，改为约束语义职责、依赖方向与可验证性；允许 MVC 等架构在同一物理组件内共置编排与领域逻辑，并在 MVC 插件中补充方法级边界说明。
- 再修正：继续清理 core 中的架构细节、物理分层示例和落点提示；core 仅保留角色语义与通用职责边界，具体实现事实完全交由外部适配规范。
- 接入：`ALCoding/core/coding-core.md` 改为直接承载 `be-coding-thinking-engine.md` CodingModel 母版，并补齐反模式库及插件章节指针；母版源文件保持不变。
- 修复：Java + Spring 适配器改为 Spring Boot 1.x/2.x/3.x 与 Maven/Gradle 的显式决策矩阵；健康检查按项目 Actuator 配置解析，`/actuator/beans` 不再作为跨版本硬门槛；事务提交后执行改用 `@TransactionalEventListener(AFTER_COMMIT)` 或 `registerSynchronization(...)`，移除不存在的 `TransactionSynchronizationManager.afterCommit()` 调用。
- 收口：语言插件只保留 Java/Spring 语法、工具链与版本敏感决策；BFF、SPI、持久化字段、删除/分页/锁/级联等项目规则改为引用项目适配器。DDD/MVC 架构插件移除 Java 文件后缀、具体注解、构建命令和项目模块事实，统一使用语言/项目适配器提供的实现细节。
- 规范化：新增结构化 `overlays`/`extends` 条目（稳定 target/ID、mode、source），拆分候选选择与章节合并语义；补充 Maven/Gradle 探测、架构证据与 segment-aware project root 规则。
- 工具化：新增 `scripts/validate_plugins.py`（manifest/registry/entry/信任路径校验）与 `scripts/match_plugins.py`（能力过滤、版本/构建工具匹配、特异度排序、平局阻断）及 6 个回归测试。
