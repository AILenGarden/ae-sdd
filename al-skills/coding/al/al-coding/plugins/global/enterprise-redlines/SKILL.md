# enterprise-redlines — 企业级编码红线（global 层 · coding/review 能力）

> **定位：** 叠加于 `core/coding-core.md` 的基准过滤器与实现/测试检查，以及 `core/review-core.md` 阶段 A/C 之上的**全局层**插件：跨语言、跨架构、跨项目无条件生效，只做"追加 / 加严"，不取消 core 任何条目。来源：用户企业研发标准（AGENTS.md 黄金法则红线表，2026-08 固化版）。任何特化轴与本文冲突时特化轴胜，但不得放宽本文红线（core 不变量规则同样约束本层）。
>
> 本文件不含语言命令、分层落点、版本事实（分别归 language / architecture / project 轴）。

## 红线总表（🔴 违反任何一条 = 返工/阻断）

| # | 红线 | 后果 / 判定要点 |
|---|------|---------------|
| 1 | **无设计编码、无确认编码** | 代码返工；先设计后编码、先评审后落地 |
| 2 | **大事务、长事务** | 系统假死；事务内禁止网络调用/远程查询 |
| 3 | **SQL 拼接** | SQL 注入；一律参数化查询 |
| 4 | **敏感数据明文存储/打印** | 合规风险；密码/Token/身份证等加密存储、日志脱敏 |
| 5 | **分布式操作无幂等保障** | 数据重复；幂等键/唯一索引/状态机三选一起步 |
| 6 | **硬编码魔法值** | 可维护性差；常量化/枚举化/配置化 |
| 7 | **跨层调用、反向依赖** | 架构腐化；分层依赖只准单向 |
| 8 | **空 catch 块、吞异常** | 故障难定位；catch 必须记日志或转译后上抛 |
| 9 | **循环内调用外部接口** | 性能灾难；批量化/并行化/预取 |
| 10 | **重复代码、复制粘贴** | 技术债务；抽象封装复用 |

## 使用方式

- **写代码前**（叠加在 CodingModel 设计阶段之后）：把红线 1 作为"是否有已确认设计"的前置自检
- **方案自检时**（叠加在 CodingModel 11 维决策与设计出口之后）：红线 2/5/7 对应原子性/幂等性/职责边界维度，未体现即不应进入实现
- **编码后核查**（叠加在 CodingModel 实现与测试收口之后）：红线 3/4/8/9 属高发风险区，逐条对照
- **评审时**（review-core 阶段 A/C）：红线 2/3/4/5/8/9 命中即定 🔴 阻断型（review-core 标尺 2）
