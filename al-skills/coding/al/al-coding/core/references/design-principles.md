# Coding Design Principles

此文件承载 coding-core 的设计思想细节；主干保留索引和触发问题，涉及对应结构决策时读取本文件。

## Object and Structure

| 思想 | 设计判定 |
|---|---|
| 封装 | 状态和行为由拥有者维护，只暴露协作所需契约。 |
| 继承 | 仅表达真实且可替换的 is-a 关系。 |
| 多态 | 调用者依赖稳定契约，各实现保持相同可见语义。 |
| SRP | 一个单元对应一个主要变化原因，影响面可枚举。 |
| OCP | 已识别变化点可扩展，稳定行为保持不变。 |
| LSP | 替换实现不强化前置条件、不削弱后置保证。 |
| ISP | 契约按使用者真实需要拆分。 |
| DIP | 策略和细节依赖业务所需抽象，抽象不泄漏实现。 |
| 高内聚低耦合 | 单元内部共同变化，边界只暴露必要契约。 |
| 模块化与分层 | 责任和抽象层次隔离，具体层次由架构技能确定。 |
| 控制反转与依赖注入 | 边界负责创建和绑定依赖，业务依赖契约。 |
| 组合优于继承 | 复用优先组合/委托，继承需要替换证据。 |
| 最少知识 | 只依赖直接协作者，不穿透内部结构。 |
| 关注点分离 | 业务、数据、呈现和横切变化分别处理。 |
| 管道与处理链 | 可组合处理有明确顺序和每步责任。 |

## General Design Rules

| 思想 | 设计判定 |
|---|---|
| 抽象 | 提炼共同业务知识，减少重复决策且保留语义。 |
| 复用 | 语义和约束一致才直接复用；差异通过适配隔离。 |
| KISS | 选择可解释、可验证的最小结构。 |
| DRY | 统一重复的知识和规则，不合并仅表面相似的语义。 |
| YAGNI | 没有当前需求或风险证据的未来能力不进入设计。 |
| 防御式设计 | 在信任、状态和资源边界校验并定义可控失败。 |
| 不变量 | 明确必须持续成立的条件，并让修改点维护它。 |
| 契约优先 | 先稳定输入、输出、错误和兼容语义，再实现。 |
| 最小惊讶 | 可见行为遵循调用者和领域的自然预期。 |
| 显式优于隐式 | 关键状态、依赖、失败和副作用能从结构中读出。 |
| 约定优于配置 | 稳定约定减少选择；环境差异和阈值有来源。 |
| 配置外置 | 环境开关和可变阈值与代码分离并可追溯。 |
| 演进式设计 | 先满足真实需要，把未来变化留在已观察的扩展点。 |
| 童子军军规 | 变更保持局部整洁，不把无关复杂度留给下一次。 |

## Data, Failure, and Concurrency

| 思想 | 设计判定 |
|---|---|
| 数据建模 | 结构表达实体、关系和约束，不按页面字段堆叠。 |
| 事务边界 | 必须一起提交的变化在同一原子范围；避免过大事务。 |
| 一致性边界 | 区分强一致、读己写和最终一致，声明窗口和收敛。 |
| 索引意识 | 访问路径、选择性、排序、分页和写放大共同评估。 |
| 数据迁移兼容 | 新旧结构、字段含义和历史数据可共存或恢复。 |
| 原子性 | 多步操作全成或全败，失败后不破坏不变量。 |
| 可见性 | 状态变化按契约被其他执行者观察。 |
| 有序性 | 先后关系由同步、版本或消息规则证明。 |
| 超时控制 | 连接、读取、锁和异步等待都有来源明确的上限。 |
| 重试与退避 | 仅重试可判定暂时失败，并受预算与幂等约束。 |
| 降级与补偿 | 依赖失败时快速失败/替代结果；跨边界副作用可补偿或对账。 |
| 失败隔离 | 局部故障不扩散到无关链路。 |
| 资源隔离 | 核心与低优负载有独立预算、上限和拒绝语义。 |
| 生产者消费者 | 有界缓冲、顺序、积压和失败去向清晰。 |
| 异步非阻塞 | 完成、取消、异常和背压可观察。 |
| 缓存 | 命中收益覆盖一致性与容量代价，失效和异常可控。 |
| 惰性求值 | 延迟计算有触发、取消、资源和可见性语义。 |

## Engineering and Security

| 思想 | 设计判定 |
|---|---|
| 可测试性 | 依赖可隔离，断言来自契约、规则或固定真实数据。 |
| 兼容性 | 旧调用方、数据、事件和配置的共存与迁移明确。 |
| 可观测性 | 关键入口、状态、依赖失败和恢复可关联。 |
| 自动化 | 重复验证由工程环境自动执行，结果可追溯。 |
| 测试分层 | 测试范围与风险相称，真实边界不被全量 Mock 隐藏。 |
| 最小权限 | 身份认证、资源授权、租户/所有者检查分别成立。 |
| 纵深防御 | 输入、数据、传输、日志和出口分别保护。 |
| 安全默认 | 未明确授权时拒绝，敏感数据脱敏，密钥不进代码和日志。 |
| 分布式取舍 | 分区下的一致性、可用性、软状态和收敛条件显式。 |

## Paradigms

| 范式 | 适用视角 |
|---|---|
| OOP | 以拥有状态和行为的协作对象表达边界。 |
| FP | 以不可变数据、纯计算和受控副作用降低状态复杂度。 |
| 声明式 | 描述目标和约束，让执行机制承担细节。 |
| AOP | 只在横切关注点稳定且边界清晰时集中处理。 |
| 事件驱动 | 以事件解耦变化，明确投递、顺序、重复和失败语义。 |
| 响应式 | 以流、背压和异步边界表达持续数据变化。 |
