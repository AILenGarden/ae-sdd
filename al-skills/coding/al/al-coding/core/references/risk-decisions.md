# Coding Risk Decisions

每个被触发的维度记录：事实与来源、风险含义、决策、职责落点、验证证据。机制名称表示语义类别，具体技术由语言、架构和项目技能决定。

| ID | 核心问题 | 最低决策 |
|---|---|---|
| R01 原子性 | 哪些步骤必须全成或全败？ | 原子范围、协调方式、不可回滚副作用、失败状态 |
| R02 并发安全 | 同一状态或资源会否并发读写？ | 所有权、串行化/乐观/锁策略、冲突和释放 |
| R03 幂等性 | 重复请求/消息/任务会否重复副作用？ | 重复来源、识别方式、唯一性/状态前置、重复响应 |
| R04 同步异步 | 下游结果是否决定当前响应？ | 边界、可靠投递、顺序、背压、积压、失败去向 |
| R05 数据一致性 | 多资源允许多长不一致窗口？ | 权威源、更新顺序、可见性、补偿、对账和订正 |
| R06 外部容错 | 依赖不响应、失败或恢复时怎么办？ | 各等待点上限、有限重试、退避、隔离、降级、恢复 |
| R07 性能 | 计算、IO、存储或网络何处随规模失控？ | 量级、复杂度、批量/分页、缓存、限流、容量证据 |
| R08 资源隔离 | 低优负载会否挤占核心路径？ | 预算、队列/池/实例边界、拒绝和优先级 |
| R09 安全 | 输入、身份、权限和敏感数据如何保护？ | 校验、认证授权、数据隔离、密钥、脱敏、审计 |
| R10 可观测性 | 出问题时能否重建因果并及时发现？ | 关联 ID、结构化日志、指标、追踪、告警、隐私 |
| R11 可运维性 | 行为能否安全启用、兼容、回退和修复？ | 开关、迁移、回退、配置、订正和操作证据 |

## Common Branches

| 场景 | 判断 |
|---|---|
| 核心动作被下游结果决定 | 同步边界清晰；等待有界；失败结果可见。 |
| 结果不影响当前响应 | 异步解耦；可靠投递；顺序/重复/失败去向明确。 |
| 生产快于消费 | 有界队列、背压或限流；积压和延迟可观测。 |
| 多优先级共享资源 | 分别设置预算、上限、拒绝和调度规则。 |
| 跨边界副作用部分成功 | 保留状态、重试、补偿、对账或人工订正路径。 |
| 失败后重复调用 | 先确认幂等键、状态前置和副作用是否可重放。 |

## Core Path Check

涉及回调、状态通知、批量/异步任务、消息、外部推送或共享资源时，检查：

1. 动作是否在核心实时路径？
2. 是否与低优负载共享执行器、队列、连接或热点数据？
3. 队列、并发和批量规模是否有上限、拒绝和优先级？
4. 重试、失败存放、补偿/人工处理和重复消费如何追踪？
5. 积压、延迟、错误和资源饱和的观察/告警条件是什么？
6. 满载负载存在时，如何证明核心路径仍受保护？
